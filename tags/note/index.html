一、数字系统

  1. 定义
    数字系统是离散信息处理系统，以一组离散信息为输入，以离散内部信息为系统状态，最终输出离散形式的结果。
  2. 分类
  • 组合逻辑系统：无状态记忆功能，输出值仅由当前输入决定，公式：output = f (input)
  • 时序逻辑系统：具备状态记忆功能，输出值由当前输入 + 系统状态共同决定，公式：output = f (state, input)
    • 同步时序系统：在离散时间点更新状态
    • 异步时序系统：在任意时间点更新状态
  1. 典型系统
    数字计数器、数字计算机、嵌入式系统、手机、相机、汽车电子、GPS、复印机、洗碗机等。

二、信息表示

  1. 核心概念
  • 信息：对物质世界与人类社会现象的表示，可消除不确定性，用信息熵衡量。
  • 信号：信息的物理载体，分为模拟信号（连续物理量）和数字信号（离散物理量）。

  1. 二进制表示

    数字系统广泛采用二进制，用 0 和 1 表示，也可对应真 / 假、高 / 低、开 / 关；可通过电压、磁场方向、电荷量等物理量实现二进制。

三、数制

  1. 基础定义
  • 数制：数的表示规则。
  • 基底 r：数制包含的数字符号个数。
  • 权 r^i：数字符号位置对应的值，数值 = 各位数字值 × 对应权值之和。
  1. 常用数制
  • 二进制（B/2）：0、1
  • 八进制（O/8）：0~7
  • 十进制（D/10）：0~9
  • 十六进制（H/16）：09、AF

  1. 二进制单位

    2^10=1K、2^20=1M、2^30=1G、2^40=1T

  2. 数制运算

    二进制、八进制、十六进制加减乘规则同十进制，按位计算，逢基底 r 进 1。

  3. 数制转换

  • 非十进制→十进制：按权展开求和
  • 十进制→非十进制：整数部分除 r 取余（余数倒序），小数部分乘 r 取整（整数正序）
  • 二 / 八 / 十六互转：1 位八进制 = 3 位二进制，1 位十六进制 = 4 位二进制，以小数点为界分组转换

四、编码

  1. 二进制编码

    n 位二进制编码可表示 2^n 个数据；表达 M 个数据需要⌈log₂(M)⌉位；分数值型（可算术运算）、非数值型（无需算术运算）。

  2. BCD 码

    用 4 位二进制表示 09 的十进制编码，8421 码最常用（加权码，权值 8、4、2、1），10101111 为无效码；进制转换≠编码，如十进制 13，二进制是 1101，BCD 码是 0001 0011。

  3. 格雷码

  • 核心特点：计数时相邻编码仅 1 位不同，位翻转少、功耗低、抗干扰，可避免编码错误。
  • 编制方法：(n+1) 位格雷码 = n 位格雷码（顺序 + 前缀 0）+ n 位格雷码（逆序 + 前缀 1）。
  1. 字符编码
  • ASCII 码：7 位二进制，共 128 个字符（94 个可打印 + 34 个控制符）；数字 09、大写 AZ、小写 a~z 编码连续，大小写转换翻转 B6 位即可。
  • Unicode：统一码，覆盖全球语言字符；UTF-8 兼容 ASCII，1~4 字节可变长编码。
  1. 校验位
  • 作用：检测数据传输错误，增加 1 位校验码。
  • 偶校验：编码中 1 的个数为偶数，校验位填 0。
  • 奇校验：编码中 1 的个数为奇数，校验位填 0。
  • 局限：无法定位错误位，无法检测偶数个位出错。

数字逻辑 第一章 数字系统 完整易错点总结

  1. 组合逻辑与时序逻辑混淆：组合逻辑无状态、输出只看当前输入；时序逻辑有记忆、输出依赖输入 + 历史状态，二者判断易出错。
  2. 十进制转非十进制顺序错误：整数部分除 r 取余需倒序排列，小数部分乘 r 取整需正序排列，极易写反。
  3. 二 / 八 / 十六进制转换补零错误：以小数点为界分组时，整数左侧、小数右侧易漏补 0，导致转换结果错误。
  4. BCD 码与二进制转换混淆：将十进制数直接转为二进制当作 BCD 码，忽略 BCD 码按十进制位拆分编码的规则。
  5. 格雷码核心特性误解：误以为格雷码是二进制逐位加 1，忽略相邻仅 1 位变化的关键特点。
  6. 校验位功能认知错误：认为奇偶校验能纠正错误、检测所有错误，忽略其无法定位错误、无法检测偶数位错误的局限。
  7. 进制后缀标识错误：B（二）、O（八）、D（十）、H（十六）混用，导致数制识别错误。
  8. 二进制单位计算错误：混淆二进制 1K=1024 与十进制 1K=1000，单位换算出错。
  9. 数制按权展开计算错误：小数点左右侧权值符号搞反（左侧正次幂、右侧负次幂），求和结果错误。
  10. ASCII 码大小写转换错误：记错翻转位，或混淆数字、字母的编码区间。
  11. 编码 长度 存储方式 兼容 ASCII 常用场景

    UTF-8 1~4 字节 按码点大小自动选长度 完全兼容 网页 / 文件 / 全球通用

一、章节总结

SQL（Structured Query Language）是介于关系代数与关系演算之间的关系数据库标准语言，集查询、数据操纵、数据定义和数据控制于一体。课件强调它是通用、功能很强、并且最适合关系数据库系统的标准语言；版本上提到 SQL-89、SQL-92、SQL-99（加入面向对象概念）和 SQL2003。

SQL 的突出特点有三点：第一，综合统一，把 DDL、DML、DCL 融合在同一种语言里；第二，高度非过程化，用户只需说“做什么”，不必说明“怎么做”；第三，面向集合，查询、插入、删除、修改的对象都是集合而不是单条记录。它还支持独立使用，也支持嵌入高级语言，语法结构基本一致，因此既方便交互，也方便程序调用。

从系统结构看，SQL 支持三级模式结构：基本表对应模式层，视图对应外模式，存储文件对应内模式。基本表是独立存在的真实表，一个关系对应一个基本表；视图则是从一个或多个基本表导出的虚表，本身不实际存储数据，其定义保存在数据字典中，但可以像表一样查询，并在一定条件下更新。

SQL 的数据定义功能主要包括模式、表、视图和索引。SQL2 还增加了 SQL 数据库模式的定义。模式由模式名、权限标识符和模式元素描述符组成；同一应用的表、视图、索引可以放在同一模式中。模式可以先建空壳，再逐步补充内部对象；删除模式时可用 CASCADE 级联删除全部对象，或用 RESTRICT 限制删除。

表的定义使用 CREATE TABLE，列名后面跟数据类型，还可以写列级约束和表级约束。课件用 Student、Course、SC 三个表作为标准示例：Student 表中 Sno 用 NOT NULL UNIQUE 和主键约束，Ssex 用 CHECK 限定为“男/女”；SC 表中 Sno、Cno 作为联合主键，Grade 用 CHECK 限定在 0 到 100，并通过 FOREIGN KEY 分别引用 Student 和 Course。课件还提到 SQL2 可以用 CREATE DOMAIN 定义域，便于多个列共享同一类型定义。

表的修改使用 ALTER TABLE，可以新增列、删除列或修改列定义。新增列后，旧记录中该列值自动为空值；修改列长度或类型时要小心，因为可能破坏已有数据。删除表用 DROP TABLE；RESTRICT 会拒绝删除被外键、视图等依赖的表，CASCADE 则会联动删除相关依赖对象。

索引是一种用于提高查询速度的数据结构。课件强调索引是大型关系数据库实现中的核心问题之一：可以在一个表上建一个或多个索引，也可以不建；DBA 或表的属主决定是否建立，而系统在查询时自动决定是否使用索引。CREATE INDEX 可以建普通索引，也可以建 UNIQUE 索引或 CLUSTER 聚簇索引；DROP INDEX 用于删除索引。聚簇索引会决定表中数据的物理顺序，因此一个表只能有一个聚簇索引。

SQL 的数据操纵主要包括查询、插入、修改和删除。本章主要展开的是查询：单表查询、连接查询、嵌套查询和集合查询。SQL 的统一 SELECT 语句一般结构包含 SELECT、FROM、WHERE、GROUP BY、HAVING、ORDER BY 等子句，分别控制输出列、查询对象、筛选条件、分组、分组过滤和排序。

单表查询部分重点讲了比较大小、范围查询、集合查询、字符串匹配、空值查询、多重条件、排序、聚集函数和分组。比如 BETWEEN 用于范围，IN 用于集合匹配，LIKE 用于模式匹配，IS NULL 不能用 = NULL 代替，ORDER BY 可指定 ASC/DESC，聚集函数包括 COUNT、SUM、AVG、MAX、MIN，GROUP BY 用于分组，HAVING 用于筛选组。

连接查询部分包括广义笛卡尔积、等值连接、自然连接、非等值连接、自身连接、外连接和复合条件连接。课件用 Student、SC、Course 作为标准示例，说明等值连接如何把学生信息和选课信息拼接，自然连接如何去掉重复属性，自身连接如何通过别名处理同一表的两次引用，外连接如何保留未匹配元组，复合条件连接如何把连接条件与其他筛选条件结合。

嵌套查询部分讲了不相关子查询与相关子查询，常见引出谓词包括 IN、比较运算符、ANY、ALL、EXISTS、NOT EXISTS。课件强调：IN 型子查询常用于“属于某个集合”的判断，ANY/ALL 常用于“某个值比集合中某些值大/小”的比较，EXISTS/NOT EXISTS 只关心子查询是否有结果，不关心具体值。全称量词和逻辑蕴涵可以用 NOT EXISTS 进行等价表达，这是 SQL 中处理“所有”“全部满足”类问题的标准套路。

集合查询部分讲了 UNION、INTERSECT、EXCEPT 以及集合结果排序。课件明确指出，ORDER BY 只能出现在整个集合操作的最后，不能写在 UNION/INTERSECT/EXCEPT 的中间结果上；对集合操作结果排序时，可以用序号指定排序列。

本章目录中还包括 SQL 中的视图、数据控制和嵌入式 SQL。结合前面的系统结构，视图属于外模式的重要组成部分；数据控制属于 SQL 的统一功能之一；嵌入式 SQL 则对应“SQL 作为高级语言中的子语言使用”的那条路线。

二、易错点总结

1. 把基本表和视图混为一谈

基本表是真实存储的独立表，视图是从基本表导出的虚表，不实际存储数据。很多人会把视图当成普通表直接理解，这是错的；视图本质上是“逻辑定义”，不是“数据实体”。

2. 把模式、表、数据库模式的层次弄混

SQL 模式不是一张表，而是一个命名空间，里面可以放表、视图、索引等对象。CREATE SCHEMA 只是建立模式框架，真正的数据对象还要继续定义。

3. 忘记模式名可能省略，但会隐含为用户名

课件明确说过：如果 CREATE SCHEMA 里没有显式写模式名，则隐含为用户名。这个细节很容易在考试里被忽略。

4. 把列级约束和表级约束混在一起

CREATE TABLE 里既可以写列级约束，也可以写表级约束。像 PRIMARY KEY、FOREIGN KEY、CHECK 都可能出现在不同层次，考试里常考“这个约束该写在哪里”。

5. 忽略 CHECK 的实际作用

课件中 Grade BETWEEN 0 AND 100、Ssex IN (‘男’,’女’) 都是典型的 CHECK 约束。很多同学会只记主键和外键，忘了 CHECK 也是非常常见的完整性约束表达方式。

6. 用 ALTER TABLE 增列后，以为旧数据会自动补合理值

新增列后，原有记录中新列一律为空值，不会自动生成默认业务值。修改列类型或长度则可能破坏已有数据，这个风险常常被忽略。

7. DROP TABLE 不考虑依赖关系

RESTRICT 和 CASCADE 的区别非常重要。若表被外键、视图、触发器、存储过程等依赖，RESTRICT 会拒绝删除；CASCADE 则会连带删除相关对象。考试很喜欢考“能不能删、删了会影响什么”。

8. 索引只记“快”，不记“代价”

索引能加快检索和连接，但会占额外空间，还会增加插入、更新、删除时的维护成本。课件明确强调要权衡数据性质和查询性质，不是所有列都适合建索引。

9. UNIQUE 索引不是“想建就能建”

如果该列已有重复值，就不能建 UNIQUE 索引。很多同学只记“唯一索引更快”，却忘了它的前提是数据本身必须唯一。

10. 把 SQL 结果的重复元组理解错

关系理论里元组不重复，但课件指出商用数据库为了效率，允许 SQL 结果中出现重复元组，所以 SELECT 默认可能返回重复行，需要用 DISTINCT 去重。这个点非常容易和“关系是集合”混淆。

11. DISTINCT 的作用范围弄错

DISTINCT 作用于所有目标列，不是单独作用于某一个列。像“SELECT DISTINCT Cno, DISTINCT Grade”这种写法是错的。

12. SELECT、FROM、WHERE、GROUP BY、HAVING、ORDER BY 的作用不分

SELECT 选列，FROM 选表，WHERE 过滤元组，GROUP BY 分组，HAVING 过滤组，ORDER BY 排序。最常见的错法是把 HAVING 当 WHERE 用，或者把 WHERE 写成聚集函数过滤条件。

13. WHERE 和 HAVING 混淆

WHERE 作用于基表或视图中的元组，不能直接使用聚集函数；HAVING 作用于组，可以使用聚集函数。这个区别是分组查询的核心考点。

14. 把 LIKE 的通配符含义记反

% 表示任意长度字符串，_ 表示任意单个字符。像“欧阳_ _”表示三个汉字姓名，“刘%”表示刘姓学生。很多同学会把两者含义弄反。

15. 不会用 ESCAPE

当要匹配的字符串本身含有 % 或 _ 时，必须使用 ESCAPE 转义，否则会被当成通配符。课件中的“DB_Design”就是典型例子。

16. 把 NULL 当成普通值

NULL 不是 0，也不是空串，也不是普通空白。它表示未知、不适用或保留的信息；与 NULL 的比较不能用 = NULL，而要用 IS NULL 或 IS NOT NULL。空值参与算术运算仍是空值，逻辑运算还可能得到 UNKNOWN。

17. 不理解空串和空值的区别

空串是零长度字符串，不等于 NULL。这个细节在数据库题里经常被混问。

18. ORDER BY 的位置写错

ORDER BY 只能出现在最终查询结果后面，不能放在 UNION/INTERSECT/EXCEPT 之前的子句后面。集合操作结果排序时，还要注意可用数字指定排序列。

19. 连接查询里忘记表名前缀

多个表中出现同名属性时，必须写表名前缀，否则会歧义。自身连接尤其容易出错，因为同一表引用两次时必须使用别名区分。

20. 把自然连接和等值连接完全等同

自然连接是等值连接的一种特殊情况，会自动去掉重复属性列；等值连接则只是按条件相等连接，结果中可能保留重复列。

21. 外连接理解不完整

普通连接只保留满足连接条件的元组；外连接还要保留左表或右表中未匹配的元组，缺失部分通常补 NULL。很多同学只记“外连接保留未匹配行”，但忘了它是“以某一边为主体”的。

22. 复合条件连接和普通连接混为一谈

复合条件连接是在连接条件之外再加其他筛选条件，本质上可以看成“连接后再筛选”。如果不区分连接谓词和其他限定条件，很容易写错。

23. 嵌套查询顺序想反

不相关子查询通常先算子查询再算父查询；相关子查询则依赖父查询元组逐行执行。很多人会把这两种执行方式混在一起。

24. IN、ANY、ALL、EXISTS 不会区分

IN 常表达“属于集合”；ANY 表示“子查询结果中的某一个”；ALL 表示“子查询结果中的所有”；EXISTS 只看是否存在结果。课件还给出 ANY/ALL 与 MAX/MIN 的对应关系，这个非常容易考。

25. 把 = ANY 和 = ALL 记错

课件明确指出，= ANY 相当于 IN；= ALL 通常没有实际意义。很多同学会把它们机械背成同类语义。

26. 不会用 NOT EXISTS 表达“全部满足”

SQL 没有全称量词，但可以用“对不存在的反例进行否定”来表达。像“选修了全部课程的学生”这种题，本质就是：不存在一门他没选的课程。

27. 集合运算题不会把问题翻译成“普通查询”

课件里多次强调，集合差、交、并很多时候可以转成普通 SQL 条件。比如“CS 系学生与年龄不大于 19 岁的差集”实际上就是“CS 系且年龄大于 19 岁”。如果一上来硬套集合运算，反而容易绕晕。

28. 以为标准 SQL 允许在集合运算中间随便排序

课件明确说 ORDER BY 只能用于最终结果，不能用于中间结果。集合操作时的排序必须放在最后，这是很多同学写集合题的高频错误。

29. 只记语法，不记语义

SQL 看起来是命令式语法，但本质是非过程化语言。真正做题时，关键不是死背语句，而是先判断：查哪些表、筛什么条件、是否需要分组、是否需要关联、是否需要“全部满足”语义。

第3章 关系数据库 复习整理

一、本章主线

关系数据库系统是支持关系模型的数据库系统。关系模型以集合论中的“关系”为基础，运用数学方法研究数据库的结构以及对数据的操作。本章围绕数据模型的三要素展开：数据结构、数据操作、完整性约束；并进一步学习关系模型的基本概念、关系代数、元组关系演算和域关系演算。

二、关系模型的基本概念

2.1 域（Domain）

域是一组具有相同数据类型的值的集合。它表示属性的取值范围。比如自然数、整数、{男，女}、{0，1} 都可以看作域；在教师关系中，姓名、性别、年龄也都可以分别对应一个域。

2.2 笛卡尔积（Cartesian Product）

给定若干集合 D1, D2, …, Dn，它们的笛卡尔积是所有分量组合形成的集合：
D1×D2×…×Dn = {(d1,d2,…,dn) | di∈Di}。
它的本质是“所有域的所有值的组合”，并且这些组合不重复。PDF 用“导师—专业—研究生”给出了三域笛卡尔积的完整例子。

2.3 元组（Tuple）与分量（Component）

笛卡尔积中的每一个元素称为一个元组；元组中的每一个值称为一个分量。比如 (张清玫, 计算机专业, 李勇) 是一个三元组，而“张清玫”“计算机专业”“李勇”分别是分量。

2.4 关系（Relation）

关系是笛卡尔积的任意一个子集。n 叫做关系的目或度。关系中的每一行对应一个元组，每一列对应一个属性。严格说，关系数据库中的关系必须是有限集合。

PDF 还特别强调：由于笛卡尔积本身不满足交换律，关系模型通过“属性名”来取消元组的有序性，因此在关系中列的顺序本质上是无关的。

2.5 规范化关系应满足的性质

规范化的关系有几个重要性质：
第一，列是同质的，即同一列的数据来自同一个域；第二，不同的列可以来自同一个域，但必须用不同属性名区分；第三，列的顺序无所谓；第四，元组不能重复；第五，行的顺序无所谓；第六，每个分量必须是原子值，不能再分。
其中“分量必须取原子值”是最基本、最重要的规范条件。PDF 还举了“职工工资”嵌套结构不符合关系模型要求的例子。

2.6 一元关系、二元关系

当 n=1 时称为一元关系；当 n=2 时称为二元关系。这个定义本身是关系理论中的基础概念，后面讲查询语言和运算时都会用到。

三、关系模式与关系数据库

3.1 关系模式（Relation Schema）

关系模式是对关系的描述，通常包括关系名、属性名、属性类型、长度以及属性间固有的数据联系。简记形式通常写作 R(A1, A2, …, An)。例如，图书关系模式可以写成：图书(书号, 书名, 作者, 单价, 出版社)。

3.2 关系的值

关系的值是元组的集合。一个关系模式在某一时刻对应的实际内容，就是该关系的值。PDF 强调，关系是现实世界某一时刻状态的反映，因此关系的值会随时间变化。

3.3 关系数据库与关系数据库模式

关系模式的集合称为关系数据库模式，通常写作 R={R1, R2, …, Rp}。每个关系模式上对应的关系集合，构成完整的关系数据库。

四、键（Key）

为了区分不同元组，需要用一个或多个属性值唯一标识元组，这样的属性或属性组称为关系的键。能够起标识作用而其子集不能起标识作用的键称为候选键；在多个候选键中选定一个作为主键；若键由多个属性组成，则称为联合键；若关系的所有属性都构成键，则称为全键。

这一部分的核心是：键的作用不是“好看”，而是“唯一标识元组”。后面的实体完整性、参照完整性，都建立在键的基础上。

五、完整性约束

关系模型中的完整性规则是对关系的约束条件。为了保证数据库中的数据与现实世界一致，关系数据库的插入、删除和修改操作必须受到约束。关系模型的三类完整性约束是：实体完整性、参照完整性、用户定义完整性。通常前两类由系统自动支持，用户定义完整性则反映具体应用的语义要求。

5.1 实体完整性—主键

实体完整性要求主键的值不能为空或部分为空。换句话说，若属性 A 是基本关系 R 的主属性，则 A 不能取空值。原因是：如果键为空或部分为空，该元组就不可标识，也就不能表示任何实体。

PDF 进一步解释了实体完整性为什么成立：基本表通常对应一个实体集或多对多联系；现实世界中的实体是可区分的，关系模型用主键作为唯一标识，因此主键不能为空，否则就会出现不可区分的实体，这与实体可区分的现实相矛盾。

5.2 参照完整性—外键

关系模型中实体及其联系都用关系表示，因此关系与关系之间自然存在引用。若关系 R1 中的属性 A 引用了关系 R2 的主键，则 R1 中 A 的值要么为空，要么必须等于 R2 中某个元组的主键值。

PDF 的学生—专业例子非常典型：学生关系中的“专业号”必须来自专业关系中真实存在的专业号，不能引用不存在的专业。这个规则就是参照完整性。

5.3 外键（Foreign Key）

若 F 是基本关系 R 的一个或一组属性，但不是 R 的键；并且 F 对应于基本关系 S 的主键 Ks，则称 F 为 R 的外键。R 是参照关系，S 是被参照关系或目标关系。R 和 S 不一定是不同的关系；外键与主键也不一定同名，但必须定义在同一个或一组域上。

PDF 还给出了“学生实体及其内部领导联系”的例子：学生关系中的“班长”属性值，如果非空，则必须是本关系中某个元组的学号值；这说明参照完整性不仅可以发生在不同关系之间，也可以发生在同一关系内部。

5.4 用户定义完整性

用户定义完整性是针对具体数据库的特殊约束，反映某一应用领域的语义要求。PDF 举例：选课关系中成绩不能为负数，或者某些数据输入格式需要满足特定限制。关系模型应提供统一的机制来定义和检验这类约束，而不应完全交给应用程序。

六、关系代数

6.1 关系代数是什么

关系代数是一种抽象查询语言，用对关系的运算来表达查询要求。它的三个要素是：运算对象是关系，运算结果也是关系，运算由一组运算符构成。关系代数是关系数据库系统中实现关系操作的重要基础。

6.2 关系代数的分类

关系代数分为三类：
第一，传统集合运算，包括并、差、交、广义笛卡尔积；
第二，专门的关系运算，包括选择、投影、连接、除法；
第三，扩充的关系运算，包括属性重命名、外连接。

关系操作的特点是“集合操作方式”，即操作对象和结果都是集合，属于“一次一集合”；而非关系数据模型通常是“一次一记录”。这是关系模型与传统记录式数据模型的根本区别之一。

七、传统集合运算

7.1 并（Union）

R∪S 仍为 n 目关系，由属于 R 或属于 S 的元组组成。前提是 R 和 S 具有相同的目数，并且对应属性来自同一个域。

7.2 差（Difference）

R-S 由属于 R 而不属于 S 的元组组成。同样要求两者具有相同目数和相应域匹配。

7.3 交（Intersection）

R∩S 由同时属于 R 和 S 的元组组成，也可表示为 R-(R-S)。

7.4 广义笛卡尔积

若 R 是 n 目关系，S 是 m 目关系，则 R×S 是一个 n+m 目关系，行数等于两者元组数的乘积。其本质是把 R 中每个元组与 S 中每个元组拼接。

八、专门的关系运算

8.1 选择（Selection）

选择是从关系中选择满足条件的元组子集，记作 σF(R)。F 是由逻辑连接词和比较表达式组成的布尔条件。选择从“行”的角度进行运算。

典型例子：
查询信息系学生：σSdept=’IS’(Student)
查询年龄小于 20 的学生：σSage<20(Student)。

8.2 投影（Projection）

投影是从关系中选出若干属性列组成新关系，记作 πA(R)。投影从“列”的角度进行运算，但它不仅会删除某些列，也可能删除重复元组。

例子：查询学生姓名和所在系，即 πSname,Sdept(Student)。

8.3 连接（Join）

连接是按条件把两个关系中的元组拼接起来形成新关系。最常见的是条件连接和自然连接。条件连接可写成 R ⋈AθB S，其中 A 和 B 为同域属性。等值连接是 θ 为“=”的情况。

自然连接是一种特殊的等值连接，要求被比较的分量是相同的属性组，并且结果中去掉重复属性列。PDF 强调，自然连接既涉及行，也涉及列。

8.4 除（Division）

除运算是一个二元运算，用符号 ÷ 表示。若 R(X,Y) 与 S(Y) 相关，则 R÷S 产生一个新关系 R’(X)，其含义是：找出那些在 X 上取值 x，使得 x 对应的“象集”包含了 S 在 Y 上的投影。直观上可以理解为“满足所有条件的那些对象”。

PDF 给了两个很经典的例子：

  1. 同时选修了 C2 和 C3 的所有学生；

  2. 选修了全部课程的学生号码和姓名。
    这类题几乎都是除法运算的标准应用场景。

8.5 属性重命名

属性重命名用来改变属性名，但不改变数据本身。它不仅可以对单个属性重命名，也可以对一组属性同时操作。其作用之一是便于同一关系做自然连接或笛卡尔积，也能把等值连接方便地表示为自然连接。

8.6 外连接

外连接是对自然连接的扩展，结果中除了满足连接条件的元组外，还包含没有被连接上的元组。左外连接保留左侧关系中未匹配的元组，右外连接保留右侧关系中未匹配的元组，完全外连接则是左右外连接的并。未匹配处通常用 NULL 填充。

九、关系代数中的典型例子

9.1 查询计算机系学生的学号和姓名

先选出计算机系学生，再投影学号和姓名：
πSno,Sname(σSdept=’计算机’(Student))。

9.2 查询选修了 2 号课程的学生学号

先在选课关系中选择 Cno=’2’，再投影 Sno：
πSno(σCno=’2’(SC))。

9.3 查询选修了 1 号课程的学生姓名

思路是：先连接 Student 和 SC，再筛选 Cno=’1’，最后投影 Sname。
这类题的关键不是直接背表达式，而是先问自己三件事：从哪里取数据、筛什么条件、最后保留哪些列。PDF 在这个例题里就是这样一步步展开的。

9.4 查询不选 1 号课的学生信息

先从 SC 中找出选了 1 号课的学号，再与 Student 做差集或差相关表达式，得到不选 1 号课的学生。这个例子用于训练“先找集合，再做差”的思路。

9.5 查询学生“刘明亮”选修的全部课程名

先连接 Student、SC、Course，再筛选 Sname=’刘明亮’，最后投影 Cname。PDF 还展示了利用属性重命名后做自然连接的写法，这个例子特别适合理解“为什么要先重命名”。

9.6 查询至少选修了其直接先行课为 5 号课的课程的学生姓名

这道题的关键是先从 Course 中筛出 Cpno=’5’ 的课程，再与 SC 和 Student 关联，最后投影学生姓名。PDF 还展示了通过中间关系再改写的等价形式，这说明复杂查询通常要拆成多个中间步骤。

9.7 查询选修全部课程的学生号码和姓名

这是除法运算的经典应用。思路是先用 πSno,Cno(SC) 除以 πCno(Course)，得到“选修了所有课程”的学生学号，再与 Student 连接取姓名。

9.8 插入、删除示例

插入示例是把学号 200504 的学生选修 4 号课、成绩 88 的记录加入 SC。删除示例则是删除学生“刘明亮”选修的英语课，并且要先考虑参照完整性，必要时先处理相关依赖记录。PDF 用这些例子说明：关系代数不仅可用于查询，也可用于更新表达。

9.9 利用重命名查询“与李勇在同一个系的学生”

PDF 的做法是先将 Student 自连接前重命名部分属性，然后做自然连接，再筛选李勇所在系，最后投影学号和姓名。这个例子非常适合理解重命名的必要性：如果不改名，自连接时属性名冲突会导致语义混乱。

十、关系代数的基本结论

关系代数可以用来完成查询、插入和删除等操作，其中查询是最重要的部分。关系代数中，并、差、笛卡尔积、选择、投影是基本运算；交、连接、除都可以由这些基本运算表示，因此引入它们并不增加语言能力，但可以简化表达。

十一、关系演算

11.1 关系代数语言与关系演算语言

关系代数语言用对关系的运算来表达查询要求，典型代表是 ISBL。关系演算语言则用谓词来表达查询要求，按谓词变元的基本对象不同，分为元组关系演算和域关系演算。

11.2 元组关系演算

元组关系演算语言以元组变量为基本对象。PDF 介绍了 ALPHA 和 QUEL，ALPHA 是由 Codd 提出的，QUEL 是 INGRES 所用语言，参考 ALPHA 研制，但并没有实际实现。

ALPHA 的基本格式是：
操作语句 <工作空间名>(表达式)：操作条件。
其中表达式可以是关系名或属性名，操作条件是一个逻辑表达式，可为空，还能附加排序要求、定额要求等。

ALPHA 的 GET 语句用于检索，例如：
GET W (SC.Cno)
GET W (Student)
GET W (Student.Sno, Student.Sage): Student.Sdept=’IS’ ∧ Student.Sage<20。

ALPHA 的更新语句包括 PUT、HOLD、UPDATE、DELETE、DROP。修改的标准步骤是：先用 HOLD 把元组读入工作空间，再用宿主语言修改，最后用 UPDATE 写回数据库。插入通常先在工作空间中构造新元组，再用 PUT 存入指定关系；删除则先 HOLD 再 DELETE。PDF 还给出了学生转系、插入课程、删除学生等完整例子。

11.3 域关系演算

典型的域关系演算语言是 QBE（Query By Example），由 M. M. Zloof 提出，并在 1978 年于 IBM 370 上实现。QBE 是基于屏幕表格的查询语言，通过填写表格构造查询，用示例元素表示结果可能情况，最终以表格形式输出结果。

QBE 的操作框架是：用户提出要求，系统显示空白表格，用户输入关系名，系统显示属性名，用户构造查询条件，最后显示结果。PDF 还给出了 QBE 的修改、插入、删除示例，如把 95001 学生年龄改为 18、把学生信息插入数据库、删除学生 95089 以及其选课记录等。

十二、关系数据语言的分类与特点

关系数据语言分为三类：关系代数语言、关系演算语言，以及同时具有关系代数和关系演算双重特点的语言。典型代表是 SQL。SQL 集 Query、DDL、DML、DCL 于一体，是关系数据库的标准语言。

关系数据语言的特点是高度非过程化，存取路径由 DBMS 优化机制决定，用户不必用循环结构完成操作，而且可以嵌入高级语言中使用。另一方面，关系代数、元组关系演算和域关系演算三者在表达能力上完全等价。

十三、关系运算的安全限制

由于集合论中的关系可以是无限的，而数据库中的关系必须是有限的，因此需要“安全限制”。不产生无限关系的关系表达式称为安全运算表达式。关系代数是安全的，只要输入关系有限，结果就有限；而关系演算不一定安全，因此需要加以限制。加上安全限制后，三种关系运算在表达能力上等价。

十四、概念结构与逻辑结构的对应

PDF 还给出了 E-R 模型与关系数据模型之间的对应关系：实体集对应关系表，实体集属性对应表的列，联系集与属性对应表和列，实体实例对应行，主键/候选键对应关系表中的主键/候选键。数据操作层面对应 SQL 语句、关系代数、关系演算；约束层面对应联系类型约束、键约束、完全参与约束以及关系模型中的三类完整性约束。

十五、本章最重要的专有名词清单

  1. 域：同类型值的集合。

  2. 笛卡尔积：多个域所有值组合形成的集合。

  3. 元组：关系中的一行。

  4. 分量：元组中的一个值。

  5. 关系：笛卡尔积的子集。

  6. 关系模式：关系的结构描述。

  7. 关系数据库模式：多个关系模式的集合。

  8. 键：能唯一标识元组的属性或属性组。

  9. 候选键、主键、联合键、全键。

  10. 实体完整性、参照完整性、用户定义完整性。

  11. 外键：引用其他关系主键的属性组。

  12. 选择、投影、连接、除、重命名、外连接。

  13. 元组关系演算、域关系演算。

  14. ALPHA、QUEL、QBE、SQL。

十六、最容易混淆的点

第一，关系、关系模式、关系数据库模式不是一回事：关系是值，关系模式是结构描述，关系数据库模式是一组关系模式。

第二，主键和外键的作用不同：主键负责唯一标识元组，外键负责引用别的关系的主键。

第三，选择和投影一个看“行”，一个看“列”；连接是把两个关系按条件拼起来；除法通常对应“所有都满足”的语义。

第四，三种关系数据语言在表达能力上等价，但风格不同：关系代数偏运算，关系演算偏谓词，SQL 则兼具两者特点。

第五，关系演算要注意安全性，否则可能出现无限结果；关系代数天然安全。

一、基础概念层易错点（最容易混淆）

1. 关系 vs 关系模式 vs 关系数据库模式

❌ 常见错误

  • 把“关系”和“关系模式”当成一回事

  • 认为表结构和表数据没有区别

✔ 正确认知

  • 关系（Relation）：某一时刻的数据（表的内容）

  • 关系模式（Schema）：表结构（列定义）

  • 数据库模式：多个关系模式的集合

👉 一句话记忆：
模式是“定义”，关系是“数据”

2. 域 vs 属性 vs 分量

❌ 常见错误

  • 把“域”当成列

  • 把“分量”和“属性”混用

✔ 正确认知

  • 域：取值范围（类型空间）

  • 属性：列名

  • 分量：某一行中的具体值

👉 举例：
学生(学号, 年龄)

  • 年龄 → 属性

  • “20” → 分量

  • “整数集合” → 域

3. 笛卡尔积 vs 关系

❌ 常见错误

  • 认为关系 = 笛卡尔积

✔ 正确认知

  • 笛卡尔积：所有组合

  • 关系：合法组合的子集

👉 关键点：
关系 = 筛选后的笛卡尔积

二、关系结构层易错点（考试高频）

4. “关系是集合”这一点被忽略

❌ 常见错误

  • 认为表中可以有重复行

✔ 正确认知

  • 关系是集合 → 元组不能重复

5. 列顺序 / 行顺序问题

❌ 常见错误

  • 认为列顺序有意义

  • 认为行顺序有意义

✔ 正确认知

一、数据模型总论

  1. 数据模型的定义
    数据模型是用来抽象、表示和处理现实世界中的数据和信息的工具，本质上是对现实世界数据特征的抽象。它是数据库研究中的核心问题之一。

  2. 数据模型的两层含义
    广义上，数据模型是数据库研究的核心；狭义上，每个 DBMS 都建立在某种具体的数据模型之上。PDF 指出，常见的传统数据模型包括层次模型、网状模型和关系模型。

  3. 数据模型的分类
    数据模型按应用目的可分为两类：
    （1）概念模型，也称信息模型，按用户观点对数据和信息建模，主要用于数据库设计。
    （2）数据模型，按计算机系统观点对数据逻辑结构建模，主要用于 DBMS 实现。其下又可分为逻辑数据模型和物理数据模型。逻辑数据模型包括层次模型、网状模型、关系模型、面向对象模型、对象关系模型等；物理数据模型描述数据在系统内部的表示方式和存取方法。

  4. 数据模型的三个要素
    数据模型通常由数据结构、数据操作、完整性约束三个要素组成。
    （1）数据结构：描述数据库的组成对象及对象之间的联系，是刻画数据模型性质最重要的方面。
    （2）数据操作：描述对数据库对象实例允许执行的操作集合，包括检索、插入、删除、修改等，同时要定义操作的含义、符号、规则及语言。
    （3）完整性约束条件：一组完整性规则，用于限定符合数据模型的数据库状态及状态变化，保证数据正确、有效、相容。

  5. 静态与动态特性
    数据结构描述系统静态特性；数据操作描述系统动态特性。完整性约束则是保证系统状态合法的规则体系。

二、E-R 概念模型

  1. 概念模型的作用
    概念模型用于信息世界建模，是现实世界到机器世界之间的中间层次，也是数据库设计的有力工具和数据库设计人员与用户之间交流的语言。它的要求是语义表达能力强，同时简单、清晰、易于理解。E-R 模型是最著名的概念模型。

  2. E-R 模型的三大基本概念
    （1）实体（Entity）：客观存在并可相互区别的事物，可以是具体对象，也可以是抽象概念。
    （2）属性（Attribute）：实体具有的某一特征，用来刻画实体。属性有“型”和“值”之分，属性名是型，具体内容是值。
    （3）联系（Relationship）：现实世界中事物内部以及事物之间的联系，在信息世界中抽象为实体内部的联系和实体之间的联系。

  3. 联系的基本类型
    （1）一对一联系（1:1）：实体集 A 中一个实体至多对应实体集 B 中一个实体，反之亦然。例子是“班级与班长”，一个班级只有一个正班长，一个班长只在一个班中任职。
    （2）一对多联系（1:n）：实体集 A 中一个实体对应实体集 B 中的多个实体，反过来一个 B 中实体至多对应一个 A 中实体。例子是“班级与学生”，一个班级中有若干学生，一个学生只在一个班级中学习。
    （3）多对多联系（m:n）：实体集 A 中一个实体对应实体集 B 中多个实体，反之亦然。例子是“课程与学生”，一门课程有若干学生选修，一个学生也可选修多门课程。

  4. 多元联系
    两个以上实体集之间也可以存在联系，称为多元联系。PDF 以“供应商—零件—工程”为例，说明三者之间存在 m:n:p 的联系，表达的是“某个供应商供应某种零件给某个工程”。

  5. 三元联系与二元联系的区别
    这是本章非常关键的细节。PDF 明确指出，三个实体集两两之间的多对多联系，只能表示“一个工程需要哪些零件”“这些零件可以由哪些供应商供应”，却不能表示“一个工程所用的零件具体由哪个供应商供应”以及“一个供应商具体供应哪种零件给哪个工程”。因此，三元联系不能简单拆成三个二元联系，否则会丢失语义。

  6. 同一实体集内部的联系
    PDF 还强调，联系不只存在于不同实体集之间，同一实体集内部也可以有联系。典型例子是职工实体集内部的“领导与被领导”关系：某一职工可以领导若干职工，而一个职工仅被另一个职工直接领导，这是同一实体型内部的一对多联系。PDF 也提到，同一实体集内部还可能存在一对一联系和多对多联系。

  7. E-R 图的表示方法
    E-R 图有三个基本成分：实体、属性和联系。
    （1）实体用矩形表示，矩形框内写实体名。
    （2）属性用椭圆表示，并用无向边与对应实体连接。
    （3）联系用菱形表示，菱形框内写联系名，再用连线把关联实体连接起来，并在连线旁标明联系类型 1:1、1:n 或 m:n。

  8. 联系的属性
    联系本身也可以有属性。PDF 的“选课”例子中，成绩是联系“选课”的属性，而不是学生实体或课程实体的属性，因为成绩描述的是“学生选修某门课程”这个联系。

  9. 弱实体
    弱实体是一类特殊实体，它的存在依赖于其他实体而存在。与弱实体相对应，所依赖的实体称为强实体。弱实体在 E-R 模型中用双框矩形表示，与菱形联系间用双线连接，以表示全部参与。PDF 举例说，在学生管理信息中，家长实体依赖学生实体存在，因此家长可视为弱实体。

  10. 子类实体
    扩展 E-R 模型中增加了子类和超类概念，使模型更有语义表达能力。一个实体集中的个体可以根据不同特性划分为多个子集。PDF 的例子是学校一个系的职工可分为教师、实验人员和机关工作人员，它们共享姓名、年龄、性别等共同属性，同时又有各自的特殊属性。

  11. E-R 模型的用途与特点
    E-R 模型广泛用于数据库概念模型设计。它只表示现实世界中的信息结构及信息之间的关系，不涉及信息在计算机中的表示；只要用户需求不变，E-R 模型是稳定的，并且可以方便地转换成具体 DBMS 支持的数据模型。

  12. PDF 中的综合建模例子
    工厂物资管理模型是本章最完整的例子之一。它涉及五类实体：仓库、零件、供应商、项目、职工。
    （1）仓库：仓库号、面积、电话号码。
    （2）零件：零件号、名称、规格、单价、描述。
    （3）供应商：供应商号、姓名、地址、电话号码、账号。
    （4）项目：项目号、预算、开工日期。
    （5）职工：职工号、姓名、年龄、职称。
    这些实体之间的联系包括：仓库和零件是 m:n 联系，联系属性为库存量；仓库和职工是 1:n 联系；职工内部存在领导与被领导的一对多联系；供应商、项目和零件三者之间存在多对多的三元联系。这个例子综合体现了本章几乎所有 E-R 概念。

三、层次数据模型

  1. 层次模型的定义
    层次模型是数据库系统中最早出现的数据模型，典型代表是 IBM 的 IMS。它用树型结构表示各类实体及实体间联系。现实世界中许多关系具有天然层次性，例如家族关系和行政机构。

  2. 层次模型的结构条件
    满足下面两个条件的基本层次联系集合构成层次模型：
    （1）有且只有一个结点没有双亲结点，该结点称为根结点。
    （2）根以外的其他结点有且只有一个双亲结点。

  3. 层次结构中的术语
    根结点位于最上层；其他结点的上一级结点称为双亲结点；同一双亲结点的子女结点称为兄弟结点；没有子女的结点称为叶结点。双亲结点到子女结点之间表示记录间的一对多联系。

  4. 层次模型的优点
    结构简单清晰；查询效率高；提供较好的数据完整性支持。

  5. 层次模型的缺点
    不能直接表示两个以上实体型间的复杂联系和实体型间的多对多联系，通常要通过引入冗余数据或虚拟结点来解决，容易产生不一致性；插入和删除操作限制较多；查询子女结点必须通过双亲结点；由于结构严密，层次命令趋于程序化。

四、网状数据模型

  1. 网状模型的定义
    网状模型用有向图表示实体及实体间的联系，是对层次模型局限性的突破。现实世界中的许多事物之间是非层次关系，因此网状模型比层次模型更接近实际。

  2. 网状模型的结构条件
    基本网状模型满足两个条件：
    （1）允许一个以上的结点没有双亲。
    （2）一个结点可以有多于一个的双亲。

  3. 网状模型与层次模型的关系
    PDF 明确指出，层次模型实际上是网状模型的特例。两者从结构上看，层次模型是树，网状模型是图；当多个结点都可以有多个双亲时，有向树就变成了有向图。

  4. 网状模型的优点
    能更直接地描述现实世界，例如一个结点可以有多个双亲；性能较好，存取效率较高。

  5. 网状模型的缺点
    结构复杂，随着应用环境扩大，数据库结构会越来越复杂，不利于最终用户掌握；DDL、DML 语言复杂，用户不容易使用；访问数据时必须自行选择存取路径，增加程序编写负担。

  6. 网状模型如何表示多对多联系
    PDF 提到，网状模型可以间接表示多对多联系，方法是将多对多联系分解成一对多联系，并用联结记录来处理。

五、关系数据模型

  1. 关系模型的重要地位
    关系模型是最重要的数据模型。E.F. Codd 于 1970 年系统而严格地提出关系数据模型，并随后提出关系代数、关系演算以及关系范式理论，奠定了现代数据库的理论基础，1981 年因此获得图灵奖。

  2. 关系数据库的发展
    PDF 提到，1977 年 IBM 的 System R 开始运行，后来出现了基于 System R 的 SQL/DB。20 世纪 80 年代以来，几乎所有数据库管理系统都支持关系模型，非关系系统也增加了关系接口；当前数据库研究工作也以关系方法为基础，关系数据库成为最广泛应用的数据库系统。

  3. 关系模型的基本结构
    关系模型中，基本数据结构被限制为二维表，一张二维表称为一个关系。一个关系可用于描述一个实体集。

  4. 关系模型中的基本术语
    （1）关系（relation）：二维表，由行和列组成。
    （2）属性（attribute）：关系中的一列。
    （3）域（domain）：某属性的取值集合，即属性的取值范围。
    （4）元组（tuple）：关系中的一行，表示实体集中的一个个体。
    （5）键（key）：一个或多个属性组成，能够唯一标识一个元组。一个关系中可能有多个键，其中选定一个为主键，其余为候选键。

  5. 关系模式
    对关系结构的描述称为关系模式，形式通常写作“关系名(属性名1, 属性名2, …, 属性名n)”。例如学生关系可表示为“学生(学号, 姓名, 出生年月, 性别, 入学年份, 班级)”。关系数据库模式是一组关系模式的集合，而这些关系模式对应的关系集合构成关系数据库。

  6. 关系模型中实体与联系的表示
    关系模型中，基本数据结构是单一的关系，现实世界中的实体以及实体间的联系都用关系表示。E-R 模型中的联系在关系模式中也可以用表表示，例如“选课”联系可用“选课(学号, 课程号, 成绩)”表示，其中成绩是联系自身的描述属性。

  7. 关系模型的规范化要求
    关系必须规范化，最基本的规范条件是：关系的每一个分量必须是一个不可分的数据项。PDF 用“职工工资”表说明，如果一个属性中又包含“基本工资、工龄、职务、房租、水电”等嵌套成分，就不符合关系模型要求。

  8. 关系模型的数据完整性约束
    为维护数据库与现实世界的一致性，需要对数据施加约束条件。关系模型中主要有三类完整性约束：实体完整性、参照完整性、用户自定义完整性。

  9. 关系模型的数据操纵
    关系模型中的数据操作包括查询、插入、删除和修改。关系数据库系统中对数据的全部操作都可以归结为关系运算；关系运算结果形成一个新关系；关系运算分为关系代数和关系演算。

  10. 关系模型的优点
    PDF 归纳的关系模型优点包括：数据结构简单；一体化的数据子语言；数据独立性高；面向集合的存取方式；理论基础坚实；有利于开展其他应用。

  11. 概念模型与关系数据模型的对应
    PDF 给出了一组非常重要的对应关系：
    （1）E-R 模型中的实体集对应关系表。
    （2）实体集属性对应表的列。
    （3）联系集及其属性也可对应表和列。
    （4）实体的实例对应表中的各行。
    （5）主键或候选键对应关系表中的主键或候选键。
    （6）数据操作在实现层面对应 SQL 语句，在理论层面对应关系代数和关系演算。
    （7）联系类型约束、键约束、完全参与约束在关系模型中分别对应实体完整性、参照完整性和用户自定义完整性。

六、面向对象数据模型

  1. 面向对象数据库系统的两条路线
    PDF 指出，对象关系数据库系统 ORDBS 是面向对象数据模型和关系数据模型结合的产物。研究路线有两条：一是建立新的面向对象数据库系统 OODB，直接支持 OO 数据模型；二是以关系数据库和 SQL 为基础，把面向对象技术融入数据库系统，形成 ORDBS。

  2. 对象的定义
    对象是由一组数据结构和在这组数据结构上的操作程序代码封装起来的基本单位。对象由属性集合和方法集合构成：属性描述状态、组成和特性，方法描述行为特性。

  3. OID
    OID 是对象标识符，即每个对象都有一个唯一且不变的标识。它具有永久持久性、独立于值、系统全局唯一等特点。

  4. 封装
    封装是对象的外部界面与内部实现之间实行清晰隔离的一种抽象，外部与对象的通信只能通过消息。对象封装后，查询属性值必须通过调用方法。

  5. 类
    类是共享同样属性和方法集的所有对象构成的集合。对象是某一类的实例，在 OODB 中，类是“型”，对象是某一类的“值”。

  6. 类层次结构
    PDF 以“教员、行政人员、工人继承教职员工类和人的属性与方法”为例，说明面向对象模型中存在类层次结构；子类在逻辑上继承父类的所有属性和方法，同时还拥有自身特有的属性和方法。

  7. 关系模型与 OO 模型的比较
    PDF 从多个角度对比两者：关系模型的基本数据结构是二维表，OO 模型是类；关系模型使用码作为标识，OO 模型使用 OID；关系模型的动态行为用关系操作描述，OO 模型用方法描述；OO 模型支持抽象数据类型和封装，而关系模型没有；关系模型主要依赖主外码联系和数据依赖，OO 模型则强调继承和组合；OO 模型的模式演化能力较强。

  8. 面向对象数据库研究中的问题
    PDF 指出，OO 数据库研究中存在缺乏通用数据模型、缺乏理论基础、缺乏友好的用户界面与工具环境、缺乏有力的查询优化、商业上没有建立坚实基础等问题。

七、概念模型与数据库系统支持的数据模型的关系

  1. 两类数据模型
    一类是概念模型，用于表示信息结构，不涉及信息在计算机中的表示，典型代表是 E-R 模型；另一类是数据库系统支持的数据模型，包括层次数据模型、网状数据模型、关系数据模型、面向对象数据模型等。

  2. 从概念到实现的路径
    数据库设计通常先把现实世界抽象为概念模型，再把概念模型转换为某种具体的数据模型。这说明概念模型是设计起点，而关系模型、层次模型、网状模型等是实现层面的表达方式。

  3. 本章的核心逻辑
    本章实际上是在讲三件事：
    （1）怎样用 E-R 模型描述现实世界；
    （2）怎样理解不同逻辑数据模型的结构差异；
    （3）怎样把概念模型转换成关系模型并用约束保证正确性。

八、小结

  1. 本章最重要的结论
    数据模型分为概念模型和数据库系统支持的数据模型；概念模型中最重要的是 E-R 模型；数据库系统支持的数据模型中，层次模型、网状模型、关系模型、面向对象模型各有特点，但目前应用最广泛的是关系模型。

  2. E-R 模型的核心
    关键不是只会画图，而是要能准确识别实体、属性、联系，区分 1:1、1:n、m:n，理解实体内部联系、三元联系、弱实体、子类实体，并能将联系属性正确放到联系上。

  3. 关系模型的核心
    关系模型把现实世界统一映射为二维表，强调原子性、完整性约束和关系运算，是当前数据库系统的主流基础。

  4. 层次模型、网状模型、关系模型的关系
    层次模型是树，网状模型是图，关系模型是表；层次模型结构最简单但表达能力弱，网状模型表达能力更强但复杂，关系模型在表达能力、理论基础和使用便利性之间取得了最好平衡。

一、数据模型总论（+ 易错点）

核心结构回顾

  1. 数据模型 = 对现实世界数据特征的抽象

  2. 分类：

    • 概念模型（E-R）

    • 逻辑模型（层次 / 网状 / 关系 / OO）

    • 物理模型

  3. 三要素：

    • 数据结构（静态）

    • 数据操作（动态）

    • 完整性约束（规则）

易错点与分析

易错点1：混淆“概念模型”和“数据模型”

  • 错误理解：E-R模型也是DBMS直接使用的模型

  • 本质原因：没有区分“设计阶段”和“实现阶段”

✔ 正确理解：

  • E-R模型 → 用来“画世界”（设计）

  • 关系模型 → 用来“落地”（实现）

易错点2：三要素记不清 / 混淆

  • 常见错误：

    • 把“完整性约束”当成数据操作

    • 忘记“数据结构是核心”

✔ 正确记忆：

  • 静态：数据结构

  • 动态：数据操作

  • 规则：完整性约束

二、E-R 概念模型（+ 易错点重点）

核心结构回顾

  1. 基本概念：

    • 实体

    • 属性（型 + 值）

    • 联系（实体间 / 实体内部）

  2. 联系分类：

    • 按数量：1:1 / 1:n / m:n

    • 按实体数：二元 / 多元

    • 按范围：实体间 / 实体内部

  3. 扩展：

    • 弱实体

    • 子类实体

易错点与分析（这一章最重要部分）

易错点1：把“联系属性”放到实体里

例子：成绩

❌ 错误：

  • 学生表加“成绩”

  • 课程表加“成绩”

✔ 正确：

  • 成绩属于“选课联系”

👉 原因分析：
成绩依赖两个实体（学生+课程），不是单个实体属性

👉 判断口诀：
“属性是否依赖多个实体？” → 是 → 放联系

易错点2：m:n 不建表

❌ 错误：

  • 直接用外键表示多对多

✔ 正确：

  • 必须建中间表（联系表）

👉 原因：
关系模型无法直接表达 m:n

易错点3：三元联系拆错（高频考点）

❌ 错误：
把“供应商-零件-工程”拆成三个两两关系

✔ 正确：
必须保留三元联系

👉 本质原因：
两两关系只能表达：

  • 谁和谁有关

但表达不了：

  • 谁 给 谁 提供 什么

👉 关键结论：
三元联系 = 信息更完整

易错点4：不会识别“实体内联系”

❌ 常见忽略：
只会画不同实体之间关系

✔ 正确：
同一实体内部也有联系

例：

  • 职工 → 领导关系（1:n）

易错点5：弱实体判断错误

❌ 错误理解：
“有外键就是弱实体”

✔ 正确判断：
弱实体必须满足：

  1. 不能独立存在

  2. 依赖强实体标识

例：

  • 家长依赖学生 ✔

  • 订单依赖用户 ✔（典型）

易错点6：子类实体理解不清

❌ 错误：
把子类当普通实体

✔ 正确：
子类 = 继承结构

👉 特点：

  • 共享父类属性

  • 有自己特有属性

三、层次模型（+ 易错点）

核心回顾

  1. 树结构

  2. 一个根节点

  3. 每个节点只有一个父节点

  4. 只能表达 1:n

易错点与分析

易错点1：认为可以表示 m:n

❌ 错误：
觉得树可以扩展表达多对多

✔ 正确：
不能，必须靠冗余或虚拟节点

易错点2：忽略访问路径限制

✔ 正确认知：
必须从根访问

👉 本质：
不是“表查询”，而是“路径访问”

四、网状模型（+ 易错点）

核心回顾

  1. 图结构

  2. 一个节点可以有多个父节点

易错点与分析

易错点1：认为“更高级”

❌ 错误：
网状模型 > 关系模型

✔ 正确：
只是更复杂，不更优

易错点2：忽略“路径依赖”

✔ 正确理解：
查询需要手动指定路径

👉 这是它难用的根本原因

五、关系模型（+ 易错点重点）

核心结构回顾

  1. 关系 = 表

  2. 元组 = 行

  3. 属性 = 列

  4. 域 = 取值范围

  5. 键 = 唯一标识

易错点与分析（考试重点）

易错点1：属性不原子（最常考）

❌ 错误：
一个字段存多个值

例：

  • 工资 = (基本+奖金+补贴)

✔ 正确：
必须拆开

👉 原因：
关系模型要求“不可分”

易错点2：主键理解错误

❌ 错误：

  • 主键可以重复

  • 主键可以为空

✔ 正确：

  • 唯一 + 非空

易错点3：候选键 vs 主键

❌ 混淆：
认为只有一个键

✔ 正确：

  • 候选键：可能的主键

  • 主键：选定的一个

易错点4：联系不转表

❌ 错误：
E-R 有联系，但关系模型不建表

✔ 正确：

  • m:n → 必建表

  • 1:n → 可用外键

易错点5：完整性约束混乱

❌ 错误：
分不清三种约束

✔ 正确：

  • 实体完整性：主键

  • 参照完整性：外键

  • 用户定义：业务规则

易错点6：关系运算理解错误

❌ 错误：
SQL = 随便写

✔ 正确：
SQL 背后是：

  • 关系代数

  • 关系演算

六、面向对象数据模型（+ 易错点）

核心回顾

  1. 对象 = 数据 + 方法

  2. OID 唯一标识

  3. 封装

  4. 类

易错点与分析

易错点1：把 OID 当普通字段

✔ 正确：
OID 是系统级唯一标识，不是用户字段

易错点2：忽略“方法”

✔ 正确：
对象不仅有数据，还有行为

易错点3：封装理解错误

✔ 正确：
不能直接访问属性，要通过方法

七、概念模型 → 关系模型（转换）（+ 易错点）

核心规则

  1. 实体 → 表

  2. 属性 → 列

  3. 实体实例 → 行

  4. 联系 → 表或外键

易错点与分析

易错点1：所有联系都建表

❌ 错误：
1:n 也建表

✔ 正确：

  • m:n → 建表

  • 1:n → 外键即可

易错点2：忽略联系属性

✔ 正确：
联系属性必须进入关系表

易错点3：主键设计错误

✔ 正确：
联系表主键通常是：

  • 外键组合

八、小结（+ 易错点终极总结）

本章核心逻辑

  1. 用 E-R 模型描述现实世界

  2. 用关系模型实现

  3. 用约束保证正确

最容易丢分的 5 个点（强烈建议背）

  1. 成绩属于联系，不属于实体

  2. m:n 必须建中间表

  3. 三元联系不能拆

  4. 属性必须原子化

  5. 主键必须唯一且非空

一句话总纲（考试用）

E-R 负责建模语义，关系模型负责结构实现，而完整性约束负责保证数据正确性。
