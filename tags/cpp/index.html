二、本章核心规则

  • 继承和组合复用的是对象代码，模板复用的是源代码。

  • 模板提供的是一种把“类型”当成参数来用的泛型编程方式。

  • 模板分为两类：函数模板 和 类模板。

  • 模板被具体类型替换、生成可用函数/类的过程叫 template instantiation。

  • 函数模板的类型参数通常写成 typename T 或 class T。

  • 类模板的成员函数如果放到类外定义，必须写成模板函数形式。

  • 模板不是“自动万能”，它仍然依赖具体类型能满足模板里使用的操作，比如 >、拷贝、赋值等。这个点从 getmax 和 StackTemplate 例子里都能看出来。

经验句：
模板的本质是：先写一份通用代码，再让具体类型来“套模板”。

二、本章核心规则

  • 面向对象的基本特征包括：封装、继承、多态；动态多态主要靠 virtual functions 实现。

  • 派生类对象可以通过指针或引用当成基类对象来处理，这叫 upcasting。

  • 如果基类函数声明为 virtual，那么它在所有派生类中都保持虚函数属性。

  • 继承中对虚函数的重新定义叫 overriding。

  • 同名不同参的同一类函数是 overloading；普通成员函数在继承里被重新定义，常叫 redefining。

  • 使用虚函数实现多态时，必须通过基类指针或引用调用；直接拿对象本身调用时，编译器知道精确类型，通常是早绑定。

  • 作用域解析运算符 :: 会绕过虚函数机制。

  • 虚函数必须是非静态成员函数。

  • 构造函数不能是 virtual。

  • 析构函数通常应该是 virtual；如果基类析构函数是 virtual，派生类析构函数会自动成为 virtual。

  • 抽象类至少含有一个纯虚函数；纯虚函数写成 = 0。

  • 发生对象按值传递时，可能出现 object slicing（对象切片）。

  • 除了赋值运算符，一般运算符也可以像普通成员函数一样做虚函数。

经验句：
这章就背四个词：upcasting、virtual、override、slicing。

1. 这是早绑定还是晚绑定

看调用对象是不是通过指针/引用传入。

2. 虚函数是否真正被覆盖

看函数签名是否完全一致，名字、参数、返回类型都要对。

3. 作用域解析后会不会还走虚函数

不会，A::f() 会绕过动态绑定。

4. 抽象类能不能实例化

不能，只能拿来做基类或用引用/指针。

5. 基类指针 delete 派生类对象时会发生什么

如果析构函数不是 virtual，派生类资源可能不会被正确释放。

6. 是否发生对象切片

看函数参数是不是按值传递。按值传递非常容易切片。

步骤 1：先看「调用方式」（决定上限）

先看你是用什么调用函数的，3 种情况：

  1. 子类普通对象 Derived d; d.f();

  2. 父类指针 / 父类引用 Base* p = &d; Base& r = d;

    → 只认父类的接口，子类新增的函数永远看不见

    → 重写的虚函数会多态调子类

  3. 按值传递 Base b = d;

    → 对象切片，彻底变成父类，只调用父类

步骤 2：看函数「在哪同名」

  • 都在同一个类 → 直接判定：重载
  • 一个父类、一个子类 → 进入步骤 3

步骤 3：对「函数签名」判重写 / 重定义

父类和子类都有同名函数：

  1. 签名完全一样 + 父类 virtual

    → 重写 (Override)

  2. 签名不一样（参数不同 /const 不同）

    → 重定义 / 名字隐藏

步骤 4：定最终调用结果

  1. 子类对象 + 重写 → 调子类
  2. 子类对象 + 重定义 → 父类同名全隐藏，只能调子类自己的
  3. 父类指针 / 引用 + 重写 → 多态，运行时调子类
  4. 父类指针 / 引用 + 子类新增函数 → 报错（父类没有）
  5. 按值传递 → 永远调父类

二、本章核心规则

  • C++ 的一个重要特性是代码复用，类之间的关系通常通过 composition 和 inheritance 来表达。composition 是 has-a，inheritance 是 is-a。
  • 组合和继承都会让新类里包含子对象，只是来源不同：组合是把成员对象放进去，继承是把基类子对象放进去。
  • 派生类对象创建时，先构造基类子对象，再构造成员子对象，最后构造派生类自己。析构顺序相反。
  • 构造函数初始化列表可以显式调用成员对象或基类构造函数。
  • 如果派生类里重新定义了某个函数名，基类里同名的其他重载版本会被自动隐藏。
  • 构造函数、析构函数、赋值运算符不会自动继承。

  • C++ 对象在创建时，通常会发生两件事：先分配存储空间，再调用构造函数初始化。

  • 一个指针只能被 delete / delete[] 释放一次。

第一部分：知识点（普通文本）

1. Name Control 的核心目标

这一章讲的是如何控制“名字”的创建、可见性、存储位置和链接属性。课件把重点放在两类机制上：static 和 namespace。前者用于限制名字可见范围、改变存储方式，后者用于把全局名字拆分到更可管理的命名空间中。

2. static 的两个基本含义

static 有两个核心作用。第一，它可以控制名字的可见性，使该名字不能在翻译单元外或类外被看到；第二，它表示对象存储在静态数据区，而不是每次函数调用时都在栈上重新创建。也就是说，static 同时涉及“作用域/链接”与“存储期”两个层面。

3. 函数内 static 变量

函数内部的 static 局部变量会在多次函数调用之间保留值。它只在第一次执行到定义处时初始化一次，之后不会再次初始化。若是内置类型且没有写初值，编译器会保证它被初始化为 0。普通局部变量则每次调用都会重新创建并销毁。

4. 函数内 static 对象

函数内部的 static 用户自定义类型对象也是“只构造一次”。它的构造发生在第一次调用到该语句时，之后一直存在到程序结束。对于用户定义类型，如果没有提供初始化器，通常要求有默认构造函数。课件中的例子说明：static 对象的构造与析构时机，和普通局部对象完全不同。

5. 对象的构造与析构顺序

全局对象在进入 main() 之前就会被构造；函数内的 static 对象则只有函数被调用时才会构造。程序结束时，已经构造出来的对象会按照“构造的逆序”析构。课件里通过全局对象、static 局部对象和普通局部对象的组合，演示了析构顺序的差异。

6. static 数据成员

类中的 static 数据成员属于整个类，而不是某个具体对象。所有对象共享这一份存储空间。它必须在类外进行定义和初始化，写法通常是 int Myclass::obj = 8;，而且这里不再写 static。这类成员常用于表示“全类共享数据”。

7. static 成员函数

static 成员函数不依赖某个对象，因此没有隐含的 this 指针。它只能直接访问类的 static 数据成员，不能直接访问普通非静态成员。static 成员函数可以像普通函数一样通过类名调用，也可以在类内部直接定义，从而成为内联形式。

8. 链接属性与存储类型

课件把“可见性/链接”和“存储位置”分开讲：外部链接的名字可以在多个翻译单元中可见，普通全局变量和普通函数通常是外部链接；内部链接则只在本翻译单元可见，static、const、inline 名字通常默认具有内部链接。存储类型则常分为静态数据区、栈和堆，对应全局/静态对象、局部对象、new 创建的对象。

9. namespace 的作用

namespace 的目的，是把全局命名空间拆分成若干逻辑模块，减少大型项目中的名字冲突。命名空间里的名字不会直接污染全局空间，使用时可以通过作用域限定符访问，也可以通过 using 引入。

10. 命名空间的创建与使用

命名空间只能出现在全局作用域或另一个命名空间内部，不能像类一样创建对象；结尾也不需要分号。命名空间还可以起别名。使用命名空间时有两种常见方式：using directive 一次性引入整个命名空间的名字，using declaration 只引入某一个名字。

11. 作用域限定符的用途

作用域解析运算符 :: 可以用来定义或访问命名空间中的名字，也可用于类外定义类成员。课件中的例子展示了在命名空间中先声明类，再在外部定义其成员函数、嵌套类和普通函数的写法。

12. using 的两种方式

using namespace X; 会把整个命名空间引入当前作用域，适合小范围、短代码；using X::name; 只引入一个名字，更安全、更精确。课件还强调：在头文件里不要写全局 using directive，否则容易把名字污染到所有包含该头文件的文件中。

第二部分：易错点（普通文本）

1. 把 static 只理解成“变量不变”

很多人会把 static 简单理解成“值不变”，这是不完整的。课件强调 static 有两层意思：一层是名字的可见性/链接，一层是静态存储期。也就是说，static 的重点不是“常量”，而是“生命周期更长、可见范围更受控”。

2. 把 static 局部变量和普通局部变量混淆

普通局部变量每次进入函数都会重新创建；static 局部变量只初始化一次，并在多次调用间保留状态。课件里的例子里，n++ 会跨调用累加，而 x++ 每次都从 1 重新开始。

3. 忘记 static 内置类型默认置零

如果 static 内置类型没有显式初始化，编译器保证其被初始化为 0。很多人会误以为它是“随机值”，但课件明确给出了这个规则。这个点常用于判断程序第一次输出。

4. 误解 static 对象的构造和析构时机

函数内 static 对象不是每次进入函数都构造；它只在第一次执行到该语句时构造。析构也不是函数退出时发生，而是在程序结束时统一清理。这个差异是静态对象题的高频失分点。

5. 忘记静态成员必须类外初始化

static 数据成员只是“声明在类里”，真正的定义与初始化必须写在类外，而且不再写 static。如果只在类中声明而不在类外定义，链接阶段通常会出问题。

6. 把 static 成员函数当成普通成员函数

static 成员函数没有 this，所以不能直接访问普通非静态成员。它只能直接碰 static 成员。考试里经常通过“能不能访问某个变量”来考这个区别。

7. 混淆外部链接和内部链接

普通全局变量和函数通常是外部链接，能被多个翻译单元看到；static 名字通常只有内部链接。const 和 inline 名字也常默认表现为内部链接。这个点如果和“存储位置”混在一起，很容易答错。

8. 把 namespace 当成类

namespace 不能实例化，也不能像类那样有对象。它只是一个“名字容器”。很多同学会把“namespace 里能放类”误解成“namespace 本身也是一种类”，这是不对的。

9. using directive 和 using declaration 混用

using namespace calculator; 会把整个命名空间的名字都引入，可能导致重名和二义性；using calculator::Add; 只引入某个名字，更稳妥。课件还演示了引入整个命名空间后，调用 Print 可能和外部同名函数冲突。

10. 在头文件里写全局 using directive

课件明确提醒：不要在头文件里使用全局 using directive。因为头文件会被多个源文件包含，这会把命名空间里的名字无控制地扩散到全局作用域，造成命名冲突。

1. Inline Function 的核心思想

Inline function（内联函数）的本质是：用函数的方式写代码，但在编译阶段像宏一样直接展开。

作用：

  • 消除函数调用开销（不需要压栈、跳转、返回）
  • 提高运行效率（尤其是小函数被频繁调用时）

例如：

inline int max(int a, int b) {
return a > b ? a : b;
}

调用：

max(a, b)

在编译时会被替换为：

(a > b ? a : b)

2. Inline vs 宏（#define）

（1）宏的本质

宏是纯文本替换（预处理阶段），没有语法检查。

#define MAX(a, b) a > b ? a : b

问题示例：

int c = MAX(a, b) + 2;

实际展开为：

a > b ? a : b + 2

优先级错误，导致结果不符合预期。

（2）宏的缺点

  1. 容易产生隐藏 Bug（优先级问题）
  2. 没有类型检查
  3. 不能作为类成员函数
  4. 调试困难

（3）Inline 的优势

Inline 函数：

  • 有类型检查
  • 符合函数语义
  • 可以作为类成员函数
  • 编译器可优化

👉 结论：C++ 中应优先使用 inline，避免使用宏

3. Inline 的工作机制

编译器处理 inline 函数时：

  • 保存函数类型（函数签名）
  • 同时保存函数体
  • 在调用处尝试展开

但注意：
👉 inline 只是建议（hint），编译器可以拒绝

当函数很短但调用很多次时，用 inline 可以减少函数调用开销，提高效率。
inline 函数会在编译时像宏一样展开，从而避免函数调用过程。
但相比宏，inline 更安全，所以应尽量用 inline 代替宏。

#define MAX(a, b) ((a) > (b) ? (a) : (b))

第一部分：知识点整理（普通文本）

1. const 的核心作用

  • const 用于区分“可变”和“不可变”
  • 提供：
    • 类型安全（比 #define 更强）
    • 编译期检查
    • 程序稳定性

与 #define 的区别

  • #define：纯文本替换，无类型检查
  • const：
    • 有类型
    • 编译器可检查错误
    • 更安全

2. const 基本规则

  • const 变量必须初始化
  • 一旦初始化，不能修改

示例：

  • const int x = 10; ✔
  • const int x; ✘（未初始化）
  • x = 20; ✘（不可修改）

数组：

  • const int a[] = {1,2,3}
    • 每个元素都不可修改

3. const 与指针（重点）

判定原则

👉 const 修饰“离它最近的对象”

3.1 指向常量的指针（pointer to const）

定义：

  • const int* p
  • int const* p

特点：

  • 可以改指针指向
  • 不能改指针指向的值

示例：

  • p = &x ✔
  • *p = 10 ✘

3.2 常量指针（const pointer）

定义：

  • int* const p

特点：

  • 不能改变指针指向
  • 可以修改值

示例：

  • p = &y ✘
  • *p = 10 ✔

3.3 指向常量的常量指针

定义：

  • const int* const p

特点：

  • 不能改指向
  • 不能改值

总结
在 C/C++ 中，权限本质指的是“是否可以通过某个指针修改数据”。所谓“权限缩小”，就是把原本“可以修改”的对象，通过 const 限制为“不可修改”，这种行为是安全的，因此允许，例如 const int *p 指向变量，本质是“我选择不通过 p 修改它”；
因此指向常量的指针以及指向常量的常量型指针可以指向变量

而“权限放大”则是试图通过指针获得本不具备的修改能力（如用 int * 指向 const int），这会破坏数据的只读性，因此被禁止。

所有指针与常量的规则，本质都遵循一句话：👉 只能减少修改权限，不能增加修改权限；同时 const 只限制“指针的使用方式”，不会改变变量本身的属性，因此“指向常量的指针”“常量指针”“双 const 指针”本质都是在约束“能不能改值”和“能不能改指向”，而是否允许绑定某个对象，取决于是否违反了“不能放大权限”的原则。

  • 能改”的指针 ❌ 不能指向 const
  • “不改”的指针 ✅ 可以指向任何

4.1 参数中的 const

目的：
👉 防止函数修改外部数据

示例：

  • void f(const int* p)
    • *p 不可修改

4.2 返回值中的 const

目的：
👉 防止调用者修改返回对象

示例：

  • const char* func()

int* const w();

int main() {
int* p = w();
p = nullptr;
}
合法 因为虽然p被复制了一个限制地址的指针 但本质是复制 失效。所以可以被重新修改地址

  • int* const w(); 里的 const 限制的只是函数内部的那份指针
  • 函数返回时，你拿到的是拷贝，所以外部的变量 p 不再受原来的 const 限制
  • 也就是 “指针本身的 const 在返回值上失效”

4.3 规则总结

  • const 参数：保护输入
  • const 返回：保护输出

5. 临时对象（Temporaries）

  • 编译器生成的临时对象默认是 const
    因为临时对象生命周期很短，C++不希望你去修改一个马上就要消失的东西
    意义：

  • 防止对临时对象进行非法修改

  • 提高安全性

  • 临时对象 = 没有变量名接收的对象表达式结果

6. 类中的 const（重点大题区）

6.1 static 成员变量

特点：

  • 所有对象共享
  • 必须在类外初始化

格式：

  • int Class::var = value;

6.2 const 成员变量

特点：

  • 必须初始化
  • 只能在构造函数初始化列表中初始化

原因：

  • const 不能先声明再赋值

6.3 初始化列表

作用：

  • 初始化 const 成员
  • 初始化引用成员

示例：

  • A::A(int i) : a(i) {}

6.4 初始化顺序（超级重要）

👉 按“声明顺序”，不是初始化列表顺序

错误来源：

  • 写顺序 ≠ 执行顺序

6.5 const 成员函数

定义：

  • 函数后加 const

特点：

  • 不能修改成员变量

示例：

  • int get() const

错误：

  • return x++ ✘

6.6 const 对象

规则：

对象类型 可调用函数
const对象 只能调用 const函数
非const对象 可调用所有函数

6.7 mutable（非常重要考点）

作用：
👉 允许在 const 函数中修改变量

示例：

  • mutable int x;

意义：

  • 逻辑常量 vs 物理常量

第一部分：知识点（普通文本）

一、构造函数（Constructor）

1. 基本概念

  • 构造函数是在对象创建时自动调用的函数，用于初始化对象。
  • 特点：
    • 函数名与类名相同
    • 没有返回值（连 void 都没有）
    • 在对象定义时自动调用

2. 调用机制

  • 对象创建时自动调用构造函数
  • 编译器隐式传入 this 指针（指向当前对象）

3. 带参数构造函数

  • 构造函数可以有参数
  • 可以用于初始化成员变量

示例思想：

  • 将传入参数赋值给成员变量
  • 实现对象初始化的灵活性

4. 构造函数重载

  • 一个类可以有多个构造函数（参数不同）
  • 编译器根据参数匹配调用对应构造函数

例如：

  • Student(int id)
  • Student(int year, int order)

二、默认构造函数（Default Constructor）

1. 定义

  • 可以无参数调用的构造函数

2. 形式

  • 显式定义：A() {}
  • 或使用默认参数实现：A(int x = 0) 就可以实现额外传几个就改几个。其余的仍为默认值

3. 注意事项

  • 如果定义了带参数构造函数，而没有默认构造函数：
    • 编译器不会自动生成默认构造函数
    • 会导致无法无参创建对象

4. 成员对象影响

  • 类成员对象会先调用其构造函数
  • 若成员类没有默认构造函数，会导致错误

三、析构函数（Destructor）

1. 基本概念

  • 用于对象销毁时释放资源

2. 特点

  • 函数名：~类名
  • 无参数
  • 不能重载
  • 无返回值

3. 调用时机

  • 对象生命周期结束时自动调用：
    • 作用域结束
    • 函数结束
    • delete（动态对象）

4. 调用顺序

  • 构造：先成员 → 后自身
  • 析构：先自身 → 后成员（逆序）

四、构造与析构的执行过程

1. 局部对象

  • 进入作用域：构造
  • 离开作用域：析构

2. 嵌套调用

  • 函数中创建对象：
    • 函数结束立即析构

3. 示例核心逻辑

  • 对象按栈顺序创建
  • 按逆序销毁（类似栈）

  1. 有没有 new？
    有 → 堆对象

  2. 在不在函数里？
    在 → 局部对象（栈）。作用域与函数的生命周期绑定

  3. 在类里面？
    是 → 成员对象。 和这个类的周期绑定。

  4. 在函数外？
    是 → 全局对象。和程序的运行周期绑定

  5. 有 static？
    是 → 静态对象
    对象什么时候死，不看它写在哪个文件，
    只看它在哪个作用域里被“创建”。

真的是栈（物理结构）

对于其他对象

不是栈，但遵循“栈式规则”

第二部分：易错点（普通文本）

一、构造函数相关

  1. 写了带参构造函数但忘记写默认构造函数
    → 导致无法创建无参对象
  2. 误以为构造函数有返回值
    → 实际没有任何返回类型
  3. 构造函数不会自动执行逻辑以外代码
    → 必须手动初始化成员变量
  4. 构造函数重载冲突
    → 参数不明确可能导致二义性

二、默认构造函数陷阱

  1. 一旦定义了有参构造函数，默认构造函数不会自动生成
  2. 类成员对象没有默认构造函数
    → 当前类构造失败

三、析构函数相关

  1. 析构函数不能带参数、不能重载
  2. 忘记释放动态内存
    → 内存泄漏
  3. 错误理解析构顺序
    → 实际是“后构造先析构”

四、对象生命周期错误

  1. 误以为函数结束对象还存在 但注意是函数先结束然后再释放对象
    → 实际已析构
  2. 临时对象生命周期极短
    → 容易产生悬空引用

五、数组相关

  1. 对象数组必须有默认构造函数（除非完全初始化）
  2. 未初始化元素会调用默认构造函数
    → 若不存在则编译错误

六、资源管理错误

  1. 在构造函数中申请资源但析构函数未释放
  2. 使用裸指针但未管理生命周期
