第一部分：知识点（普通文本）

1. Name Control 的核心目标

这一章讲的是如何控制“名字”的创建、可见性、存储位置和链接属性。课件把重点放在两类机制上：static 和 namespace。前者用于限制名字可见范围、改变存储方式，后者用于把全局名字拆分到更可管理的命名空间中。

2. static 的两个基本含义

static 有两个核心作用。第一，它可以控制名字的可见性，使该名字不能在翻译单元外或类外被看到；第二，它表示对象存储在静态数据区，而不是每次函数调用时都在栈上重新创建。也就是说，static 同时涉及“作用域/链接”与“存储期”两个层面。

3. 函数内 static 变量

函数内部的 static 局部变量会在多次函数调用之间保留值。它只在第一次执行到定义处时初始化一次，之后不会再次初始化。若是内置类型且没有写初值，编译器会保证它被初始化为 0。普通局部变量则每次调用都会重新创建并销毁。

4. 函数内 static 对象

函数内部的 static 用户自定义类型对象也是“只构造一次”。它的构造发生在第一次调用到该语句时，之后一直存在到程序结束。对于用户定义类型，如果没有提供初始化器，通常要求有默认构造函数。课件中的例子说明：static 对象的构造与析构时机，和普通局部对象完全不同。

5. 对象的构造与析构顺序

全局对象在进入 main() 之前就会被构造；函数内的 static 对象则只有函数被调用时才会构造。程序结束时，已经构造出来的对象会按照“构造的逆序”析构。课件里通过全局对象、static 局部对象和普通局部对象的组合，演示了析构顺序的差异。

6. static 数据成员

类中的 static 数据成员属于整个类，而不是某个具体对象。所有对象共享这一份存储空间。它必须在类外进行定义和初始化，写法通常是 int Myclass::obj = 8;，而且这里不再写 static。这类成员常用于表示“全类共享数据”。

7. static 成员函数

static 成员函数不依赖某个对象，因此没有隐含的 this 指针。它只能直接访问类的 static 数据成员，不能直接访问普通非静态成员。static 成员函数可以像普通函数一样通过类名调用，也可以在类内部直接定义，从而成为内联形式。

8. 链接属性与存储类型

课件把“可见性/链接”和“存储位置”分开讲：外部链接的名字可以在多个翻译单元中可见，普通全局变量和普通函数通常是外部链接；内部链接则只在本翻译单元可见，static、const、inline 名字通常默认具有内部链接。存储类型则常分为静态数据区、栈和堆，对应全局/静态对象、局部对象、new 创建的对象。

9. namespace 的作用

namespace 的目的，是把全局命名空间拆分成若干逻辑模块，减少大型项目中的名字冲突。命名空间里的名字不会直接污染全局空间，使用时可以通过作用域限定符访问，也可以通过 using 引入。

10. 命名空间的创建与使用

命名空间只能出现在全局作用域或另一个命名空间内部，不能像类一样创建对象；结尾也不需要分号。命名空间还可以起别名。使用命名空间时有两种常见方式：using directive 一次性引入整个命名空间的名字，using declaration 只引入某一个名字。

11. 作用域限定符的用途

作用域解析运算符 :: 可以用来定义或访问命名空间中的名字，也可用于类外定义类成员。课件中的例子展示了在命名空间中先声明类，再在外部定义其成员函数、嵌套类和普通函数的写法。

12. using 的两种方式

using namespace X; 会把整个命名空间引入当前作用域，适合小范围、短代码；using X::name; 只引入一个名字，更安全、更精确。课件还强调：在头文件里不要写全局 using directive，否则容易把名字污染到所有包含该头文件的文件中。

第二部分：易错点（普通文本）

1. 把 static 只理解成“变量不变”

很多人会把 static 简单理解成“值不变”，这是不完整的。课件强调 static 有两层意思：一层是名字的可见性/链接，一层是静态存储期。也就是说，static 的重点不是“常量”，而是“生命周期更长、可见范围更受控”。

2. 把 static 局部变量和普通局部变量混淆

普通局部变量每次进入函数都会重新创建；static 局部变量只初始化一次，并在多次调用间保留状态。课件里的例子里，n++ 会跨调用累加，而 x++ 每次都从 1 重新开始。

3. 忘记 static 内置类型默认置零

如果 static 内置类型没有显式初始化，编译器保证其被初始化为 0。很多人会误以为它是“随机值”，但课件明确给出了这个规则。这个点常用于判断程序第一次输出。

4. 误解 static 对象的构造和析构时机

函数内 static 对象不是每次进入函数都构造；它只在第一次执行到该语句时构造。析构也不是函数退出时发生，而是在程序结束时统一清理。这个差异是静态对象题的高频失分点。

5. 忘记静态成员必须类外初始化

static 数据成员只是“声明在类里”，真正的定义与初始化必须写在类外，而且不再写 static。如果只在类中声明而不在类外定义，链接阶段通常会出问题。

6. 把 static 成员函数当成普通成员函数

static 成员函数没有 this，所以不能直接访问普通非静态成员。它只能直接碰 static 成员。考试里经常通过“能不能访问某个变量”来考这个区别。

7. 混淆外部链接和内部链接

普通全局变量和函数通常是外部链接，能被多个翻译单元看到；static 名字通常只有内部链接。const 和 inline 名字也常默认表现为内部链接。这个点如果和“存储位置”混在一起，很容易答错。

8. 把 namespace 当成类

namespace 不能实例化，也不能像类那样有对象。它只是一个“名字容器”。很多同学会把“namespace 里能放类”误解成“namespace 本身也是一种类”，这是不对的。

9. using directive 和 using declaration 混用

using namespace calculator; 会把整个命名空间的名字都引入，可能导致重名和二义性；using calculator::Add; 只引入某个名字，更稳妥。课件还演示了引入整个命名空间后，调用 Print 可能和外部同名函数冲突。

10. 在头文件里写全局 using directive

课件明确提醒：不要在头文件里使用全局 using directive。因为头文件会被多个源文件包含，这会把命名空间里的名字无控制地扩散到全局作用域，造成命名冲突。

第一部分：知识点

1. Inline Function 的核心思想

Inline function（内联函数）的本质是：用函数的方式写代码，但在编译阶段像宏一样直接展开。

作用：

  • 消除函数调用开销（不需要压栈、跳转、返回）
  • 提高运行效率（尤其是小函数被频繁调用时）

例如：

inline int max(int a, int b) {
return a > b ? a : b;
}

调用：

max(a, b)

在编译时会被替换为：

(a > b ? a : b)

2. Inline vs 宏（#define）

（1）宏的本质

宏是纯文本替换（预处理阶段），没有语法检查。

#define MAX(a, b) a > b ? a : b

问题示例：

int c = MAX(a, b) + 2;

实际展开为：

a > b ? a : b + 2

优先级错误，导致结果不符合预期。

（2）宏的缺点

  1. 容易产生隐藏 Bug（优先级问题）
  2. 没有类型检查
  3. 不能作为类成员函数
  4. 调试困难

（3）Inline 的优势

Inline 函数：

  • 有类型检查
  • 符合函数语义
  • 可以作为类成员函数
  • 编译器可优化

👉 结论：C++ 中应优先使用 inline，避免使用宏

3. Inline 的工作机制

编译器处理 inline 函数时：

  • 保存函数类型（函数签名）
  • 同时保存函数体
  • 在调用处尝试展开

但注意：
👉 inline 只是建议（hint），编译器可以拒绝

当函数很短但调用很多次时，用 inline 可以减少函数调用开销，提高效率。
inline 函数会在编译时像宏一样展开，从而避免函数调用过程。
但相比宏，inline 更安全，所以应尽量用 inline 代替宏。

✅ 最后一句总结（建议记）

👉 inline 是“带类型检查的宏替代方案”，用于减少小函数调用开销，但是否展开由编译器决定

inline 需要在编译阶段展开，而编译是按文件独立进行的，所以函数体必须在当前文件可见，通常放在头文件中

4. Inline 的使用规则（考试重点）

（1）定义必须在调用之前

因为编译器需要看到函数体才能展开。

（2）适用于小函数

适合：

  • 简单计算函数
  • getter/setter
  • 短逻辑

（3）不适合的情况

一般不会被 inline：

  • 含循环（for / while）
  • 含 switch
  • 含异常处理
  • 递归函数
  • 代码过大

5. Inline 在类中的使用

（1）类内定义（自动 inline）

class Point {
public:
void print() const {
// 自动 inline
}
};

👉 在类内部定义的函数默认 inline

（2）类外定义（需要显式 inline）

class Point {
public:
void print() const;
};

inline void Point::print() const {
// 需要 inline 关键字
}

👉 原因：
类外定义默认不是 inline，需要手动声明

6. Inline vs 宏的典型代码对比

宏：

#define f(x) xx
f(x+1) → x+1x+1 → 错误

Inline：

inline int f(int x) {
return xx;
}
f(x+1) → (x+1)(x+1) → 正确

👉 本质区别：

  • 宏：文本替换
  • inline：语法级函数展开

7. Inline 的限制（重要）

  1. 代码过大 → 编译器不会展开
  2. 取函数地址 → 无法 inline
  3. 复杂控制流 → 无法 inline

8. Inline 的使用建议（总结）

  • 小函数 + 高频调用 → 用 inline
  • 复杂逻辑 → 普通函数
  • 不要用宏替代函数

第二部分：易错点总结

1. 宏优先级陷阱（最常考）

错误：

#define MAX(a, b) a > b ? a : b
MAX(a, b) + 2

正确写法（但仍不推荐）：

#define MAX(a, b) ((a) > (b) ? (a) : (b))

👉 但本质解决方案：用 inline

2. 误以为 inline 一定会展开

错误理解：

写了 inline 就一定内联

实际：

  • 编译器可以拒绝
  • 只是建议，不是强制

3. 忘记“定义必须在调用之前”

错误：

int main() {
max(1,2); // 此时未看到定义
}
inline int max(int a, int b) {…}

👉 inline 必须在调用前定义

4. 类外定义忘记 inline

错误：

void Point::print() const { }

👉 会变成普通函数

正确：

inline void Point::print() const { }

5. 误用 inline 处理复杂函数

错误：

  • 循环
  • 递归
  • 大量逻辑

👉 编译器直接忽略 inline

6. 宏与函数混淆

典型误解：

  • 宏 = 函数（错误）
  • 宏没有类型、没有作用域

7. inline 与 const、引用等混用不理解

例如：

void print(const string& msg)

👉 这里重点是：

  • const 防止修改
  • 引用避免拷贝
  • 和 inline 是不同层面的优化

一、数据模型总论

  1. 数据模型的定义
    数据模型是用来抽象、表示和处理现实世界中的数据和信息的工具，本质上是对现实世界数据特征的抽象。它是数据库研究中的核心问题之一。

  2. 数据模型的两层含义
    广义上，数据模型是数据库研究的核心；狭义上，每个 DBMS 都建立在某种具体的数据模型之上。PDF 指出，常见的传统数据模型包括层次模型、网状模型和关系模型。

  3. 数据模型的分类
    数据模型按应用目的可分为两类：
    （1）概念模型，也称信息模型，按用户观点对数据和信息建模，主要用于数据库设计。
    （2）数据模型，按计算机系统观点对数据逻辑结构建模，主要用于 DBMS 实现。其下又可分为逻辑数据模型和物理数据模型。逻辑数据模型包括层次模型、网状模型、关系模型、面向对象模型、对象关系模型等；物理数据模型描述数据在系统内部的表示方式和存取方法。

  4. 数据模型的三个要素
    数据模型通常由数据结构、数据操作、完整性约束三个要素组成。
    （1）数据结构：描述数据库的组成对象及对象之间的联系，是刻画数据模型性质最重要的方面。
    （2）数据操作：描述对数据库对象实例允许执行的操作集合，包括检索、插入、删除、修改等，同时要定义操作的含义、符号、规则及语言。
    （3）完整性约束条件：一组完整性规则，用于限定符合数据模型的数据库状态及状态变化，保证数据正确、有效、相容。

  5. 静态与动态特性
    数据结构描述系统静态特性；数据操作描述系统动态特性。完整性约束则是保证系统状态合法的规则体系。

二、E-R 概念模型

  1. 概念模型的作用
    概念模型用于信息世界建模，是现实世界到机器世界之间的中间层次，也是数据库设计的有力工具和数据库设计人员与用户之间交流的语言。它的要求是语义表达能力强，同时简单、清晰、易于理解。E-R 模型是最著名的概念模型。

  2. E-R 模型的三大基本概念
    （1）实体（Entity）：客观存在并可相互区别的事物，可以是具体对象，也可以是抽象概念。
    （2）属性（Attribute）：实体具有的某一特征，用来刻画实体。属性有“型”和“值”之分，属性名是型，具体内容是值。
    （3）联系（Relationship）：现实世界中事物内部以及事物之间的联系，在信息世界中抽象为实体内部的联系和实体之间的联系。

  3. 联系的基本类型
    （1）一对一联系（1:1）：实体集 A 中一个实体至多对应实体集 B 中一个实体，反之亦然。例子是“班级与班长”，一个班级只有一个正班长，一个班长只在一个班中任职。
    （2）一对多联系（1:n）：实体集 A 中一个实体对应实体集 B 中的多个实体，反过来一个 B 中实体至多对应一个 A 中实体。例子是“班级与学生”，一个班级中有若干学生，一个学生只在一个班级中学习。
    （3）多对多联系（m:n）：实体集 A 中一个实体对应实体集 B 中多个实体，反之亦然。例子是“课程与学生”，一门课程有若干学生选修，一个学生也可选修多门课程。

  4. 多元联系
    两个以上实体集之间也可以存在联系，称为多元联系。PDF 以“供应商—零件—工程”为例，说明三者之间存在 m:n:p 的联系，表达的是“某个供应商供应某种零件给某个工程”。

  5. 三元联系与二元联系的区别
    这是本章非常关键的细节。PDF 明确指出，三个实体集两两之间的多对多联系，只能表示“一个工程需要哪些零件”“这些零件可以由哪些供应商供应”，却不能表示“一个工程所用的零件具体由哪个供应商供应”以及“一个供应商具体供应哪种零件给哪个工程”。因此，三元联系不能简单拆成三个二元联系，否则会丢失语义。

  6. 同一实体集内部的联系
    PDF 还强调，联系不只存在于不同实体集之间，同一实体集内部也可以有联系。典型例子是职工实体集内部的“领导与被领导”关系：某一职工可以领导若干职工，而一个职工仅被另一个职工直接领导，这是同一实体型内部的一对多联系。PDF 也提到，同一实体集内部还可能存在一对一联系和多对多联系。

  7. E-R 图的表示方法
    E-R 图有三个基本成分：实体、属性和联系。
    （1）实体用矩形表示，矩形框内写实体名。
    （2）属性用椭圆表示，并用无向边与对应实体连接。
    （3）联系用菱形表示，菱形框内写联系名，再用连线把关联实体连接起来，并在连线旁标明联系类型 1:1、1:n 或 m:n。

  8. 联系的属性
    联系本身也可以有属性。PDF 的“选课”例子中，成绩是联系“选课”的属性，而不是学生实体或课程实体的属性，因为成绩描述的是“学生选修某门课程”这个联系。

  9. 弱实体
    弱实体是一类特殊实体，它的存在依赖于其他实体而存在。与弱实体相对应，所依赖的实体称为强实体。弱实体在 E-R 模型中用双框矩形表示，与菱形联系间用双线连接，以表示全部参与。PDF 举例说，在学生管理信息中，家长实体依赖学生实体存在，因此家长可视为弱实体。

  10. 子类实体
    扩展 E-R 模型中增加了子类和超类概念，使模型更有语义表达能力。一个实体集中的个体可以根据不同特性划分为多个子集。PDF 的例子是学校一个系的职工可分为教师、实验人员和机关工作人员，它们共享姓名、年龄、性别等共同属性，同时又有各自的特殊属性。

  11. E-R 模型的用途与特点
    E-R 模型广泛用于数据库概念模型设计。它只表示现实世界中的信息结构及信息之间的关系，不涉及信息在计算机中的表示；只要用户需求不变，E-R 模型是稳定的，并且可以方便地转换成具体 DBMS 支持的数据模型。

  12. PDF 中的综合建模例子
    工厂物资管理模型是本章最完整的例子之一。它涉及五类实体：仓库、零件、供应商、项目、职工。
    （1）仓库：仓库号、面积、电话号码。
    （2）零件：零件号、名称、规格、单价、描述。
    （3）供应商：供应商号、姓名、地址、电话号码、账号。
    （4）项目：项目号、预算、开工日期。
    （5）职工：职工号、姓名、年龄、职称。
    这些实体之间的联系包括：仓库和零件是 m:n 联系，联系属性为库存量；仓库和职工是 1:n 联系；职工内部存在领导与被领导的一对多联系；供应商、项目和零件三者之间存在多对多的三元联系。这个例子综合体现了本章几乎所有 E-R 概念。

三、层次数据模型

  1. 层次模型的定义
    层次模型是数据库系统中最早出现的数据模型，典型代表是 IBM 的 IMS。它用树型结构表示各类实体及实体间联系。现实世界中许多关系具有天然层次性，例如家族关系和行政机构。

  2. 层次模型的结构条件
    满足下面两个条件的基本层次联系集合构成层次模型：
    （1）有且只有一个结点没有双亲结点，该结点称为根结点。
    （2）根以外的其他结点有且只有一个双亲结点。

  3. 层次结构中的术语
    根结点位于最上层；其他结点的上一级结点称为双亲结点；同一双亲结点的子女结点称为兄弟结点；没有子女的结点称为叶结点。双亲结点到子女结点之间表示记录间的一对多联系。

  4. 层次模型的优点
    结构简单清晰；查询效率高；提供较好的数据完整性支持。

  5. 层次模型的缺点
    不能直接表示两个以上实体型间的复杂联系和实体型间的多对多联系，通常要通过引入冗余数据或虚拟结点来解决，容易产生不一致性；插入和删除操作限制较多；查询子女结点必须通过双亲结点；由于结构严密，层次命令趋于程序化。

四、网状数据模型

  1. 网状模型的定义
    网状模型用有向图表示实体及实体间的联系，是对层次模型局限性的突破。现实世界中的许多事物之间是非层次关系，因此网状模型比层次模型更接近实际。

  2. 网状模型的结构条件
    基本网状模型满足两个条件：
    （1）允许一个以上的结点没有双亲。
    （2）一个结点可以有多于一个的双亲。

  3. 网状模型与层次模型的关系
    PDF 明确指出，层次模型实际上是网状模型的特例。两者从结构上看，层次模型是树，网状模型是图；当多个结点都可以有多个双亲时，有向树就变成了有向图。

  4. 网状模型的优点
    能更直接地描述现实世界，例如一个结点可以有多个双亲；性能较好，存取效率较高。

  5. 网状模型的缺点
    结构复杂，随着应用环境扩大，数据库结构会越来越复杂，不利于最终用户掌握；DDL、DML 语言复杂，用户不容易使用；访问数据时必须自行选择存取路径，增加程序编写负担。

  6. 网状模型如何表示多对多联系
    PDF 提到，网状模型可以间接表示多对多联系，方法是将多对多联系分解成一对多联系，并用联结记录来处理。

五、关系数据模型

  1. 关系模型的重要地位
    关系模型是最重要的数据模型。E.F. Codd 于 1970 年系统而严格地提出关系数据模型，并随后提出关系代数、关系演算以及关系范式理论，奠定了现代数据库的理论基础，1981 年因此获得图灵奖。

  2. 关系数据库的发展
    PDF 提到，1977 年 IBM 的 System R 开始运行，后来出现了基于 System R 的 SQL/DB。20 世纪 80 年代以来，几乎所有数据库管理系统都支持关系模型，非关系系统也增加了关系接口；当前数据库研究工作也以关系方法为基础，关系数据库成为最广泛应用的数据库系统。

  3. 关系模型的基本结构
    关系模型中，基本数据结构被限制为二维表，一张二维表称为一个关系。一个关系可用于描述一个实体集。

  4. 关系模型中的基本术语
    （1）关系（relation）：二维表，由行和列组成。
    （2）属性（attribute）：关系中的一列。
    （3）域（domain）：某属性的取值集合，即属性的取值范围。
    （4）元组（tuple）：关系中的一行，表示实体集中的一个个体。
    （5）键（key）：一个或多个属性组成，能够唯一标识一个元组。一个关系中可能有多个键，其中选定一个为主键，其余为候选键。

  5. 关系模式
    对关系结构的描述称为关系模式，形式通常写作“关系名(属性名1, 属性名2, …, 属性名n)”。例如学生关系可表示为“学生(学号, 姓名, 出生年月, 性别, 入学年份, 班级)”。关系数据库模式是一组关系模式的集合，而这些关系模式对应的关系集合构成关系数据库。

  6. 关系模型中实体与联系的表示
    关系模型中，基本数据结构是单一的关系，现实世界中的实体以及实体间的联系都用关系表示。E-R 模型中的联系在关系模式中也可以用表表示，例如“选课”联系可用“选课(学号, 课程号, 成绩)”表示，其中成绩是联系自身的描述属性。

  7. 关系模型的规范化要求
    关系必须规范化，最基本的规范条件是：关系的每一个分量必须是一个不可分的数据项。PDF 用“职工工资”表说明，如果一个属性中又包含“基本工资、工龄、职务、房租、水电”等嵌套成分，就不符合关系模型要求。

  8. 关系模型的数据完整性约束
    为维护数据库与现实世界的一致性，需要对数据施加约束条件。关系模型中主要有三类完整性约束：实体完整性、参照完整性、用户自定义完整性。

  9. 关系模型的数据操纵
    关系模型中的数据操作包括查询、插入、删除和修改。关系数据库系统中对数据的全部操作都可以归结为关系运算；关系运算结果形成一个新关系；关系运算分为关系代数和关系演算。

  10. 关系模型的优点
    PDF 归纳的关系模型优点包括：数据结构简单；一体化的数据子语言；数据独立性高；面向集合的存取方式；理论基础坚实；有利于开展其他应用。

  11. 概念模型与关系数据模型的对应
    PDF 给出了一组非常重要的对应关系：
    （1）E-R 模型中的实体集对应关系表。
    （2）实体集属性对应表的列。
    （3）联系集及其属性也可对应表和列。
    （4）实体的实例对应表中的各行。
    （5）主键或候选键对应关系表中的主键或候选键。
    （6）数据操作在实现层面对应 SQL 语句，在理论层面对应关系代数和关系演算。
    （7）联系类型约束、键约束、完全参与约束在关系模型中分别对应实体完整性、参照完整性和用户自定义完整性。

六、面向对象数据模型

  1. 面向对象数据库系统的两条路线
    PDF 指出，对象关系数据库系统 ORDBS 是面向对象数据模型和关系数据模型结合的产物。研究路线有两条：一是建立新的面向对象数据库系统 OODB，直接支持 OO 数据模型；二是以关系数据库和 SQL 为基础，把面向对象技术融入数据库系统，形成 ORDBS。

  2. 对象的定义
    对象是由一组数据结构和在这组数据结构上的操作程序代码封装起来的基本单位。对象由属性集合和方法集合构成：属性描述状态、组成和特性，方法描述行为特性。

  3. OID
    OID 是对象标识符，即每个对象都有一个唯一且不变的标识。它具有永久持久性、独立于值、系统全局唯一等特点。

  4. 封装
    封装是对象的外部界面与内部实现之间实行清晰隔离的一种抽象，外部与对象的通信只能通过消息。对象封装后，查询属性值必须通过调用方法。

  5. 类
    类是共享同样属性和方法集的所有对象构成的集合。对象是某一类的实例，在 OODB 中，类是“型”，对象是某一类的“值”。

  6. 类层次结构
    PDF 以“教员、行政人员、工人继承教职员工类和人的属性与方法”为例，说明面向对象模型中存在类层次结构；子类在逻辑上继承父类的所有属性和方法，同时还拥有自身特有的属性和方法。

  7. 关系模型与 OO 模型的比较
    PDF 从多个角度对比两者：关系模型的基本数据结构是二维表，OO 模型是类；关系模型使用码作为标识，OO 模型使用 OID；关系模型的动态行为用关系操作描述，OO 模型用方法描述；OO 模型支持抽象数据类型和封装，而关系模型没有；关系模型主要依赖主外码联系和数据依赖，OO 模型则强调继承和组合；OO 模型的模式演化能力较强。

  8. 面向对象数据库研究中的问题
    PDF 指出，OO 数据库研究中存在缺乏通用数据模型、缺乏理论基础、缺乏友好的用户界面与工具环境、缺乏有力的查询优化、商业上没有建立坚实基础等问题。

七、概念模型与数据库系统支持的数据模型的关系

  1. 两类数据模型
    一类是概念模型，用于表示信息结构，不涉及信息在计算机中的表示，典型代表是 E-R 模型；另一类是数据库系统支持的数据模型，包括层次数据模型、网状数据模型、关系数据模型、面向对象数据模型等。

  2. 从概念到实现的路径
    数据库设计通常先把现实世界抽象为概念模型，再把概念模型转换为某种具体的数据模型。这说明概念模型是设计起点，而关系模型、层次模型、网状模型等是实现层面的表达方式。

  3. 本章的核心逻辑
    本章实际上是在讲三件事：
    （1）怎样用 E-R 模型描述现实世界；
    （2）怎样理解不同逻辑数据模型的结构差异；
    （3）怎样把概念模型转换成关系模型并用约束保证正确性。

八、小结

  1. 本章最重要的结论
    数据模型分为概念模型和数据库系统支持的数据模型；概念模型中最重要的是 E-R 模型；数据库系统支持的数据模型中，层次模型、网状模型、关系模型、面向对象模型各有特点，但目前应用最广泛的是关系模型。

  2. E-R 模型的核心
    关键不是只会画图，而是要能准确识别实体、属性、联系，区分 1:1、1:n、m:n，理解实体内部联系、三元联系、弱实体、子类实体，并能将联系属性正确放到联系上。

  3. 关系模型的核心
    关系模型把现实世界统一映射为二维表，强调原子性、完整性约束和关系运算，是当前数据库系统的主流基础。

  4. 层次模型、网状模型、关系模型的关系
    层次模型是树，网状模型是图，关系模型是表；层次模型结构最简单但表达能力弱，网状模型表达能力更强但复杂，关系模型在表达能力、理论基础和使用便利性之间取得了最好平衡。

一、数据模型总论（+ 易错点）

核心结构回顾

  1. 数据模型 = 对现实世界数据特征的抽象

  2. 分类：

    • 概念模型（E-R）

    • 逻辑模型（层次 / 网状 / 关系 / OO）

    • 物理模型

  3. 三要素：

    • 数据结构（静态）

    • 数据操作（动态）

    • 完整性约束（规则）

易错点与分析

易错点1：混淆“概念模型”和“数据模型”

  • 错误理解：E-R模型也是DBMS直接使用的模型

  • 本质原因：没有区分“设计阶段”和“实现阶段”

✔ 正确理解：

  • E-R模型 → 用来“画世界”（设计）

  • 关系模型 → 用来“落地”（实现）

易错点2：三要素记不清 / 混淆

  • 常见错误：

    • 把“完整性约束”当成数据操作

    • 忘记“数据结构是核心”

✔ 正确记忆：

  • 静态：数据结构

  • 动态：数据操作

  • 规则：完整性约束

二、E-R 概念模型（+ 易错点重点）

核心结构回顾

  1. 基本概念：

    • 实体

    • 属性（型 + 值）

    • 联系（实体间 / 实体内部）

  2. 联系分类：

    • 按数量：1:1 / 1:n / m:n

    • 按实体数：二元 / 多元

    • 按范围：实体间 / 实体内部

  3. 扩展：

    • 弱实体

    • 子类实体

易错点与分析（这一章最重要部分）

易错点1：把“联系属性”放到实体里

例子：成绩

❌ 错误：

  • 学生表加“成绩”

  • 课程表加“成绩”

✔ 正确：

  • 成绩属于“选课联系”

👉 原因分析：
成绩依赖两个实体（学生+课程），不是单个实体属性

👉 判断口诀：
“属性是否依赖多个实体？” → 是 → 放联系

易错点2：m:n 不建表

❌ 错误：

  • 直接用外键表示多对多

✔ 正确：

  • 必须建中间表（联系表）

👉 原因：
关系模型无法直接表达 m:n

易错点3：三元联系拆错（高频考点）

❌ 错误：
把“供应商-零件-工程”拆成三个两两关系

✔ 正确：
必须保留三元联系

👉 本质原因：
两两关系只能表达：

  • 谁和谁有关

但表达不了：

  • 谁 给 谁 提供 什么

👉 关键结论：
三元联系 = 信息更完整

易错点4：不会识别“实体内联系”

❌ 常见忽略：
只会画不同实体之间关系

✔ 正确：
同一实体内部也有联系

例：

  • 职工 → 领导关系（1:n）

易错点5：弱实体判断错误

❌ 错误理解：
“有外键就是弱实体”

✔ 正确判断：
弱实体必须满足：

  1. 不能独立存在

  2. 依赖强实体标识

例：

  • 家长依赖学生 ✔

  • 订单依赖用户 ✔（典型）

易错点6：子类实体理解不清

❌ 错误：
把子类当普通实体

✔ 正确：
子类 = 继承结构

👉 特点：

  • 共享父类属性

  • 有自己特有属性

核心回顾

  1. 树结构

  2. 一个根节点

  3. 每个节点只有一个父节点

3. const 与指针（重点）

判定原则

👉 const 修饰“离它最近的对象”

3.1 指向常量的指针（pointer to const）

定义：

  • const int* p
  • int const* p

特点：

  • 可以改指针指向
  • 不能改指针指向的值

示例：

  • p = &x ✔
  • *p = 10 ✘

3.2 常量指针（const pointer）

定义：

  • int* const p

特点：

  • 不能改变指针指向
  • 可以修改值

示例：

  • p = &y ✘
  • *p = 10 ✔

3.3 指向常量的常量指针

定义：

  • const int* const p

特点：

  • 不能改指向
  • 不能改值

总结
在 C/C++ 中，权限本质指的是“是否可以通过某个指针修改数据”。所谓“权限缩小”，就是把原本“可以修改”的对象，通过 const 限制为“不可修改”，这种行为是安全的，因此允许，例如 const int *p 指向变量，本质是“我选择不通过 p 修改它”；
因此指向常量的指针以及指向常量的常量型指针可以指向变量

而“权限放大”则是试图通过指针获得本不具备的修改能力（如用 int * 指向 const int），这会破坏数据的只读性，因此被禁止。

所有指针与常量的规则，本质都遵循一句话：👉 只能减少修改权限，不能增加修改权限；同时 const 只限制“指针的使用方式”，不会改变变量本身的属性，因此“指向常量的指针”“常量指针”“双 const 指针”本质都是在约束“能不能改值”和“能不能改指向”，而是否允许绑定某个对象，取决于是否违反了“不能放大权限”的原则。

  • 能改”的指针 ❌ 不能指向 const
  • “不改”的指针 ✅ 可以指向任何

2.1.5. 节省内存

运行一些操作可能会导致为新结果分配内存。 例如，如果我们用Y = X + Y，我们将取消引用Y指向的张量，而是指向新分配的内存处的张量。
在下面的例子中，我们用Python的id()函数演示了这一点， 它给我们提供了内存中引用对象的确切地址。 运行Y = Y + X后，我们会发现id(Y)指向另一个位置。 这是因为Python首先计算Y + X，为结果分配新的内存，然后使Y指向内存中的这个新位置。
before = id(Y)
Y = Y + X
id(Y) == before
False
错误原因是因为其实内存有变
这可能是不可取的，原因有两个：

  1. 首先，我们不想总是不必要地分配内存。在机器学习中，我们可能有数百兆的参数，并且在一秒内多次更新所有参数。通常情况下，我们希望原地执行这些更新；

  2. 如果我们不原地更新，其他引用仍然会指向旧的内存位置，这样我们的某些代码可能会无意中引用旧的参数。

幸运的是，执行原地操作非常简单。 我们可以使用切片表示法将操作的结果分配给先前分配的数组，例如Y[:] = <expression>。 为了说明这一点，我们首先创建一个新的矩阵Z，其形状与另一个Y相同， 使用zeros_like来分配一个全的块。
Z = torch.zeros_like(Y)
print('id(Z):', id(Z))
Z[:] = X + Y
print('id(Z):', id(Z))
id(Z): 140327634811696
id(Z): 140327634811696
如果在后续计算中没有重复使用X， 我们也可以使用X[:] = X + Y或X += Y来减少操作的内存开销。
before = id(X)
X += Y
id(X) == before
True

深度学习笔记（一）：走进机器学习

1. 机器学习中的关键组件

首先介绍一些核心组件。无论什么类型的机器学习问题，都会遇到这些组件：

  1. 可以用来学习的_数据_（data）；

  2. 如何转换数据的_模型_（model）；

  3. 一个_目标函数_（objective function），用来量化模型的有效性；

    • 定义模型的优劣程度且可优化的度量，这被称之为目标函数， 我们通常定义一个目标函数，并希望优化它到最低点。 因为越低越好，所以这些函数有时被称为损失函数（loss function，或cost function）。也可取反。
    • 当任务在试图预测数值时，最常见的损失函数是平方误差（squared error），即预测值与实际值之差的平方。 当试图解决分类问题时，最常见的目标函数是最小化错误率，即预测与实际情况不符的样本比例。 有些目标函数（如平方误差）很容易被优化，有些目标（如错误率）由于不可微性或其他复杂性难以直接优化。 在这些情况下，通常会优化替代目标。
    • 通常，损失函数是根据模型参数定义的，并取决于数据集。 在一个数据集上，我们可以通过最小化总损失来学习模型参数的最佳值。
    • 该数据集由一些为训练而收集的样本组成，称为_训练数据集_（training dataset，或称为_训练集_（training set））。 然而，在训练数据上表现良好的模型，并不一定在“新数据集”上有同样的性能，这里的“新数据集”通常称为_测试数据集_（test dataset，或称为_测试集_（test set））。
    • 综上所述，可用数据集通常可以分成两部分：训练数据集用于拟合模型参数，测试数据集用于评估拟合的模型。 然后我们观察模型在这两部分数据集的性能。 “一个模型在训练数据集上的性能”可以被想象成“一个学生在模拟考试中的分数”。 这个分数用来为一些真正的期末考试做参考，即使成绩令人鼓舞，也不能保证期末考试成功。 换言之，测试性能可能会显著偏离训练性能。 当一个模型在训练集上表现良好，但不能推广到测试集时，这个模型被称为过拟合（overfitting）的。 就像在现实生活中，尽管模拟考试考得很好，真正的考试不一定百发百中。

  4. 调整模型参数以优化目标函数的算法（algorithm）。
    大多流行的优化算法通常基于一种基本方法–梯度下降（gradient descent）。 简而言之，在每个步骤中，梯度下降法都会检查每个参数，看看如果仅对该参数进行少量变动，训练集损失会朝哪个方向移动。 然后，它在可以减少损失的方向上优化参数。

2.常见机器学习种类

1. 监督学习

何为监督学习

监督学习（supervised learning）擅长在“给定输入特征”的情况下预测标签。 每个“特征-标签”对都称为一个样本。 有时，即使标签是未知的，样本也可以指代输入特征。 我们的目标是生成一个模型，能够将任何输入特征映射到标签（即预测）。
举一个具体的例子： 假设我们需要预测患者的心脏病是否会发作，那么观察结果“心脏病发作”或“心脏病没有发作”将是样本的标签。 输入特征可能是生命体征，如心率、舒张压和收缩压等。
监督学习之所以能发挥作用，是因为在训练参数时，我们为模型提供了一个数据集，其中每个样本都有真实的标签。 用概率论术语来说，我们希望预测“估计给定输入特征的标签”的条件概率。 虽然监督学习只是几大类机器学习问题之一，但是在工业中，大部分机器学习的成功应用都使用了监督学习。 这是因为在一定程度上，许多重要的任务可以清晰地描述为，在给定一组特定的可用数据的情况下，估计未知事物的概率。比如：

  • 根据计算机断层扫描（Computed Tomography，CT）肿瘤图像，预测是否为癌症；
  • 给出一个英语句子，预测正确的法语翻译；
  • 根据本月的财务报告数据，预测下个月股票的价格；
    监督学习的学习过程一般可以分为三大步骤：
  1. 从已知大量数据样本中随机选取一个子集，为每个样本获取真实标签。有时，这些样本已有标签（例如，患者是否在下一年内康复？）；有时，这些样本可能需要被人工标记（例如，图像分类）。这些输入和相应的标签一起构成了训练数据集；
  2. 选择有监督的学习算法，它将训练数据集作为输入，并输出一个“已完成学习的模型”；
  3. 将之前没有见过的样本特征放到这个“已完成学习的模型”中，使用模型的输出作为相应标签的预测。

    即使使用简单的描述给定输入特征的预测标签，监督学习也可以采取多种形式的模型，并且需要大量不同的建模决策，这取决于输入和输出的类型、大小和数量。 例如，我们使用不同的模型来处理“任意长度的序列”或“固定长度的序列”。

小类 输出标签 y是什么 示例 本质任务

回归（Regression） 连续数值 房价预测 预测一个数值

  • 人们宁愿错误地分入一个相关的类别，也不愿错误地分入一个遥远的类别，这通常被称为_层次分类_

2.无监督学习

  • 聚类（clustering）问题：没有标签的情况下，我们是否能给数据分类呢？
    • 比如，给定一组照片，我们能把它们分成风景照片、狗、婴儿、猫和山峰的照片吗？同样，给定一组用户的网页浏览记录，我们能否将具有相似行为的用户聚类呢？
  • 主成分分析（principal component analysis）问题：我们能否找到少量的参数来准确地捕捉数据的线性相关属性？
    • 比如，一个球的运动轨迹可以用球的速度、直径和质量来描述。再比如，裁缝们已经开发出了一小部分参数，这些参数相当准确地描述了人体的形状，以适应衣服的需要。另一个例子：在欧几里得空间中是否存在一种（任意结构的）对象的表示，使其符号属性能够很好地匹配?这可以用来描述实体及其关系，例如“罗马”  “意大利”  “法国”  “巴黎”。
  • 因果关系（causality）和概率图模型（probabilistic graphical models）问题：我们能否描述观察到的许多数据的根本原因？
    • 例如，如果我们有关于房价、污染、犯罪、地理位置、教育和工资的人口统计数据，我们能否简单地根据经验数据发现它们之间的关系？
  • 生成对抗性网络（generative adversarial networks）：为我们提供一种合成数据的方法，甚至像图像和音频这样复杂的非结构化数据。潜在的统计机制是检查真实和虚假数据是否相同的测试，它是无监督学习的另一个重要而令人兴奋的领域。
  • 训练和测试数据不同时，就是分布偏移（distribution shift）的问题
  • 先获取大量数据，然后启动模型，不再与环境交互。 这里所有学习都是在算法与环境断开后进行的，被称为_离线学习_（offline learning）

3.强化学习

何为强化学习

强化学习问题中，智能体（agent）在一系列的时间步骤上与环境交互。 在每个特定时间点，智能体从环境接收一些观察（observation），并且必须选择一个动作（action），然后通过某种机制（有时称为执行器）将其传输回环境，最后智能体从环境中获得奖励（reward）。
可以将任何监督学习问题转化为强化学习问题。 假设我们有一个分类问题，可以创建一个强化学习智能体，每个分类对应一个“动作”。 然后，我们可以创建一个环境，该环境给予智能体的奖励。 这个奖励与原始监督学习问题的损失函数是一致的。

强化学习细分

当环境可被完全观察到时，强化学习问题被称为_马尔可夫决策过程_（markov decision process）。
当状态不依赖于之前的操作时，我们称该问题为_上下文赌博机_（contextual bandit problem）。
当没有状态，只有一组最初未知回报的可用动作时，这个问题就是经典的_多臂赌博机_（multi-armed bandit problem）。
