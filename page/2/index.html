一、CDN 与分布式缓存 背景

1. 实际业务场景问题

为什么需要 CDN 和分布式缓存？

  • 同样视频网站，不同地区加载速度不一样
  • 同一个视频网站，热门视频和普通视频加载速度不一样

2. CDN 核心概念

CDN：内容分发网络
核心思路：
把网站视频、图片等静态热点资源，提前部署到全国 / 全球各地边缘缓存服务器。
用户访问时就近获取资源，不用跨上万公里传输，大幅降低时延。

类比：京东物流多级仓库

  • 下级前置仓 → 本地优先发货

  • 下级无货 → 向上级仓库查找

    CDN 缓存服务器也是多层级架构：下级缓存没有，再向上级节点请求。

3. 分布式缓存 产生原因

单台服务器存不下全网海量资源，必须用多台机器集群做分布式缓存。

核心难题（考试必问）：

给定一个文件 / URL，如何快速确定它缓存在哪一台机器？
不能遍历所有机器逐个查找，效率太低。

二、基础方案：普通哈希分片

1. 实现步骤

  1. 选哈希函数（如 MD5），对文件 / URL 计算哈希值
  2. 机器编号：0,1,2,…,n−1
  3. 映射规则：
    机器编号=h(x)modn
    示例：
    输入 URL → MD5 算出 32 位 16 进制哈希值 → 对机器数 n 取余 → 分到对应机器。
    MD5 本质是：一个复杂数学函数
    输入：字符串
    输出：128位二进制数
    为了方便显示写成：32位16进制，
    优点：均匀分担存储任务

2. 优点

哈希映射均匀，文件能相对均衡分散在各台机器。

3. 致命缺陷（核心考点）

当机器数量动态变化（扩容 / 缩容）：

原来机器数 n1​，后来变成 n2​
h(x)modn1不等于h(x)modn2​
几乎所有文件的映射位置都会改变，需要大规模迁移数据，开销极大、服务不稳定。

三、一致性哈希 核心原理

1. 解决目标

解决机器增减时全量迁移的问题，做到：
机器新增 / 下线，只迁移极少部分文件。
解决思路：为每⼀台机器也计算⼀个哈希值

2. 哈希环构造

  1. 把哈希值域 0∼232−1 首尾相连，形成环形哈希空间
  2. 机器也做哈希：对每台机器 IP / 域名计算哈希，映射到哈希环固定位置
  3. 文件映射规则
    对文件计算哈希值，落在环上某位置；
    从该位置顺时针往下，找到第一台遇到的机器，文件就存在这台机器上。

3. 核心优势

  1. 机器增减，只影响相邻一小段环区间，只需迁移少量数据
  2. 天然保证数据在集群中分布均匀
  3. 当机器数⽬从n-1增加到n时，平均需要移动的⽂件数是总⽂件数的1/n

四、关键数学推导：机器新增时文件迁移比例

1. 结论

机器从 n−1 台增加到 n 台时：

期望迁移文件比例 = n1​

2. 完整推导步骤

  1. 把哈希环归一化为区间 [0,1) 圆周
  2. 利用圆周对称性，把新增机器固定放在位置 0
  3. 设迁移文件比例为随机变量 X
  4. 事件 X>t：迁移区间长度大于 t，说明 (−t,0) 弧内没有旧机器
    P(X>t)=(1−t)n−1
  5. 累积分布函数
    FX​(t)=P(X≤t)=1−(1−t)n−1
  6. 概率密度函数（求导）
    fX​(t)=(n−1)(1−t)n−2
  7. 用尾积分求期望
    E[X]=∫01​P(X>t)dt=∫01​(1−t)n−1dt
    令 u=1−t：
    E[X]=∫01​un−1du=n1​

3.简单证明

一致性哈希中，机器随机均匀分布在哈希环上。
当机器数从n−1增加到n时：
新增机器仅会接管其顺时针前驱机器的一部分区间。
由于哈希均匀性，新增后每台机器平均负责1/n的哈希空间。
因此新增机器平均需要接管1/n的数据。
故平均迁移文件比例为：1/n

五、一致性哈希 概率渐近分析

性质一：一致性哈希中，机器随机均匀分布在单位圆上。平均区间长度为 1/n，但由于随机波动，会存在较大的空隙。概率分析表明，以高概率，最大空隙长度不会超过O(log⁡n/n)
因此任何机器负责的数据比例都不会过大，从而保证了一致性哈希具有较好的负载均衡性。
性质二：以较⼤的概率，⾄少⼀个机器在“圆圈”上占据的区间⽐例⼩于1/n

七、一致性哈希 负载均衡优化

1. 原生一致性哈希缺点

虽然概率均匀，但实际会出现：

  • 哈希偏斜：部分机器负载远高于平均
  • 负载方差大

2. 优化方案：虚拟节点

利用多个不同的哈希函数，给一台物理机器生成多个不同哈希值，映射到哈希环多个位置。
作用：

  1. 进一步抹平负载差异
  2. 减少哈希偏斜，工程上 Redis、Kafka 全部采用虚拟节点版一致性哈希。

八、一致性哈希 发展历史与工程落地

  1. 1997 年：MIT 学者在STOC（计算机理论顶会）发表一致性哈希论文
  2. 1998 年：基于该技术创办 Akamai（全球顶级 CDN 服务商）
  3. 1999 年：星球大战预告片上线，海量流量冲击下，只有 Akamai 服务器稳定承载，一战成名
  4. 1999 年 4 月：乔布斯曾致电 Akamai，因愚人节被总裁误以为玩笑
  5. 2001 年：Akamai 创始人 Danny Lewin 在 911 事件中遇难
  6. 2001 年后：一致性哈希广泛用于 P2P 网络、Chord 协议、BitTorrent 等分布式系统

九、进阶：带负载边界的一致性哈希

1. 传统一致性哈希两大短板

  1. 哈希偏斜：随机分配导致部分机器负载过高
  2. 热点数据：爆款 Key 访问量极大，映射单节点容易过载

2. 容量配额设计

设定每台机器负载上限：

Cj​=(1+ϵ)⋅NM​

  • M：总请求 / 文件数
  • N：机器数
  • ϵ：负载冗余系数（如 0.1 允许超 10%）

3. 写入分配逻辑

  1. 先计算 Key 最理想节点 h(x)
  2. 若该节点负载 < 上限：直接存入
  3. 若已满：沿哈希环顺时针依次找下一个节点，找到未满为止

4. 读取定位逻辑

严格和写入同一条探测路径：

先查理想节点，满载则顺次往后找，一定能定位到数据。

5. 核心性质：向回迁移

新增机器后，之前因节点满载被 “挤到远处” 的数据，

会自动向更近的新空闲节点回迁。

既保留一致性哈希少迁移优点，又限制单节点负载上限，解决偏斜和热点问题。

二、本章核心规则

  • SQL 是关系数据库的标准语言，介于关系代数与关系演算之间，集查询、操纵、定义和控制于一体。
  • SQL 的特点是：综合统一、高度非过程化、面向集合、语法统一且简洁易学。
  • SQL 支持三级模式结构：基本表对应模式，视图对应外模式，存储文件对应内模式。
  • 基本表是独立存在的真实表；视图是从一个或多个基本表导出的虚表，不实际存储数据。
  • DDL 包括 CREATE / DROP / ALTER；DML 包括 SELECT / INSERT / UPDATE / DELETE；DCL 包括 GRANT / REVOKE。
  • 定义表时，主键、外键、唯一性、非空和检查约束是高频考点。
  • 索引能加快查询，但会占空间、增加维护成本；PRIMARY KEY 和 UNIQUE 常会自动建索引。
  • SELECT 的核心顺序是：FROM 确定对象，WHERE 选行，GROUP BY 分组，HAVING 过滤组，ORDER BY 排序。
  • WHERE 负责行筛选，HAVING 负责组筛选；WHERE 不能直接用聚集函数。
  • 视图的更新很复杂，有些视图可更新，有些不可更新；WITH CHECK OPTION 用来限制通过视图修改时不能破坏视图条件。
  • 嵌入式 SQL 需要预编译、主变量、SQLCA 和游标来协调“集合操作”和“过程式处理”的差异。
    经验句：

二、本章核心规则

  • 继承和组合复用的是对象代码，模板复用的是源代码。

  • 模板提供的是一种把“类型”当成参数来用的泛型编程方式。

  • 模板分为两类：函数模板 和 类模板。

  • 模板被具体类型替换、生成可用函数/类的过程叫 template instantiation。

  • 函数模板的类型参数通常写成 typename T 或 class T。

  • 类模板的成员函数如果放到类外定义，必须写成模板函数形式。

  • 模板不是“自动万能”，它仍然依赖具体类型能满足模板里使用的操作，比如 >、拷贝、赋值等。这个点从 getmax 和 StackTemplate 例子里都能看出来。

经验句：
模板的本质是：先写一份通用代码，再让具体类型来“套模板”。

二、本章核心规则

  • 面向对象的基本特征包括：封装、继承、多态；动态多态主要靠 virtual functions 实现。

  • 派生类对象可以通过指针或引用当成基类对象来处理，这叫 upcasting。

  • 如果基类函数声明为 virtual，那么它在所有派生类中都保持虚函数属性。

  • 继承中对虚函数的重新定义叫 overriding。

  • 同名不同参的同一类函数是 overloading；普通成员函数在继承里被重新定义，常叫 redefining。

  • 使用虚函数实现多态时，必须通过基类指针或引用调用；直接拿对象本身调用时，编译器知道精确类型，通常是早绑定。

  • 作用域解析运算符 :: 会绕过虚函数机制。

  • 虚函数必须是非静态成员函数。

  • 构造函数不能是 virtual。

  • 析构函数通常应该是 virtual；如果基类析构函数是 virtual，派生类析构函数会自动成为 virtual。

  • 抽象类至少含有一个纯虚函数；纯虚函数写成 = 0。

  • 发生对象按值传递时，可能出现 object slicing（对象切片）。

  • 除了赋值运算符，一般运算符也可以像普通成员函数一样做虚函数。

经验句：
这章就背四个词：upcasting、virtual、override、slicing。

二、本章核心规则

  • C++ 的一个重要特性是代码复用，类之间的关系通常通过 composition 和 inheritance 来表达。composition 是 has-a，inheritance 是 is-a。
  • 组合和继承都会让新类里包含子对象，只是来源不同：组合是把成员对象放进去，继承是把基类子对象放进去。
  • 派生类对象创建时，先构造基类子对象，再构造成员子对象，最后构造派生类自己。析构顺序相反。
  • 构造函数初始化列表可以显式调用成员对象或基类构造函数。
  • 如果派生类里重新定义了某个函数名，基类里同名的其他重载版本会被自动隐藏。
  • 构造函数、析构函数、赋值运算符不会自动继承。
  • 继承中的 static 成员函数会被继承，但它们没有 this，只能访问 static 成员，也不能是 virtual。
  • public / protected / private 继承会改变基类成员在派生类中的可见性；派生类成员函数仍可访问基类的 public 和 protected 成员，但对象能不能访问，要看继承方式。
  • 除赋值运算符外，运算符通常会自动继承到派生类。
  • 多重继承可能带来同名成员函数歧义；虚基类可以解决“基类被继承两次”的问题。
  • 派生类对象可以通过指针或引用被当作基类对象使用，这叫向上转型。
    经验句：
    这章就记四件事：谁包含谁、谁先构造、谁会隐藏、谁会歧义。

一、数字系统

  1. 定义
    数字系统是离散信息处理系统，以一组离散信息为输入，以离散内部信息为系统状态，最终输出离散形式的结果。
  2. 分类
  • 组合逻辑系统：无状态记忆功能，输出值仅由当前输入决定，公式：output = f (input)
  • 时序逻辑系统：具备状态记忆功能，输出值由当前输入 + 系统状态共同决定，公式：output = f (state, input)
    • 同步时序系统：在离散时间点更新状态
    • 异步时序系统：在任意时间点更新状态
  1. 典型系统
    数字计数器、数字计算机、嵌入式系统、手机、相机、汽车电子、GPS、复印机、洗碗机等。

二、信息表示

  1. 核心概念
  • 信息：对物质世界与人类社会现象的表示，可消除不确定性，用信息熵衡量。
  • 信号：信息的物理载体，分为模拟信号（连续物理量）和数字信号（离散物理量）。

  1. 二进制表示

    数字系统广泛采用二进制，用 0 和 1 表示，也可对应真 / 假、高 / 低、开 / 关；可通过电压、磁场方向、电荷量等物理量实现二进制。

三、数制

  1. 基础定义
  • 数制：数的表示规则。
  • 基底 r：数制包含的数字符号个数。
  • 权 r^i：数字符号位置对应的值，数值 = 各位数字值 × 对应权值之和。
  1. 常用数制
  • 二进制（B/2）：0、1
  • 八进制（O/8）：0~7
  • 十进制（D/10）：0~9
  • 十六进制（H/16）：09、AF

  1. 二进制单位

    2^10=1K、2^20=1M、2^30=1G、2^40=1T

  2. 数制运算

    二进制、八进制、十六进制加减乘规则同十进制，按位计算，逢基底 r 进 1。

  3. 数制转换

  • 非十进制→十进制：按权展开求和
  • 十进制→非十进制：整数部分除 r 取余（余数倒序），小数部分乘 r 取整（整数正序）
  • 二 / 八 / 十六互转：1 位八进制 = 3 位二进制，1 位十六进制 = 4 位二进制，以小数点为界分组转换

四、编码

  1. 二进制编码

    n 位二进制编码可表示 2^n 个数据；表达 M 个数据需要⌈log₂(M)⌉位；分数值型（可算术运算）、非数值型（无需算术运算）。

  2. BCD 码

    用 4 位二进制表示 09 的十进制编码，8421 码最常用（加权码，权值 8、4、2、1），10101111 为无效码；进制转换≠编码，如十进制 13，二进制是 1101，BCD 码是 0001 0011。

  3. 格雷码

  • 核心特点：计数时相邻编码仅 1 位不同，位翻转少、功耗低、抗干扰，可避免编码错误。

  1. 字符编码

  • 作用：检测数据传输错误，增加 1 位校验码。
  • 偶校验：编码中 1 的个数为偶数，校验位填 0。
  • 奇校验：编码中 1 的个数为奇数，校验位填 0。

第3章 关系数据库 复习整理

一、本章主线

关系数据库系统是支持关系模型的数据库系统。关系模型以集合论中的“关系”为基础，运用数学方法研究数据库的结构以及对数据的操作。本章围绕数据模型的三要素展开：数据结构、数据操作、完整性约束；并进一步学习关系模型的基本概念、关系代数、元组关系演算和域关系演算。

二、关系模型的基本概念

2.1 域（Domain）

域是一组具有相同数据类型的值的集合。它表示属性的取值范围。比如自然数、整数、{男，女}、{0，1} 都可以看作域；在教师关系中，姓名、性别、年龄也都可以分别对应一个域。

2.2 笛卡尔积（Cartesian Product）

给定若干集合 D1, D2, …, Dn，它们的笛卡尔积是所有分量组合形成的集合：
D1×D2×…×Dn = {(d1,d2,…,dn) | di∈Di}。
它的本质是“所有域的所有值的组合”，并且这些组合不重复。PDF 用“导师—专业—研究生”给出了三域笛卡尔积的完整例子。

2.3 元组（Tuple）与分量（Component）

笛卡尔积中的每一个元素称为一个元组；元组中的每一个值称为一个分量。比如 (张清玫, 计算机专业, 李勇) 是一个三元组，而“张清玫”“计算机专业”“李勇”分别是分量。

2.4 关系（Relation）

关系是笛卡尔积的任意一个子集。n 叫做关系的目或度。关系中的每一行对应一个元组，每一列对应一个属性。严格说，关系数据库中的关系必须是有限集合。

PDF 还特别强调：由于笛卡尔积本身不满足交换律，关系模型通过“属性名”来取消元组的有序性，因此在关系中列的顺序本质上是无关的。

2.5 规范化关系应满足的性质

规范化的关系有几个重要性质：
第一，列是同质的，即同一列的数据来自同一个域；第二，不同的列可以来自同一个域，但必须用不同属性名区分；第三，列的顺序无所谓；第四，元组不能重复；第五，行的顺序无所谓；第六，每个分量必须是原子值，不能再分。
其中“分量必须取原子值”是最基本、最重要的规范条件。PDF 还举了“职工工资”嵌套结构不符合关系模型要求的例子。

2.6 一元关系、二元关系

当 n=1 时称为一元关系；当 n=2 时称为二元关系。这个定义本身是关系理论中的基础概念，后面讲查询语言和运算时都会用到。

三、关系模式与关系数据库

3.1 关系模式（Relation Schema）

关系模式是对关系的描述，通常包括关系名、属性名、属性类型、长度以及属性间固有的数据联系。简记形式通常写作 R(A1, A2, …, An)。例如，图书关系模式可以写成：图书(书号, 书名, 作者, 单价, 出版社)。

3.2 关系的值

关系的值是元组的集合。一个关系模式在某一时刻对应的实际内容，就是该关系的值。PDF 强调，关系是现实世界某一时刻状态的反映，因此关系的值会随时间变化。

3.3 关系数据库与关系数据库模式

关系模式的集合称为关系数据库模式，通常写作 R={R1, R2, …, Rp}。每个关系模式上对应的关系集合，构成完整的关系数据库。

四、键（Key）

为了区分不同元组，需要用一个或多个属性值唯一标识元组，这样的属性或属性组称为关系的键。能够起标识作用而其子集不能起标识作用的键称为候选键；在多个候选键中选定一个作为主键；若键由多个属性组成，则称为联合键；若关系的所有属性都构成键，则称为全键。

这一部分的核心是：键的作用不是“好看”，而是“唯一标识元组”。后面的实体完整性、参照完整性，都建立在键的基础上。

五、完整性约束

关系模型中的完整性规则是对关系的约束条件。为了保证数据库中的数据与现实世界一致，关系数据库的插入、删除和修改操作必须受到约束。关系模型的三类完整性约束是：实体完整性、参照完整性、用户定义完整性。通常前两类由系统自动支持，用户定义完整性则反映具体应用的语义要求。

5.1 实体完整性—主键

实体完整性要求主键的值不能为空或部分为空。换句话说，若属性 A 是基本关系 R 的主属性，则 A 不能取空值。原因是：如果键为空或部分为空，该元组就不可标识，也就不能表示任何实体。

PDF 进一步解释了实体完整性为什么成立：基本表通常对应一个实体集或多对多联系；现实世界中的实体是可区分的，关系模型用主键作为唯一标识，因此主键不能为空，否则就会出现不可区分的实体，这与实体可区分的现实相矛盾。

5.2 参照完整性—外键

关系模型中实体及其联系都用关系表示，因此关系与关系之间自然存在引用。若关系 R1 中的属性 A 引用了关系 R2 的主键，则 R1 中 A 的值要么为空，要么必须等于 R2 中某个元组的主键值。

PDF 的学生—专业例子非常典型：学生关系中的“专业号”必须来自专业关系中真实存在的专业号，不能引用不存在的专业。这个规则就是参照完整性。

5.3 外键（Foreign Key）

若 F 是基本关系 R 的一个或一组属性，但不是 R 的键；并且 F 对应于基本关系 S 的主键 Ks，则称 F 为 R 的外键。R 是参照关系，S 是被参照关系或目标关系。R 和 S 不一定是不同的关系；外键与主键也不一定同名，但必须定义在同一个或一组域上。

PDF 还给出了“学生实体及其内部领导联系”的例子：学生关系中的“班长”属性值，如果非空，则必须是本关系中某个元组的学号值；这说明参照完整性不仅可以发生在不同关系之间，也可以发生在同一关系内部。

5.4 用户定义完整性

用户定义完整性是针对具体数据库的特殊约束，反映某一应用领域的语义要求。PDF 举例：选课关系中成绩不能为负数，或者某些数据输入格式需要满足特定限制。关系模型应提供统一的机制来定义和检验这类约束，而不应完全交给应用程序。

六、关系代数

6.1 关系代数是什么

关系代数是一种抽象查询语言，用对关系的运算来表达查询要求。它的三个要素是：运算对象是关系，运算结果也是关系，运算由一组运算符构成。关系代数是关系数据库系统中实现关系操作的重要基础。

6.2 关系代数的分类

关系代数分为三类：
第一，传统集合运算，包括并、差、交、广义笛卡尔积；
第二，专门的关系运算，包括选择、投影、连接、除法；
第三，扩充的关系运算，包括属性重命名、外连接。

关系操作的特点是“集合操作方式”，即操作对象和结果都是集合，属于“一次一集合”；而非关系数据模型通常是“一次一记录”。这是关系模型与传统记录式数据模型的根本区别之一。

七、传统集合运算

7.1 并（Union）

R∪S 仍为 n 目关系，由属于 R 或属于 S 的元组组成。前提是 R 和 S 具有相同的目数，并且对应属性来自同一个域。

7.2 差（Difference）

R-S 由属于 R 而不属于 S 的元组组成。同样要求两者具有相同目数和相应域匹配。

7.3 交（Intersection）

R∩S 由同时属于 R 和 S 的元组组成，也可表示为 R-(R-S)。

7.4 广义笛卡尔积

若 R 是 n 目关系，S 是 m 目关系，则 R×S 是一个 n+m 目关系，行数等于两者元组数的乘积。其本质是把 R 中每个元组与 S 中每个元组拼接。

八、专门的关系运算

8.1 选择（Selection）

选择是从关系中选择满足条件的元组子集，记作 σF(R)。F 是由逻辑连接词和比较表达式组成的布尔条件。选择从“行”的角度进行运算。

典型例子：
查询信息系学生：σSdept=’IS’(Student)
查询年龄小于 20 的学生：σSage<20(Student)。

8.2 投影（Projection）

投影是从关系中选出若干属性列组成新关系，记作 πA(R)。投影从“列”的角度进行运算，但它不仅会删除某些列，也可能删除重复元组。

例子：查询学生姓名和所在系，即 πSname,Sdept(Student)。

8.3 连接（Join）

连接是按条件把两个关系中的元组拼接起来形成新关系。最常见的是条件连接和自然连接。条件连接可写成 R ⋈AθB S，其中 A 和 B 为同域属性。等值连接是 θ 为“=”的情况。

自然连接是一种特殊的等值连接，要求被比较的分量是相同的属性组，并且结果中去掉重复属性列。PDF 强调，自然连接既涉及行，也涉及列。

8.4 除（Division）

除运算是一个二元运算，用符号 ÷ 表示。若 R(X,Y) 与 S(Y) 相关，则 R÷S 产生一个新关系 R’(X)，其含义是：找出那些在 X 上取值 x，使得 x 对应的“象集”包含了 S 在 Y 上的投影。直观上可以理解为“满足所有条件的那些对象”。

PDF 给了两个很经典的例子：

  1. 同时选修了 C2 和 C3 的所有学生；

  2. 选修了全部课程的学生号码和姓名。
    这类题几乎都是除法运算的标准应用场景。

8.5 属性重命名

属性重命名用来改变属性名，但不改变数据本身。它不仅可以对单个属性重命名，也可以对一组属性同时操作。其作用之一是便于同一关系做自然连接或笛卡尔积，也能把等值连接方便地表示为自然连接。

8.6 外连接

外连接是对自然连接的扩展，结果中除了满足连接条件的元组外，还包含没有被连接上的元组。左外连接保留左侧关系中未匹配的元组，右外连接保留右侧关系中未匹配的元组，完全外连接则是左右外连接的并。未匹配处通常用 NULL 填充。

九、关系代数中的典型例子

9.1 查询计算机系学生的学号和姓名

先选出计算机系学生，再投影学号和姓名：
πSno,Sname(σSdept=’计算机’(Student))。

9.2 查询选修了 2 号课程的学生学号

先在选课关系中选择 Cno=’2’，再投影 Sno：
πSno(σCno=’2’(SC))。

9.3 查询选修了 1 号课程的学生姓名

思路是：先连接 Student 和 SC，再筛选 Cno=’1’，最后投影 Sname。
这类题的关键不是直接背表达式，而是先问自己三件事：从哪里取数据、筛什么条件、最后保留哪些列。PDF 在这个例题里就是这样一步步展开的。

9.4 查询不选 1 号课的学生信息

先从 SC 中找出选了 1 号课的学号，再与 Student 做差集或差相关表达式，得到不选 1 号课的学生。这个例子用于训练“先找集合，再做差”的思路。

9.5 查询学生“刘明亮”选修的全部课程名

先连接 Student、SC、Course，再筛选 Sname=’刘明亮’，最后投影 Cname。PDF 还展示了利用属性重命名后做自然连接的写法，这个例子特别适合理解“为什么要先重命名”。

9.6 查询至少选修了其直接先行课为 5 号课的课程的学生姓名

这道题的关键是先从 Course 中筛出 Cpno=’5’ 的课程，再与 SC 和 Student 关联，最后投影学生姓名。PDF 还展示了通过中间关系再改写的等价形式，这说明复杂查询通常要拆成多个中间步骤。

9.7 查询选修全部课程的学生号码和姓名

这是除法运算的经典应用。思路是先用 πSno,Cno(SC) 除以 πCno(Course)，得到“选修了所有课程”的学生学号，再与 Student 连接取姓名。

9.8 插入、删除示例

插入示例是把学号 200504 的学生选修 4 号课、成绩 88 的记录加入 SC。删除示例则是删除学生“刘明亮”选修的英语课，并且要先考虑参照完整性，必要时先处理相关依赖记录。PDF 用这些例子说明：关系代数不仅可用于查询，也可用于更新表达。

9.9 利用重命名查询“与李勇在同一个系的学生”

PDF 的做法是先将 Student 自连接前重命名部分属性，然后做自然连接，再筛选李勇所在系，最后投影学号和姓名。这个例子非常适合理解重命名的必要性：如果不改名，自连接时属性名冲突会导致语义混乱。

十、关系代数的基本结论

关系代数可以用来完成查询、插入和删除等操作，其中查询是最重要的部分。关系代数中，并、差、笛卡尔积、选择、投影是基本运算；交、连接、除都可以由这些基本运算表示，因此引入它们并不增加语言能力，但可以简化表达。

十一、关系演算

11.1 关系代数语言与关系演算语言

关系代数语言用对关系的运算来表达查询要求，典型代表是 ISBL。关系演算语言则用谓词来表达查询要求，按谓词变元的基本对象不同，分为元组关系演算和域关系演算。

11.2 元组关系演算

元组关系演算语言以元组变量为基本对象。PDF 介绍了 ALPHA 和 QUEL，ALPHA 是由 Codd 提出的，QUEL 是 INGRES 所用语言，参考 ALPHA 研制，但并没有实际实现。

ALPHA 的基本格式是：
操作语句 <工作空间名>(表达式)：操作条件。
其中表达式可以是关系名或属性名，操作条件是一个逻辑表达式，可为空，还能附加排序要求、定额要求等。

ALPHA 的 GET 语句用于检索，例如：
GET W (SC.Cno)
GET W (Student)
GET W (Student.Sno, Student.Sage): Student.Sdept=’IS’ ∧ Student.Sage<20。

ALPHA 的更新语句包括 PUT、HOLD、UPDATE、DELETE、DROP。修改的标准步骤是：先用 HOLD 把元组读入工作空间，再用宿主语言修改，最后用 UPDATE 写回数据库。插入通常先在工作空间中构造新元组，再用 PUT 存入指定关系；删除则先 HOLD 再 DELETE。PDF 还给出了学生转系、插入课程、删除学生等完整例子。

11.3 域关系演算

典型的域关系演算语言是 QBE（Query By Example），由 M. M. Zloof 提出，并在 1978 年于 IBM 370 上实现。QBE 是基于屏幕表格的查询语言，通过填写表格构造查询，用示例元素表示结果可能情况，最终以表格形式输出结果。

QBE 的操作框架是：用户提出要求，系统显示空白表格，用户输入关系名，系统显示属性名，用户构造查询条件，最后显示结果。PDF 还给出了 QBE 的修改、插入、删除示例，如把 95001 学生年龄改为 18、把学生信息插入数据库、删除学生 95089 以及其选课记录等。

十二、关系数据语言的分类与特点

关系数据语言分为三类：关系代数语言、关系演算语言，以及同时具有关系代数和关系演算双重特点的语言。典型代表是 SQL。SQL 集 Query、DDL、DML、DCL 于一体，是关系数据库的标准语言。

关系数据语言的特点是高度非过程化，存取路径由 DBMS 优化机制决定，用户不必用循环结构完成操作，而且可以嵌入高级语言中使用。另一方面，关系代数、元组关系演算和域关系演算三者在表达能力上完全等价。

十三、关系运算的安全限制

由于集合论中的关系可以是无限的，而数据库中的关系必须是有限的，因此需要“安全限制”。不产生无限关系的关系表达式称为安全运算表达式。关系代数是安全的，只要输入关系有限，结果就有限；而关系演算不一定安全，因此需要加以限制。加上安全限制后，三种关系运算在表达能力上等价。

十四、概念结构与逻辑结构的对应

PDF 还给出了 E-R 模型与关系数据模型之间的对应关系：实体集对应关系表，实体集属性对应表的列，联系集与属性对应表和列，实体实例对应行，主键/候选键对应关系表中的主键/候选键。数据操作层面对应 SQL 语句、关系代数、关系演算；约束层面对应联系类型约束、键约束、完全参与约束以及关系模型中的三类完整性约束。

十五、本章最重要的专有名词清单

  1. 域：同类型值的集合。

  2. 笛卡尔积：多个域所有值组合形成的集合。

  3. 元组：关系中的一行。

  4. 分量：元组中的一个值。

  5. 关系：笛卡尔积的子集。

  6. 关系模式：关系的结构描述。

  7. 关系数据库模式：多个关系模式的集合。

  8. 键：能唯一标识元组的属性或属性组。

  9. 候选键、主键、联合键、全键。

  10. 实体完整性、参照完整性、用户定义完整性。

  11. 外键：引用其他关系主键的属性组。

  12. 选择、投影、连接、除、重命名、外连接。

  13. 元组关系演算、域关系演算。

  14. ALPHA、QUEL、QBE、SQL。

十六、最容易混淆的点

第一，关系、关系模式、关系数据库模式不是一回事：关系是值，关系模式是结构描述，关系数据库模式是一组关系模式。

第二，主键和外键的作用不同：主键负责唯一标识元组，外键负责引用别的关系的主键。

第三，选择和投影一个看“行”，一个看“列”；连接是把两个关系按条件拼起来；除法通常对应“所有都满足”的语义。

第四，三种关系数据语言在表达能力上等价，但风格不同：关系代数偏运算，关系演算偏谓词，SQL 则兼具两者特点。

第五，关系演算要注意安全性，否则可能出现无限结果；关系代数天然安全。

一、基础概念层易错点（最容易混淆）

1. 关系 vs 关系模式 vs 关系数据库模式

❌ 常见错误

  • 把“关系”和“关系模式”当成一回事

  • 认为表结构和表数据没有区别

✔ 正确认知

  • 关系（Relation）：某一时刻的数据（表的内容）

  • 关系模式（Schema）：表结构（列定义）

  • 数据库模式：多个关系模式的集合

👉 一句话记忆：
模式是“定义”，关系是“数据”

2. 域 vs 属性 vs 分量

❌ 常见错误

  • 把“域”当成列

  • 把“分量”和“属性”混用

✔ 正确认知

  • 域：取值范围（类型空间）

  • 属性：列名

  • 分量：某一行中的具体值

👉 举例：
学生(学号, 年龄)

  • 年龄 → 属性

  • “20” → 分量

  • “整数集合” → 域

3. 笛卡尔积 vs 关系

❌ 常见错误

  • 认为关系 = 笛卡尔积

✔ 正确认知

  • 笛卡尔积：所有组合

  • 关系：合法组合的子集

👉 关键点：
关系 = 筛选后的笛卡尔积

二、关系结构层易错点（考试高频）

4. “关系是集合”这一点被忽略

❌ 常见错误

  • 认为表中可以有重复行

✔ 正确认知

  • 关系是集合 → 元组不能重复

5. 列顺序 / 行顺序问题

❌ 常见错误

  • 认为列顺序有意义

  • 认为行顺序有意义

✔ 正确认知

  • 列顺序无关（靠属性名）

  • 行顺序无关（集合）

6. 原子性（最容易被忽视）

❌ 常见错误

  • 一个字段存多个值

  • 嵌套结构（工资=基本+奖金+补贴）

✔ 正确认知

  • 每个属性必须是不可再分的原子值

👉 这是关系模型最基本约束

三、键与约束层易错点（重点）

7. 主键可以为空（严重错误）

❌ 常见错误

  • 主键允许 NULL

✔ 正确认知

  • 主键必须：

    • 唯一

    • 非空

👉 原因：
否则实体无法区分

8. 候选键 vs 主键

❌ 常见错误

  • 认为只有一个键

  • 或认为候选键就是主键

✔ 正确认知

  • 候选键：所有可能唯一标识的属性组

  • 主键：选出来的一个

9. 外键理解错误（非常常考）

❌ 常见错误

  • 外键必须等于某个值

  • 外键不能为 NULL

✔ 正确认知
外键取值：

  • 可以为空

  • 或必须在被参照表中存在

👉 条件：
非空时必须匹配主键

10. 参照完整性方向搞反

❌ 常见错误

  • 分不清谁参照谁

✔ 正确认知

  • 外键所在表 = 参照关系

  • 主键所在表 = 被参照关系

11. 忽略“同一表内部的参照完整性”

❌ 常见错误

  • 认为外键只能跨表

✔ 正确认知

  • 同一表也可以外键

👉 例子（PDF）：
学生(学号, 班长)
班长必须是某个学生学号

12. 用户定义完整性被忽略

❌ 常见错误

  • 只记前两个约束

✔ 正确认知
第三类同样重要：

  • 成绩 ≥ 0

  • 年龄合理范围

1. 概念定义

  • MMKG 是什么：MMKG 是传统文本知识图谱的扩展，它将文本与图像、甚至视频、音频等多种模态相连，构建一个更通用的知识系统。

    • 与知识图谱 KG：MMKG 是 KG 的多模态化版本，不仅包含实体和关系三元组，还包含关联的多模态属性值。
    • 与普通图/多模态属性图 MAG：普通图侧重拓扑，MAG 侧重节点的多模态属性（如论文文本和图片）。MMKG 在此基础上强调事实性的结构化知识（即三元组关系）。

2. 常见任务

MMKG 的应用任务通常分为图谱内任务和图谱外（下游）任务：

  • 多模态知识图谱补全 (MKGC / Link Prediction)：给定三元组的前两项（如 实体h, 关系r, ?），利用多模态信息预测缺失的尾实体。
  • 多模态实体对齐 (MMEA)：识别并链接来自不同 MMKG 但指向现实世界中同一个实体的实体对。
  • 多样化图像检索 (Diverse Image Retrieval)：利用 MMKG 中的丰富关系显式扩展查询的子语义，从而检索出语义更丰富、多样的图像。
  • 实体识别与链接 (MNER / MEL)：利用 MMKG 提供的视觉特征帮助识别社交媒体帖子等场景中的命名实体。
  • 下游推理：如多模态问答（VQA）和个性化推荐。
    3. 代表数据集
  • 基础知识图谱补全类：
    • FB15K-237、WN18、WN18RR、WN9：这些是传统 KG 经过图像/描述增强后的常用 MKGC 基准数据集。
  • 实体对齐类：
    • FB15K-DB15K、FB15K-YAGO15K：专门用于测试跨图谱实体对齐性能。
  • 大规模通用 MMKG：
    • Richpedia：包含城市、景点、人物等实体的综合性 MMKG。
    • TIVA-KG：清华大学提出的涵盖文本、图像、视频和音频四种模态的通用 KG。
  • 特定任务类：
    • Div150AdHoc / Div400：用于多样化图像检索任务。
      4. 代表方法
  • 平移距离模型（Translation-based）：
    • IKRL：扩展 TransE，将实体视觉特征与结构信息分别建模学习。
    • TransAE：结合多模态自动编码器（Auto-encoder）与 TransE，学习统一的表示空间。
  • 特征融合模型（Fusion-based）：
    • RSME：设计了忘记门（Forget Gate）来过滤无关的噪声图像，优化实体表示。
    • MKGformer：利用混合 Transformer 架构（ViT + BERT）进行粗粒度的前缀引导交互和细粒度的关联感知融合。
  • 模态解耦模型：
    • MoSE：通过“模态切分学习”和“集成推理”解决不同模态间的语义冲突问题。
  • 大模型结合模型：
    • CMR：针对归纳式补全，通过对比学习对齐查询与实体的多模态空间，并利用语义邻居检索增强推理

多模态图学习（MAG/MMKG）基准数据集调研报告

数据存储路径：/root/autodl-tmp/datasets/xiaoyu_mmkg/

摘要 (Abstract)

本报告概述了当前部署于服务器上的多模态图学习数据集资产。调研涵盖了 MKG_Advanced (顶会主流) 与 MM-GRAPH (2024最新基准) 两大体系，共计 10 个子数据集。调研重点关注了数据的模态组成、表征维度以及实体-模态对齐逻辑。结果表明，所有数据集均采用属性化存储（Attribute-based），有效规避了异质图中“图像独立节点”带来的计算复杂性，目前已具备直接开展实验的生产条件。

一、 模态组成与表征策略 (Modality & Representation)

调研发现，该批数据集通过以下四种信息流实现了实体的全模态覆盖：

  1. 拓扑结构模态 (Relational Structure)：基于标准 (h, r, t) 三元组构建的知识图谱，文件格式为 .txt 或 .pickle。

  2. 视觉语义模态 (Visual Semantics)：

    • Advanced 系列：采用预提取的 Visual Tokens。

    • MM-GRAPH 系列：采用 CLIP-ViT-Large 提取的 1024 维 高密度特征。

  3. 文本语义模态 (Textual Semantics)：

    • Advanced 系列：采用 768 维 (BERT/RoBERTa) 或 4096 维 (LLM-based) 特征。

    • MM-GRAPH 系列：采用 768 维 (T5) 特征。

  4. 结构特征模态 (Structural Embeddings)：额外集成了 DeepWalk 与 Node2vec 的预训练特征，用于拓扑信息增强的基准对比。

二、 数据存储格式与逻辑 (Data Logic)

1. Token 对齐逻辑 (MKG_Advanced 系列)

该系列数据集（DB15K, MKG-W, MKG-Y）采用解耦存储方案：

  • 特征存储：实体特征独立存储于 .pth 张量文件中。

  • 映射机制：通过 .json 格式的实体名到索引（ID-to-Index）映射表，模型可实现在训练过程中对高维特征的 O(1) 级秒级检索。

2. 原始索引逻辑 (MM-GRAPH 系列)

除 MM-Codex 外，MM-GRAPH 体系数据集（如 Ele-fashion 等）已实现了高度集成：

  • 特征集成：视觉特征以 clip_feat.pt 形式存放，其 Tensor 的行顺序与图中节点的数值 ID 严格对齐。

  • 原始资源备份：在 raw-data/ 目录下保留了原始 .jsonl 文本与 .tar 图像包，确保了数据的可溯源性。

三、 关键调研结论：关于图像节点独立性

针对多模态知识图谱中常见的“图像是否作为独立节点（Independent Node）”的担忧，本研究结论如下：

  • 结论：所有受调研数据集均采用 “实体属性化（Attribute-augmented Vertices）” 存储。

  • 逻辑：多模态信息被视为节点的 Feature Vector，而非图拓扑中的 Vertex。

  • 优势：该逻辑允许我们维持**同质图（Homogeneous Graph）**结构，在保持图神经网络（GNN）计算效率的同时，通过多模态融合层（Fusion Layer）进行特征集成，极大简化了异质图建模的复杂度。
