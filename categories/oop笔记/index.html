第一部分：知识点

1. Inline Function 的核心思想

Inline function（内联函数）的本质是：用函数的方式写代码，但在编译阶段像宏一样直接展开。

作用：

  • 消除函数调用开销（不需要压栈、跳转、返回）
  • 提高运行效率（尤其是小函数被频繁调用时）

例如：

inline int max(int a, int b) {
return a > b ? a : b;
}

调用：

max(a, b)

在编译时会被替换为：

(a > b ? a : b)

2. Inline vs 宏（#define）

（1）宏的本质

宏是纯文本替换（预处理阶段），没有语法检查。

#define MAX(a, b) a > b ? a : b

问题示例：

int c = MAX(a, b) + 2;

实际展开为：

a > b ? a : b + 2

优先级错误，导致结果不符合预期。

（2）宏的缺点

  1. 容易产生隐藏 Bug（优先级问题）
  2. 没有类型检查
  3. 不能作为类成员函数
  4. 调试困难

（3）Inline 的优势

Inline 函数：

  • 有类型检查
  • 符合函数语义
  • 可以作为类成员函数
  • 编译器可优化

👉 结论：C++ 中应优先使用 inline，避免使用宏

3. Inline 的工作机制

编译器处理 inline 函数时：

  • 保存函数类型（函数签名）
  • 同时保存函数体
  • 在调用处尝试展开

但注意：
👉 inline 只是建议（hint），编译器可以拒绝

当函数很短但调用很多次时，用 inline 可以减少函数调用开销，提高效率。
inline 函数会在编译时像宏一样展开，从而避免函数调用过程。
但相比宏，inline 更安全，所以应尽量用 inline 代替宏。

✅ 最后一句总结（建议记）

👉 inline 是“带类型检查的宏替代方案”，用于减少小函数调用开销，但是否展开由编译器决定

4. Inline 的使用规则（考试重点）

（1）定义必须在调用之前

因为编译器需要看到函数体才能展开。

（2）适用于小函数

适合：

  • 简单计算函数
  • getter/setter
  • 短逻辑

（3）不适合的情况

一般不会被 inline：

  • 含循环（for / while）
  • 含 switch
  • 含异常处理
  • 递归函数
  • 代码过大

5. Inline 在类中的使用

（1）类内定义（自动 inline）

class Point {
public:
void print() const {
// 自动 inline
}
};

👉 在类内部定义的函数默认 inline

（2）类外定义（需要显式 inline）

class Point {
public:
void print() const;
};

inline void Point::print() const {
// 需要 inline 关键字
}

👉 原因：
类外定义默认不是 inline，需要手动声明

6. Inline vs 宏的典型代码对比

宏：

#define f(x) xx
f(x+1) → x+1x+1 → 错误

Inline：

inline int f(int x) {
return xx;
}
f(x+1) → (x+1)(x+1) → 正确

👉 本质区别：

  • 宏：文本替换
  • inline：语法级函数展开

7. Inline 的限制（重要）

  1. 代码过大 → 编译器不会展开
  2. 取函数地址 → 无法 inline
  3. 复杂控制流 → 无法 inline

8. Inline 的使用建议（总结）

  • 小函数 + 高频调用 → 用 inline
  • 复杂逻辑 → 普通函数
  • 不要用宏替代函数

第二部分：易错点总结

1. 宏优先级陷阱（最常考）

错误：

#define MAX(a, b) a > b ? a : b
MAX(a, b) + 2

正确写法（但仍不推荐）：

#define MAX(a, b) ((a) > (b) ? (a) : (b))

👉 但本质解决方案：用 inline

2. 误以为 inline 一定会展开

错误理解：

写了 inline 就一定内联

实际：

  • 编译器可以拒绝
  • 只是建议，不是强制

3. 忘记“定义必须在调用之前”

错误：

int main() {
max(1,2); // 此时未看到定义
}
inline int max(int a, int b) {…}

👉 inline 必须在调用前定义

4. 类外定义忘记 inline

错误：

void Point::print() const { }

👉 会变成普通函数

正确：

inline void Point::print() const { }

5. 误用 inline 处理复杂函数

错误：

  • 循环
  • 递归
  • 大量逻辑

👉 编译器直接忽略 inline

6. 宏与函数混淆

典型误解：

  • 宏 = 函数（错误）
  • 宏没有类型、没有作用域

7. inline 与 const、引用等混用不理解

例如：

void print(const string& msg)

👉 这里重点是：

  • const 防止修改
  • 引用避免拷贝
  • 和 inline 是不同层面的优化

第一部分：知识点整理（普通文本）

1. const 的核心作用

  • const 用于区分“可变”和“不可变”
  • 提供：
    • 类型安全（比 #define 更强）
    • 编译期检查
    • 程序稳定性

与 #define 的区别

  • #define：纯文本替换，无类型检查
  • const：
    • 有类型
    • 编译器可检查错误
    • 更安全

2. const 基本规则

  • const 变量必须初始化
  • 一旦初始化，不能修改

示例：

  • const int x = 10; ✔
  • const int x; ✘（未初始化）
  • x = 20; ✘（不可修改）

数组：

  • const int a[] = {1,2,3}
    • 每个元素都不可修改

3. const 与指针（重点）

判定原则

👉 const 修饰“离它最近的对象”

3.1 指向常量的指针（pointer to const）

定义：

  • const int* p
  • int const* p

特点：

  • 可以改指针指向
  • 不能改指针指向的值

示例：

  • p = &x ✔
  • *p = 10 ✘

3.2 常量指针（const pointer）

定义：

  • int* const p

特点：

  • 不能改变指针指向
  • 可以修改值

示例：

  • p = &y ✘
  • *p = 10 ✔

3.3 指向常量的常量指针

定义：

  • const int* const p

特点：

  • 不能改指向
  • 不能改值

总结
在 C/C++ 中，权限本质指的是“是否可以通过某个指针修改数据”。所谓“权限缩小”，就是把原本“可以修改”的对象，通过 const 限制为“不可修改”，这种行为是安全的，因此允许，例如 const int *p 指向变量，本质是“我选择不通过 p 修改它”；
因此指向常量的指针以及指向常量的常量型指针可以指向变量

而“权限放大”则是试图通过指针获得本不具备的修改能力（如用 int * 指向 const int），这会破坏数据的只读性，因此被禁止。

所有指针与常量的规则，本质都遵循一句话：👉 只能减少修改权限，不能增加修改权限；同时 const 只限制“指针的使用方式”，不会改变变量本身的属性，因此“指向常量的指针”“常量指针”“双 const 指针”本质都是在约束“能不能改值”和“能不能改指向”，而是否允许绑定某个对象，取决于是否违反了“不能放大权限”的原则。

  • 能改”的指针 ❌ 不能指向 const
  • “不改”的指针 ✅ 可以指向任何

4. const 与函数

4.1 参数中的 const

目的：
👉 防止函数修改外部数据

示例：

  • void f(const int* p)
    • *p 不可修改

4.2 返回值中的 const

目的：
👉 防止调用者修改返回对象

示例：

  • const char* func()

int* const w();

int main() {
int* p = w();
p = nullptr;
}
合法 因为虽然p被复制了一个限制地址的指针 但本质是复制 失效。所以可以被重新修改地址

  • int* const w(); 里的 const 限制的只是函数内部的那份指针
  • 函数返回时，你拿到的是拷贝，所以外部的变量 p 不再受原来的 const 限制
  • 也就是 “指针本身的 const 在返回值上失效”

4.3 规则总结

  • const 参数：保护输入
  • const 返回：保护输出

5. 临时对象（Temporaries）

  • 编译器生成的临时对象默认是 const
    因为临时对象生命周期很短，C++不希望你去修改一个马上就要消失的东西
    意义：

  • 防止对临时对象进行非法修改

  • 提高安全性

  • 临时对象 = 没有变量名接收的对象表达式结果

6. 类中的 const（重点大题区）

6.1 static 成员变量

特点：

  • 所有对象共享
  • 必须在类外初始化

格式：

  • int Class::var = value;

6.2 const 成员变量

特点：

  • 必须初始化
  • 只能在构造函数初始化列表中初始化

原因：

  • const 不能先声明再赋值

6.3 初始化列表

作用：

  • 初始化 const 成员
  • 初始化引用成员

示例：

  • A::A(int i) : a(i) {}

6.4 初始化顺序（超级重要）

👉 按“声明顺序”，不是初始化列表顺序

错误来源：

  • 写顺序 ≠ 执行顺序

6.5 const 成员函数

定义：

  • 函数后加 const

特点：

  • 不能修改成员变量

示例：

  • int get() const

错误：

  • return x++ ✘

6.6 const 对象

规则：

对象类型 可调用函数
const对象 只能调用 const函数
非const对象 可调用所有函数

6.7 mutable（非常重要考点）

作用：
👉 允许在 const 函数中修改变量

示例：

  • mutable int x;

意义：

  • 逻辑常量 vs 物理常量

7. 总结核心思想

  • const 是“类型系统的一部分”
  • 用于：
    • 限制修改
    • 提高安全
    • 强化接口设计

第二部分：易错点总结（普通文本）

1. const 未初始化

  • const int x; ✘
    👉 必须初始化

2. const 指针混淆（最常错）

常见误解：

  • const int* p ≠ int* const p

记忆方法：
👉 “看 const 靠谁近”

3. 函数参数错误

  • 不能把 const 指针传给非 const 参数

示例：

  • void f(int* p)
  • const int* cp
  • f(cp) ✘

4. 返回值错误

  • const 返回值不能赋给非 const 指针

5. const 成员变量初始化错误

错误写法：

  • 在构造函数体内赋值

正确：

  • 用初始化列表

6. 初始化顺序错误（高频考点）

  • 顺序由“声明顺序”决定
  • 与初始化列表顺序无关

7. const 成员函数违规修改数据

  • 修改成员变量会报错

8. const 对象调用非 const 函数

  • 会编译错误

9. mutable 误用

  • 只用于“逻辑不变但需要修改”的变量
  • 不要滥用

10. 临时对象修改错误

  • 临时对象是 const
  • 不能修改

第一部分：知识点（普通文本）

一、构造函数（Constructor）

1. 基本概念

  • 构造函数是在对象创建时自动调用的函数，用于初始化对象。
  • 特点：
    • 函数名与类名相同
    • 没有返回值（连 void 都没有）
    • 在对象定义时自动调用

2. 调用机制

  • 对象创建时自动调用构造函数
  • 编译器隐式传入 this 指针（指向当前对象）

3. 带参数构造函数

  • 构造函数可以有参数
  • 可以用于初始化成员变量

示例思想：

  • 将传入参数赋值给成员变量
  • 实现对象初始化的灵活性

4. 构造函数重载

  • 一个类可以有多个构造函数（参数不同）
  • 编译器根据参数匹配调用对应构造函数

例如：

  • Student(int id)
  • Student(int year, int order)

二、默认构造函数（Default Constructor）

1. 定义

  • 可以无参数调用的构造函数

2. 形式

  • 显式定义：A() {}
  • 或使用默认参数实现：A(int x = 0) 就可以实现额外传几个就改几个。其余的仍为默认值

3. 注意事项

  • 如果定义了带参数构造函数，而没有默认构造函数：
    • 编译器不会自动生成默认构造函数
    • 会导致无法无参创建对象

4. 成员对象影响

  • 类成员对象会先调用其构造函数
  • 若成员类没有默认构造函数，会导致错误

三、析构函数（Destructor）

1. 基本概念

  • 用于对象销毁时释放资源

2. 特点

  • 函数名：~类名
  • 无参数
  • 不能重载
  • 无返回值

3. 调用时机

  • 对象生命周期结束时自动调用：
    • 作用域结束
    • 函数结束
    • delete（动态对象）

4. 调用顺序

  • 构造：先成员 → 后自身
  • 析构：先自身 → 后成员（逆序）

四、构造与析构的执行过程

1. 局部对象

  • 进入作用域：构造
  • 离开作用域：析构

2. 嵌套调用

  • 函数中创建对象：
    • 函数结束立即析构

3. 示例核心逻辑

  • 对象按栈顺序创建
  • 按逆序销毁（类似栈）

  1. 有没有 new？
    有 → 堆对象

  2. 在不在函数里？
    在 → 局部对象（栈）。作用域与函数的生命周期绑定

  3. 在类里面？
    是 → 成员对象。 和这个类的周期绑定。

  4. 在函数外？
    是 → 全局对象。和程序的运行周期绑定

  5. 有 static？
    是 → 静态对象
    对象什么时候死，不看它写在哪个文件，
    只看它在哪个作用域里被“创建”。

对于局部对象

真的是栈（物理结构）

对于其他对象

不是栈，但遵循“栈式规则”

五、资源管理思想（重要）

1. 初始化与清理

  • 构造函数：负责资源申请
  • 析构函数：负责资源释放

2. 典型资源

  • 动态内存（new）
  • 文件
  • 网络连接

六、数组初始化

1. 基本类型数组

  • int a[5] = {1,2,3,4,5}
  • int b[6] = {2} → 其余为 0
  • int c[] = {1,2,3}

2. 数组大小计算

  • sizeof(c) / sizeof(c[0])

七、对象数组初始化

1. 初始化方式

  • 直接初始化：
    • Date d[2] = {Date(…), Date(…)}
  • 先创建再赋值：
    • d[0] = Date(…)

2. 默认构造函数的重要性

  • 如果数组未完全初始化：
    • 剩余元素调用默认构造函数
    • 因为数组初始化 = 对每个元素逐个构造，有没有“初始化值” → 决定是否需要默认构造

八、代码设计思想总结

1. 封装 + 自动管理

  • 构造函数保证初始化
  • 析构函数保证清理

2. RAII 思想（核心）

  • Resource Acquisition Is Initialization
  • 资源与对象生命周期绑定

3. 安全性提升

  • 避免未初始化变量
  • 避免资源泄漏

第二部分：易错点（普通文本）

一、构造函数相关

  1. 写了带参构造函数但忘记写默认构造函数
    → 导致无法创建无参对象
  2. 误以为构造函数有返回值
    → 实际没有任何返回类型
  3. 构造函数不会自动执行逻辑以外代码
    → 必须手动初始化成员变量
  4. 构造函数重载冲突
    → 参数不明确可能导致二义性

二、默认构造函数陷阱

  1. 一旦定义了有参构造函数，默认构造函数不会自动生成
  2. 类成员对象没有默认构造函数
    → 当前类构造失败

三、析构函数相关

  1. 析构函数不能带参数、不能重载
  2. 忘记释放动态内存
    → 内存泄漏
  3. 错误理解析构顺序
    → 实际是“后构造先析构”

四、对象生命周期错误

  1. 误以为函数结束对象还存在 但注意是函数先结束然后再释放对象
    → 实际已析构
  2. 临时对象生命周期极短
    → 容易产生悬空引用

五、数组相关

  1. 对象数组必须有默认构造函数（除非完全初始化）
  2. 未初始化元素会调用默认构造函数
    → 若不存在则编译错误

六、资源管理错误

  1. 在构造函数中申请资源但析构函数未释放
  2. 使用裸指针但未管理生命周期

一、核心考点总结（不重不漏版）

1️⃣ Access Control（访问控制）——核心基础

⭐ 两个本质目的（必考理论题）

  1. 保护数据（防止乱用）

  2. 实现实现隐藏（implementation hiding）

👉 关键词：

  • interface vs implementation

  • 抽象数据类型（ADT）

⭐ 三种访问控制（必考）

关键字 含义
public 所有人可访问
private 仅类内成员函数可访问
protected 类内 + 子类

👉 易考点：

  • 外部访问限制

  • 继承时访问权限

⭐ 类设计风格（容易考选择/判断）

👉 本质：

  • 接口在前 or 在后都可以

  • 但推荐：public → interface

2️⃣ Friend（重中之重🔥）

⭐ Friend 本质（三句话必背）

普通成员函数有 3 个属性：

  1. 能访问 private

  2. 属于类作用域

  3. 必须通过对象调用（this）

👉 friend 只有第 1 个

⭐ Friend 特性（高频选择题）

特性 是否成立
可访问 private ✅
是类成员 ❌
有 this 指针 ❌
受 public/private 控制 ❌

⭐ Friend 类型（必考分类）

  1. 普通全局函数
  1. 另一个类的成员函数

👉 难点：

  • 必须先声明类 B
  1. 整个类作为 friend

👉 含义：

  • B 可以访问 A 的所有 private

⭐ Friend 性质（必考概念题）

  • ❗ 非对称（asymmetric）

  • ❗ 不可传递（non-transitive）

  • ❗ 不可继承（non-inherited）

3️⃣ Static Members（静态成员）

⭐ 核心知识点

👉 特点：

  • 所有对象共享

  • 必须类外定义：

⭐ 访问方式

⭐ 高频考点

  • static 属于类，不属于对象

  • friend 可以访问 static private

4️⃣ Implementation Hiding（实现隐藏）

⭐ 核心思想（大题必考）

👉 接口不变，内部可以改

⭐ Handle / Cheshire（高阶考点🔥）

👉 本质：

技术 含义
前向声明 隐藏结构定义
指针 隐藏实现
cpp 中定义 真正实现

⭐ 优点（必考）

  1. 减少编译依赖

  2. 隐藏实现细节

  3. 提高可维护性

⭐ 缺点

  • 指针复杂

  • 内存管理问题

二、易错清单（高频丢分点🔥）

❌ 1. 误以为 friend 是成员函数（最常错）

错误认知：

friend 写在类里 → 就是类成员

正确：

  • friend 不是成员函数
  • 只是“被授权访问 private”

👉 直接后果：

  • ❌ 没有 this
  • ❌ 不能 obj.func()
  • ✅ 只能普通函数调用

❌ 2. 误以为 friend 受 public/private 控制

class A {
private:
friend void func(A&);
};

错误理解：

private → func 是私有函数

正确：

  • friend 不属于类
  • public/private 对它没有意义

❌ 3. 忘记 friend 仍然需要定义

class A {
friend void func(A&);
};

❗错误：

  • 以为已经完整

❗正确：

void func(A& a) {
// 必须定义
}

❌ 4. 成员函数作为 friend 的顺序问题（大坑🔥）

class Girl;

class Boy {
void show(Girl&);
};

class Girl {
friend void Boy::show(Girl&);
};

👉 易错点：

  • ❗必须先声明 Girl
  • ❗Boy 必须先有函数声明

否则编译错误

❌ 5. friend 非对称（必考）

class A {
friend class B;
};

❗错误理解：

A 和 B 互相访问

❗正确：

  • ✅ B 能访问 A
  • ❌ A 不能访问 B

❌ 6. friend 不可传递（考试超爱考）

A friend B;
B friend C;

❗错误：

C 可以访问 A

❗正确：

  • ❌ 不成立

❌ 7. friend 不可继承

class A {
friend class B;
};

class C : public B {};

❗错误：

C 也能访问 A

❗正确：

  • ❌ 不可以

❌ 8. static 成员误区

class A {
static int x;
};

❗常错：

  • ❌ 忘记类外定义
  • ❌ 认为属于对象

正确：

int A::x = 0;

❌ 9. static + friend 混淆

👉 friend 可以访问：

  • private 成员
  • static 成员

但：

👉 static 本质仍属于类

❌ 10. Cheshire / Handle（理解不到位）

class Handle {
struct Cheshire;
Cheshire* ptr;
};

❗错误理解：

只是 forward declaration

❗真正本质：

👉 隐藏实现（implementation hiding）

❌ 11. “访问权限 ≠ 可见性”

👉 很多人混淆：

概念 含义
可见性 编译器是否知道
访问权限 能不能用

👉 friend 是：

  • 可见 + 可访问

❌ 12. 误以为 private 不能被外部访问（绝对化错误）

❗错：

private 永远不能被外部访问

❗对：

  • friend 可以访问
  • 成员函数可以访问
