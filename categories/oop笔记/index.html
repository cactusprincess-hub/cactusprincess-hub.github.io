二、本章核心规则

  • 运算符重载本质上还是函数调用，只是写法更像表达式。

  • 不能新造运算符，不能改运算符优先级、结合性、操作数个数，也不能改语法结构。

  • 只用于内置类型的表达式，不能被重载。

  • 运算符函数名写成 operator@。

  • [] 和 -> 必须是成员函数。

  • ++、-- 要分前置和后置，后置版本靠一个“占位用的 int 参数”区分。

  • operator+ 常返回新对象；operator+= 常返回当前对象引用。

  • =、拷贝构造、自动类型转换这三块最容易和代码题连在一起考。

三、本章常考题型

1. 判断成员函数还是友元函数

常考：c1 + 1.5、1.5 + c1 哪个能过。
记住：左操作数是不是当前类对象，是判断关键。

2. 判断前置 ++ / 后置 ++

常考：++a 和 a++ 是否调用同一个函数。
记住：不是同一个，后置有 int 占位参数。

3. [] 和 -> 的写法

常考：是否能写成非成员函数。
记住：不能，必须成员函数。

4. 赋值运算符和拷贝构造

常考：B = A; 和 Location B = A; 分别调用什么。
记住：前者是赋值，后者是拷贝构造。

记住：进来变成我，用构造函数；我出去变成别的类型，用转换运算符。

13. 指针成员的深拷贝问题

PDF 重点提醒：类里一旦有裸指针成员，默认拷贝可能让多个对象指向同一块内存，导致重复释放。于是必须自己写拷贝构造和赋值运算符，做深拷贝。
只有类里有指针 **，才分浅 / 深拷贝；没有指针，两者完全一样 **

1. 浅拷贝（编译器自动给的）

只复制指针的地址，不复制内存

→ 多个对象共用同一块内存

❌ 问题：析构时重复删内存→程序崩溃；赋值会丢内存（泄漏）

2. 深拷贝（必须手动写）

不复制地址，新开一块独立内存，只复制数据

→ 每个对象各用各的内存

✅ 安全，不崩溃、不泄漏
终极口诀

浅拷贝：共用地址，必崩

深拷贝：各开内存，安全

第一部分：知识点（普通文本）

1. 指针（Pointer）回顾

指针本质是存储地址的变量。定义时必须指定类型，并建议初始化。

例如：

int a = 0;
int* p = &a;

核心能力：

  • 通过 *p 修改指向对象
  • 指针类型决定解引用方式

void* 指针

  • 可以接收任意类型指针
  • 但不能直接转换回具体类型（需要强制类型转换）

👉 本质：
void* = “无类型地址容器”，但缺乏类型信息

2. 引用（Reference）

（1）基本特性

引用是变量的别名（alias）：

int a = 3;
int& r = a;

特点：

  • 必须初始化
  • 一旦绑定，不能改变指向
  • 不能为空（不存在 NULL reference）

👉 本质：
引用 ≈ “不可重新绑定的指针（语法更安全）”

（2）引用 vs 指针

特性 引用 指针
是否必须初始化 是 否
是否可变指向 否 是
是否可为空 否 是
语法 更简洁 更灵活

3. 引用在函数中的作用

（1）作为参数（核心考点）

void g(int& x) {
x++;
}

👉 效果：

  • 修改实参本身
  • 类似“隐式指针”

（2）作为返回值（重点）

int& g(int& x) {
return x;
}

可以写：

g(a) = 10;

👉 本质：
返回的是“左值”

（3）错误返回引用

int& h() {
int x = 0;
return x; // 错误！
}

👉 原因：

  • 返回局部变量引用 → 悬空引用（dangling reference）

（4）安全返回引用

int& h() {
static int x = 1;
return x;
}

👉 static 保证生命周期

4. const 引用（重要）

void g(const int& x)

作用：

  1. 防止修改
  2. 可以绑定临时变量（如常量）

g(1); // 合法

👉 本质：
const 引用 = “只读引用 + 支持临时对象”

第一部分：知识点（普通文本）

1. Name Control 的核心目标

这一章讲的是如何控制“名字”的创建、可见性、存储位置和链接属性。课件把重点放在两类机制上：static 和 namespace。前者用于限制名字可见范围、改变存储方式，后者用于把全局名字拆分到更可管理的命名空间中。

2. static 的两个基本含义

static 有两个核心作用。第一，它可以控制名字的可见性，使该名字不能在翻译单元外或类外被看到；第二，它表示对象存储在静态数据区，而不是每次函数调用时都在栈上重新创建。也就是说，static 同时涉及“作用域/链接”与“存储期”两个层面。

3. 函数内 static 变量

函数内部的 static 局部变量会在多次函数调用之间保留值。它只在第一次执行到定义处时初始化一次，之后不会再次初始化。若是内置类型且没有写初值，编译器会保证它被初始化为 0。普通局部变量则每次调用都会重新创建并销毁。

4. 函数内 static 对象

函数内部的 static 用户自定义类型对象也是“只构造一次”。它的构造发生在第一次调用到该语句时，之后一直存在到程序结束。对于用户定义类型，如果没有提供初始化器，通常要求有默认构造函数。课件中的例子说明：static 对象的构造与析构时机，和普通局部对象完全不同。

5. 对象的构造与析构顺序

全局对象在进入 main() 之前就会被构造；函数内的 static 对象则只有函数被调用时才会构造。程序结束时，已经构造出来的对象会按照“构造的逆序”析构。课件里通过全局对象、static 局部对象和普通局部对象的组合，演示了析构顺序的差异。

6. static 数据成员

类中的 static 数据成员属于整个类，而不是某个具体对象。所有对象共享这一份存储空间。它必须在类外进行定义和初始化，写法通常是 int Myclass::obj = 8;，而且这里不再写 static。这类成员常用于表示“全类共享数据”。

7. static 成员函数

static 成员函数不依赖某个对象，因此没有隐含的 this 指针。它只能直接访问类的 static 数据成员，不能直接访问普通非静态成员。static 成员函数可以像普通函数一样通过类名调用，也可以在类内部直接定义，从而成为内联形式。

8. 链接属性与存储类型

课件把“可见性/链接”和“存储位置”分开讲：外部链接的名字可以在多个翻译单元中可见，普通全局变量和普通函数通常是外部链接；内部链接则只在本翻译单元可见，static、const、inline 名字通常默认具有内部链接。存储类型则常分为静态数据区、栈和堆，对应全局/静态对象、局部对象、new 创建的对象。

9. namespace 的作用

namespace 的目的，是把全局命名空间拆分成若干逻辑模块，减少大型项目中的名字冲突。命名空间里的名字不会直接污染全局空间，使用时可以通过作用域限定符访问，也可以通过 using 引入。

10. 命名空间的创建与使用

命名空间只能出现在全局作用域或另一个命名空间内部，不能像类一样创建对象；结尾也不需要分号。命名空间还可以起别名。使用命名空间时有两种常见方式：using directive 一次性引入整个命名空间的名字，using declaration 只引入某一个名字。

11. 作用域限定符的用途

作用域解析运算符 :: 可以用来定义或访问命名空间中的名字，也可用于类外定义类成员。课件中的例子展示了在命名空间中先声明类，再在外部定义其成员函数、嵌套类和普通函数的写法。

12. using 的两种方式

using namespace X; 会把整个命名空间引入当前作用域，适合小范围、短代码；using X::name; 只引入一个名字，更安全、更精确。课件还强调：在头文件里不要写全局 using directive，否则容易把名字污染到所有包含该头文件的文件中。

第二部分：易错点（普通文本）

1. 把 static 只理解成“变量不变”

很多人会把 static 简单理解成“值不变”，这是不完整的。课件强调 static 有两层意思：一层是名字的可见性/链接，一层是静态存储期。也就是说，static 的重点不是“常量”，而是“生命周期更长、可见范围更受控”。

2. 把 static 局部变量和普通局部变量混淆

普通局部变量每次进入函数都会重新创建；static 局部变量只初始化一次，并在多次调用间保留状态。课件里的例子里，n++ 会跨调用累加，而 x++ 每次都从 1 重新开始。

3. 忘记 static 内置类型默认置零

如果 static 内置类型没有显式初始化，编译器保证其被初始化为 0。很多人会误以为它是“随机值”，但课件明确给出了这个规则。这个点常用于判断程序第一次输出。

4. 误解 static 对象的构造和析构时机

函数内 static 对象不是每次进入函数都构造；它只在第一次执行到该语句时构造。析构也不是函数退出时发生，而是在程序结束时统一清理。这个差异是静态对象题的高频失分点。

5. 忘记静态成员必须类外初始化

static 数据成员只是“声明在类里”，真正的定义与初始化必须写在类外，而且不再写 static。如果只在类中声明而不在类外定义，链接阶段通常会出问题。

6. 把 static 成员函数当成普通成员函数

static 成员函数没有 this，所以不能直接访问普通非静态成员。它只能直接碰 static 成员。考试里经常通过“能不能访问某个变量”来考这个区别。

7. 混淆外部链接和内部链接

普通全局变量和函数通常是外部链接，能被多个翻译单元看到；static 名字通常只有内部链接。const 和 inline 名字也常默认表现为内部链接。这个点如果和“存储位置”混在一起，很容易答错。

8. 把 namespace 当成类

namespace 不能实例化，也不能像类那样有对象。它只是一个“名字容器”。很多同学会把“namespace 里能放类”误解成“namespace 本身也是一种类”，这是不对的。

9. using directive 和 using declaration 混用

using namespace calculator; 会把整个命名空间的名字都引入，可能导致重名和二义性；using calculator::Add; 只引入某个名字，更稳妥。课件还演示了引入整个命名空间后，调用 Print 可能和外部同名函数冲突。

10. 在头文件里写全局 using directive

课件明确提醒：不要在头文件里使用全局 using directive。因为头文件会被多个源文件包含，这会把命名空间里的名字无控制地扩散到全局作用域，造成命名冲突。

第一部分：知识点

1. Inline Function 的核心思想

Inline function（内联函数）的本质是：用函数的方式写代码，但在编译阶段像宏一样直接展开。

作用：

  • 消除函数调用开销（不需要压栈、跳转、返回）
  • 提高运行效率（尤其是小函数被频繁调用时）

例如：

inline int max(int a, int b) {
return a > b ? a : b;
}

调用：

max(a, b)

在编译时会被替换为：

(a > b ? a : b)

2. Inline vs 宏（#define）

（1）宏的本质

宏是纯文本替换（预处理阶段），没有语法检查。

#define MAX(a, b) a > b ? a : b

问题示例：

int c = MAX(a, b) + 2;

实际展开为：

a > b ? a : b + 2

优先级错误，导致结果不符合预期。

（2）宏的缺点

  1. 容易产生隐藏 Bug（优先级问题）
  2. 没有类型检查
  3. 不能作为类成员函数
  4. 调试困难

（3）Inline 的优势

Inline 函数：

  • 有类型检查
  • 符合函数语义
  • 可以作为类成员函数
  • 编译器可优化

👉 结论：C++ 中应优先使用 inline，避免使用宏

3. Inline 的工作机制

编译器处理 inline 函数时：

  • 保存函数类型（函数签名）
  • 同时保存函数体
  • 在调用处尝试展开

但注意：
👉 inline 只是建议（hint），编译器可以拒绝

当函数很短但调用很多次时，用 inline 可以减少函数调用开销，提高效率。
inline 函数会在编译时像宏一样展开，从而避免函数调用过程。
但相比宏，inline 更安全，所以应尽量用 inline 代替宏。

✅ 最后一句总结（建议记）

👉 inline 是“带类型检查的宏替代方案”，用于减少小函数调用开销，但是否展开由编译器决定

inline 需要在编译阶段展开，而编译是按文件独立进行的，所以函数体必须在当前文件可见，通常放在头文件中

4. Inline 的使用规则（考试重点）

（1）定义必须在调用之前

因为编译器需要看到函数体才能展开。

（2）适用于小函数

适合：

  • 简单计算函数
  • getter/setter
  • 短逻辑

（3）不适合的情况

一般不会被 inline：

  • 含循环（for / while）
  • 含 switch
  • 含异常处理
  • 递归函数
  • 代码过大

第一部分：知识点整理（普通文本）

1. const 的核心作用

  • const 用于区分“可变”和“不可变”
  • 提供：
    • 类型安全（比 #define 更强）
    • 编译期检查
    • 程序稳定性

    • 有类型
    • 编译器可检查错误

  • const 变量必须初始化
  • 一旦初始化，不能修改

示例：

  • const int x = 10; ✔
  • const int x; ✘（未初始化）
  • x = 20; ✘（不可修改）

数组：

  • const int a[] = {1,2,3}
    • 每个元素都不可修改

3. const 与指针（重点）

判定原则

👉 const 修饰“离它最近的对象”

3.1 指向常量的指针（pointer to const）

定义：

  • const int* p
  • int const* p

特点：

  • 可以改指针指向
  • 不能改指针指向的值

示例：

  • p = &x ✔
  • *p = 10 ✘

3.2 常量指针（const pointer）

定义：

  • int* const p

特点：

  • 不能改变指针指向
  • 可以修改值

示例：

  • p = &y ✘
  • *p = 10 ✔

3.3 指向常量的常量指针

定义：

  • const int* const p

特点：

  • 不能改指向
  • 不能改值

总结
在 C/C++ 中，权限本质指的是“是否可以通过某个指针修改数据”。所谓“权限缩小”，就是把原本“可以修改”的对象，通过 const 限制为“不可修改”，这种行为是安全的，因此允许，例如 const int *p 指向变量，本质是“我选择不通过 p 修改它”；
因此指向常量的指针以及指向常量的常量型指针可以指向变量

而“权限放大”则是试图通过指针获得本不具备的修改能力（如用 int * 指向 const int），这会破坏数据的只读性，因此被禁止。

所有指针与常量的规则，本质都遵循一句话：👉 只能减少修改权限，不能增加修改权限；同时 const 只限制“指针的使用方式”，不会改变变量本身的属性，因此“指向常量的指针”“常量指针”“双 const 指针”本质都是在约束“能不能改值”和“能不能改指向”，而是否允许绑定某个对象，取决于是否违反了“不能放大权限”的原则。

  • 能改”的指针 ❌ 不能指向 const
  • “不改”的指针 ✅ 可以指向任何

  • 写顺序 ≠ 执行顺序

6.5 const 成员函数

定义：

  • 函数后加 const

特点：

  • 不能修改成员变量

示例：

  • int get() const

错误：

  • return x++ ✘

6.6 const 对象

规则：

对象类型 可调用函数
const对象 只能调用 const函数
非const对象 可调用所有函数

6.7 mutable（非常重要考点）

作用：
👉 允许在 const 函数中修改变量

示例：

  • mutable int x;

意义：

  • 逻辑常量 vs 物理常量

7. 总结核心思想

  • const 是“类型系统的一部分”
  • 用于：
    • 限制修改
    • 提高安全
    • 强化接口设计

第一部分：知识点（普通文本）

一、构造函数（Constructor）

1. 基本概念

  • 构造函数是在对象创建时自动调用的函数，用于初始化对象。
  • 特点：
    • 函数名与类名相同
    • 没有返回值（连 void 都没有）
    • 在对象定义时自动调用

2. 调用机制

  • 对象创建时自动调用构造函数
  • 编译器隐式传入 this 指针（指向当前对象）

3. 带参数构造函数

  • 构造函数可以有参数
  • 可以用于初始化成员变量

示例思想：

  • 将传入参数赋值给成员变量
  • 实现对象初始化的灵活性

4. 构造函数重载

  • 一个类可以有多个构造函数（参数不同）
  • 编译器根据参数匹配调用对应构造函数

例如：

  • Student(int id)
  • Student(int year, int order)

二、默认构造函数（Default Constructor）

1. 定义

  • 可以无参数调用的构造函数

2. 形式

  • 显式定义：A() {}
  • 或使用默认参数实现：A(int x = 0) 就可以实现额外传几个就改几个。其余的仍为默认值

3. 注意事项

  • 如果定义了带参数构造函数，而没有默认构造函数：
    • 编译器不会自动生成默认构造函数
    • 会导致无法无参创建对象

4. 成员对象影响

  • 类成员对象会先调用其构造函数
  • 若成员类没有默认构造函数，会导致错误

三、析构函数（Destructor）

1. 基本概念

  • 用于对象销毁时释放资源

2. 特点

  • 函数名：~类名
  • 无参数
  • 不能重载
  • 无返回值

3. 调用时机

  • 对象生命周期结束时自动调用：
    • 作用域结束
    • 函数结束
    • delete（动态对象）

4. 调用顺序

  • 构造：先成员 → 后自身
  • 析构：先自身 → 后成员（逆序）

四、构造与析构的执行过程

1. 局部对象

  • 进入作用域：构造
  • 离开作用域：析构

2. 嵌套调用

  • 函数中创建对象：
    • 函数结束立即析构

3. 示例核心逻辑

  • 对象按栈顺序创建
  • 按逆序销毁（类似栈）

  1. 有没有 new？
    有 → 堆对象

  2. 在不在函数里？
    在 → 局部对象（栈）。作用域与函数的生命周期绑定

  3. 在类里面？
    是 → 成员对象。 和这个类的周期绑定。

  4. 在函数外？
    是 → 全局对象。和程序的运行周期绑定

  5. 有 static？
    是 → 静态对象
    对象什么时候死，不看它写在哪个文件，
    只看它在哪个作用域里被“创建”。

对于局部对象

真的是栈（物理结构）

对于其他对象

不是栈，但遵循“栈式规则”

五、资源管理思想（重要）

1. 初始化与清理

  • 构造函数：负责资源申请
  • 析构函数：负责资源释放

2. 典型资源

  • 动态内存（new）
  • 文件
  • 网络连接

六、数组初始化

1. 基本类型数组

  • int a[5] = {1,2,3,4,5}
  • int b[6] = {2} → 其余为 0
  • int c[] = {1,2,3}

2. 数组大小计算

  • sizeof(c) / sizeof(c[0])

七、对象数组初始化

1. 初始化方式

  • 直接初始化：
    • Date d[2] = {Date(…), Date(…)}
  • 先创建再赋值：
    • d[0] = Date(…)

2. 默认构造函数的重要性

  • 如果数组未完全初始化：
    • 剩余元素调用默认构造函数
    • 因为数组初始化 = 对每个元素逐个构造，有没有“初始化值” → 决定是否需要默认构造

八、代码设计思想总结

1. 封装 + 自动管理

  • 构造函数保证初始化
  • 析构函数保证清理

2. RAII 思想（核心）

  • Resource Acquisition Is Initialization
  • 资源与对象生命周期绑定

3. 安全性提升

  • 避免未初始化变量
  • 避免资源泄漏

第二部分：易错点（普通文本）

一、构造函数相关

  1. 写了带参构造函数但忘记写默认构造函数
    → 导致无法创建无参对象
  2. 误以为构造函数有返回值
    → 实际没有任何返回类型
  3. 构造函数不会自动执行逻辑以外代码
    → 必须手动初始化成员变量
  4. 构造函数重载冲突
    → 参数不明确可能导致二义性

二、默认构造函数陷阱

  1. 一旦定义了有参构造函数，默认构造函数不会自动生成
  2. 类成员对象没有默认构造函数
    → 当前类构造失败

三、析构函数相关

  1. 析构函数不能带参数、不能重载
  2. 忘记释放动态内存
    → 内存泄漏
  3. 错误理解析构顺序
    → 实际是“后构造先析构”

四、对象生命周期错误

  1. 误以为函数结束对象还存在 但注意是函数先结束然后再释放对象
    → 实际已析构
  2. 临时对象生命周期极短
    → 容易产生悬空引用

五、数组相关

  1. 对象数组必须有默认构造函数（除非完全初始化）
  2. 未初始化元素会调用默认构造函数
    → 若不存在则编译错误

六、资源管理错误

  1. 在构造函数中申请资源但析构函数未释放
  2. 使用裸指针但未管理生命周期

一、核心考点总结（不重不漏版）

1️⃣ Access Control（访问控制）——核心基础

⭐ 两个本质目的（必考理论题）

  1. 保护数据（防止乱用）

  2. 实现实现隐藏（implementation hiding）

👉 关键词：

  • interface vs implementation

  • 抽象数据类型（ADT）

⭐ 三种访问控制（必考）

关键字 含义
public 所有人可访问
private 仅类内成员函数可访问
protected 类内 + 子类

👉 易考点：

  • 外部访问限制

  • 继承时访问权限

⭐ 类设计风格（容易考选择/判断）

👉 本质：

  • 接口在前 or 在后都可以

  • 但推荐：public → interface

2️⃣ Friend（重中之重🔥）

⭐ Friend 本质（三句话必背）

普通成员函数有 3 个属性：

  1. 能访问 private

  2. 属于类作用域

  3. 必须通过对象调用（this）

👉 friend 只有第 1 个

⭐ Friend 特性（高频选择题）

特性 是否成立
可访问 private ✅
是类成员 ❌
有 this 指针 ❌
受 public/private 控制 ❌

⭐ Friend 类型（必考分类）

  1. 普通全局函数
  1. 另一个类的成员函数

👉 难点：

  • 必须先声明类 B
  1. 整个类作为 friend

👉 含义：

  • B 可以访问 A 的所有 private

⭐ Friend 性质（必考概念题）

  • ❗ 非对称（asymmetric）

  • ❗ 不可传递（non-transitive）

  • ❗ 不可继承（non-inherited）

3️⃣ Static Members（静态成员）

⭐ 核心知识点

👉 特点：

  • 所有对象共享

  • 必须类外定义：

⭐ 访问方式

⭐ 高频考点

  • static 属于类，不属于对象

  • friend 可以访问 static private

4️⃣ Implementation Hiding（实现隐藏）

⭐ 核心思想（大题必考）

👉 接口不变，内部可以改

⭐ Handle / Cheshire（高阶考点🔥）

👉 本质：

技术 含义
前向声明 隐藏结构定义
指针 隐藏实现
cpp 中定义 真正实现

⭐ 优点（必考）

  1. 减少编译依赖

  2. 隐藏实现细节

  3. 提高可维护性

⭐ 缺点

  • 指针复杂

  • 内存管理问题

二、易错清单（高频丢分点🔥）

❌ 1. 误以为 friend 是成员函数（最常错）

错误认知：

friend 写在类里 → 就是类成员

正确：

  • friend 不是成员函数
  • 只是“被授权访问 private”

  • ❌ 没有 this
  • ❌ 不能 obj.func()
  • ✅ 只能普通函数调用

❌ 2. 误以为 friend 受 public/private 控制

正确：

  • friend 不属于类
  • public/private 对它没有意义

❌ 5. friend 非对称（必考）

class A {

};

A 和 B 互相访问

❗正确：

  • ✅ B 能访问 A
  • ❌ A 不能访问 B

❌ 6. friend 不可传递（考试超爱考）

A friend B;

❗错误：

C 可以访问 A

❗正确：

  • ❌ 不成立

  • ❌ 不可以

概念 含义
