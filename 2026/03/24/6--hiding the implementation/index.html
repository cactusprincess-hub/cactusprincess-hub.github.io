一、核心考点总结（不重不漏版）

1️⃣ Access Control（访问控制）——核心基础

⭐ 两个本质目的（必考理论题）

  1. 保护数据（防止乱用）

  2. 实现实现隐藏（implementation hiding）

👉 关键词：

  • interface vs implementation

  • 抽象数据类型（ADT）

⭐ 三种访问控制（必考）

关键字 含义
public 所有人可访问
private 仅类内成员函数可访问
protected 类内 + 子类

👉 易考点：

  • 外部访问限制

  • 继承时访问权限

⭐ 类设计风格（容易考选择/判断）

👉 本质：

  • 接口在前 or 在后都可以

  • 但推荐：public → interface

2️⃣ Friend（重中之重🔥）

⭐ Friend 本质（三句话必背）

普通成员函数有 3 个属性：

  1. 能访问 private

  2. 属于类作用域

  3. 必须通过对象调用（this）

👉 friend 只有第 1 个

⭐ Friend 特性（高频选择题）

特性 是否成立
可访问 private ✅
是类成员 ❌
有 this 指针 ❌
受 public/private 控制 ❌

⭐ Friend 类型（必考分类）

  1. 普通全局函数
  1. 另一个类的成员函数

👉 难点：

  • 必须先声明类 B
  1. 整个类作为 friend

👉 含义：

  • B 可以访问 A 的所有 private

⭐ Friend 性质（必考概念题）

  • ❗ 非对称（asymmetric）

  • ❗ 不可传递（non-transitive）

  • ❗ 不可继承（non-inherited）

3️⃣ Static Members（静态成员）

⭐ 核心知识点

👉 特点：

  • 所有对象共享

  • 必须类外定义：

⭐ 访问方式

⭐ 高频考点

  • static 属于类，不属于对象

  • friend 可以访问 static private

4️⃣ Implementation Hiding（实现隐藏）

⭐ 核心思想（大题必考）

👉 接口不变，内部可以改

⭐ Handle / Cheshire（高阶考点🔥）

👉 本质：

技术 含义
前向声明 隐藏结构定义
指针 隐藏实现
cpp 中定义 真正实现

⭐ 优点（必考）

  1. 减少编译依赖

  2. 隐藏实现细节

  3. 提高可维护性

⭐ 缺点

  • 指针复杂

  • 内存管理问题

二、易错清单（高频丢分点🔥）

❌ 1. 误以为 friend 是成员函数（最常错）

错误认知：

friend 写在类里 → 就是类成员

正确：

  • friend 不是成员函数
  • 只是“被授权访问 private”

👉 直接后果：

  • ❌ 没有 this
  • ❌ 不能 obj.func()
  • ✅ 只能普通函数调用

❌ 2. 误以为 friend 受 public/private 控制

class A {
private:
friend void func(A&);
};

错误理解：

private → func 是私有函数

正确：

  • friend 不属于类
  • public/private 对它没有意义

❌ 3. 忘记 friend 仍然需要定义

class A {
friend void func(A&);
};

❗错误：

  • 以为已经完整

❗正确：

void func(A& a) {
// 必须定义
}

❌ 4. 成员函数作为 friend 的顺序问题（大坑🔥）

class Girl;

class Boy {
void show(Girl&);
};

class Girl {
friend void Boy::show(Girl&);
};

👉 易错点：

  • ❗必须先声明 Girl
  • ❗Boy 必须先有函数声明

否则编译错误

❌ 5. friend 非对称（必考）

class A {
friend class B;
};

❗错误理解：

A 和 B 互相访问

❗正确：

  • ✅ B 能访问 A
  • ❌ A 不能访问 B

❌ 6. friend 不可传递（考试超爱考）

A friend B;
B friend C;

❗错误：

C 可以访问 A

❗正确：

  • ❌ 不成立

❌ 7. friend 不可继承

class A {
friend class B;
};

class C : public B {};

❗错误：

C 也能访问 A

❗正确：

  • ❌ 不可以

❌ 8. static 成员误区

class A {
static int x;
};

❗常错：

  • ❌ 忘记类外定义
  • ❌ 认为属于对象

正确：

int A::x = 0;

❌ 9. static + friend 混淆

👉 friend 可以访问：

  • private 成员
  • static 成员

但：

👉 static 本质仍属于类

❌ 10. Cheshire / Handle（理解不到位）

class Handle {
struct Cheshire;
Cheshire* ptr;
};

❗错误理解：

只是 forward declaration

❗真正本质：

👉 隐藏实现（implementation hiding）

❌ 11. “访问权限 ≠ 可见性”

👉 很多人混淆：

概念 含义
可见性 编译器是否知道
访问权限 能不能用

👉 friend 是：

  • 可见 + 可访问

❌ 12. 误以为 private 不能被外部访问（绝对化错误）

❗错：

private 永远不能被外部访问

❗对：

  • friend 可以访问
  • 成员函数可以访问
