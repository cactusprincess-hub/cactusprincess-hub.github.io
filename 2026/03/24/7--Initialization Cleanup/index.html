第一部分：知识点（普通文本）

一、构造函数（Constructor）

1. 基本概念

  • 构造函数是在对象创建时自动调用的函数，用于初始化对象。
  • 特点：
    • 函数名与类名相同
    • 没有返回值（连 void 都没有）
    • 在对象定义时自动调用

2. 调用机制

  • 对象创建时自动调用构造函数
  • 编译器隐式传入 this 指针（指向当前对象）

3. 带参数构造函数

  • 构造函数可以有参数
  • 可以用于初始化成员变量

示例思想：

  • 将传入参数赋值给成员变量
  • 实现对象初始化的灵活性

4. 构造函数重载

  • 一个类可以有多个构造函数（参数不同）
  • 编译器根据参数匹配调用对应构造函数

例如：

  • Student(int id)
  • Student(int year, int order)

二、默认构造函数（Default Constructor）

1. 定义

  • 可以无参数调用的构造函数

2. 形式

  • 显式定义：A() {}
  • 或使用默认参数实现：A(int x = 0) 就可以实现额外传几个就改几个。其余的仍为默认值

3. 注意事项

  • 如果定义了带参数构造函数，而没有默认构造函数：
    • 编译器不会自动生成默认构造函数
    • 会导致无法无参创建对象

4. 成员对象影响

  • 类成员对象会先调用其构造函数
  • 若成员类没有默认构造函数，会导致错误

三、析构函数（Destructor）

1. 基本概念

  • 用于对象销毁时释放资源

2. 特点

  • 函数名：~类名
  • 无参数
  • 不能重载
  • 无返回值

3. 调用时机

  • 对象生命周期结束时自动调用：
    • 作用域结束
    • 函数结束
    • delete（动态对象）

4. 调用顺序

  • 构造：先成员 → 后自身
  • 析构：先自身 → 后成员（逆序）

四、构造与析构的执行过程

1. 局部对象

  • 进入作用域：构造
  • 离开作用域：析构

2. 嵌套调用

  • 函数中创建对象：
    • 函数结束立即析构

3. 示例核心逻辑

  • 对象按栈顺序创建
  • 按逆序销毁（类似栈）

  1. 有没有 new？
    有 → 堆对象

  2. 在不在函数里？
    在 → 局部对象（栈）。作用域与函数的生命周期绑定

  3. 在类里面？
    是 → 成员对象。 和这个类的周期绑定。

  4. 在函数外？
    是 → 全局对象。和程序的运行周期绑定

  5. 有 static？
    是 → 静态对象
    对象什么时候死，不看它写在哪个文件，
    只看它在哪个作用域里被“创建”。

对于局部对象

真的是栈（物理结构）

对于其他对象

不是栈，但遵循“栈式规则”

五、资源管理思想（重要）

1. 初始化与清理

  • 构造函数：负责资源申请
  • 析构函数：负责资源释放

2. 典型资源

  • 动态内存（new）
  • 文件
  • 网络连接

六、数组初始化

1. 基本类型数组

  • int a[5] = {1,2,3,4,5}
  • int b[6] = {2} → 其余为 0
  • int c[] = {1,2,3}

2. 数组大小计算

  • sizeof(c) / sizeof(c[0])

七、对象数组初始化

1. 初始化方式

  • 直接初始化：
    • Date d[2] = {Date(…), Date(…)}
  • 先创建再赋值：
    • d[0] = Date(…)

2. 默认构造函数的重要性

  • 如果数组未完全初始化：
    • 剩余元素调用默认构造函数
    • 因为数组初始化 = 对每个元素逐个构造，有没有“初始化值” → 决定是否需要默认构造

八、代码设计思想总结

1. 封装 + 自动管理

  • 构造函数保证初始化
  • 析构函数保证清理

2. RAII 思想（核心）

  • Resource Acquisition Is Initialization
  • 资源与对象生命周期绑定

3. 安全性提升

  • 避免未初始化变量
  • 避免资源泄漏

第二部分：易错点（普通文本）

一、构造函数相关

  1. 写了带参构造函数但忘记写默认构造函数
    → 导致无法创建无参对象
  2. 误以为构造函数有返回值
    → 实际没有任何返回类型
  3. 构造函数不会自动执行逻辑以外代码
    → 必须手动初始化成员变量
  4. 构造函数重载冲突
    → 参数不明确可能导致二义性

二、默认构造函数陷阱

  1. 一旦定义了有参构造函数，默认构造函数不会自动生成
  2. 类成员对象没有默认构造函数
    → 当前类构造失败

三、析构函数相关

  1. 析构函数不能带参数、不能重载
  2. 忘记释放动态内存
    → 内存泄漏
  3. 错误理解析构顺序
    → 实际是“后构造先析构”

四、对象生命周期错误

  1. 误以为函数结束对象还存在 但注意是函数先结束然后再释放对象
    → 实际已析构
  2. 临时对象生命周期极短
    → 容易产生悬空引用

五、数组相关

  1. 对象数组必须有默认构造函数（除非完全初始化）
  2. 未初始化元素会调用默认构造函数
    → 若不存在则编译错误

六、资源管理错误

  1. 在构造函数中申请资源但析构函数未释放
  2. 使用裸指针但未管理生命周期
