第一部分：知识点整理（普通文本）

1. 初始化与清理的必要性

  • 封装和访问控制提高了库的易用性，但安全性仍需编译器在初始化和清理方面提供支持 。

  • C++ 编译器在对象创建时自动调用构造函数，在对象销毁时自动调用析构函数，解决了 C 语言中容易被遗漏的对象状态初始化和资源释放问题 。

2. 构造函数（Constructor）原理与特性

  • 核心定义：构造函数名必须与类名完全相同 ，且没有返回类型（连 void 都没有） 。

  • 自动调用：当对象定义时（即分配内存时），编译器会自动调用构造函数 。

  • Secret Argument (this 指针)：如同普通成员函数，构造函数的第一个隐藏参数是 this 指针，它指向正在被初始化的对象内存地址 。

  • 重载与参数：构造函数可以拥有参数，并支持函数重载，允许以多种方式初始化对象 。

  • 默认构造函数：指可以不带参数调用的构造函数 。如果类中定义了带参数的构造函数，编译器将不再自动生成默认构造函数 。

3. 析构函数（Destructor）原理与特性

  • 核心定义：名称为类名前加波浪号（~） ，同样没有返回类型 。

  • 唯一性与限制：析构函数不能有任何参数，因此不能被重载 。

  • 调用时机：当对象超出其作用域（如函数结束或关闭大括号）被销毁时，系统自动调用析构函数以清理资源 。

4. 组合类（Composition）的执行顺序

  • 构造顺序：如果类 B 中包含类 A 的对象作为成员，在创建 B 对象时，先调用成员对象 A 的构造函数，再执行 B 的构造函数体 。

  • 析构顺序：析构顺序与构造顺序严格相反。先执行 B 的析构函数，再执行成员对象 A 的析构函数 。

5. 数组初始化（Array Initialization）

  • 基本类型数组：可以进行部分初始化（例如 int b[6] = {2};），未显式赋初值的元素会被赋予默认值（如 0） 。

  • 对象数组：初始化对象数组时，可以通过大括号调用特定的构造函数 。如果提供的初始化列表短于数组长度，剩余的元素将自动调用默认构造函数进行初始化 。

  • 大小计算：数组大小可以通过 sizeof(array) / sizeof(array[0]) 计算得出 。

第二部分：易错点总结（普通文本）

  • 构造函数返回类型误区：新手常习惯给构造函数写上 void。请记住，构造函数绝对没有返回类型 。

  • 默认构造函数消失陷阱：一旦你手动定义了一个带参数的构造函数（例如 Date(int y)），编译器就不会再帮你生成默认构造函数了。此时如果尝试 Date d; 就会报错 。

  • 析构函数重载误区：析构函数没有参数，所以无法重载。每个类只能有一个析构函数 。

  • 执行顺序混淆：在组合类中，构造是“自底向上”（先成员后主体），而析构是“自顶向下”（先主体后成员） 。

  • 对象数组初始化遗漏：在定义对象数组且没有提供完整初始化列表时，类必须拥有可访问的默认构造函数，否则编译器会因为无法初始化剩余元素而报错 。

  • 作用域理解：局部对象的析构函数在遇到右大括号 } 时调用。注意：函数内部定义的局部对象在函数返回前就会被析构 。
