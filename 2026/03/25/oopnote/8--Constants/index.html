第一部分：知识点整理（普通文本）

1. const 的核心作用

  • const 用于区分“可变”和“不可变”
  • 提供：
    • 类型安全（比 #define 更强）
    • 编译期检查
    • 程序稳定性

与 #define 的区别

  • #define：纯文本替换，无类型检查
  • const：
    • 有类型
    • 编译器可检查错误
    • 更安全

2. const 基本规则

  • const 变量必须初始化
  • 一旦初始化，不能修改

示例：

  • const int x = 10; ✔
  • const int x; ✘（未初始化）
  • x = 20; ✘（不可修改）

数组：

  • const int a[] = {1,2,3}
    • 每个元素都不可修改

3. const 与指针（重点）

判定原则

👉 const 修饰“离它最近的对象”

3.1 指向常量的指针（pointer to const）

定义：

  • const int* p
  • int const* p

特点：

  • 可以改指针指向
  • 不能改指针指向的值

示例：

  • p = &x ✔
  • *p = 10 ✘

3.2 常量指针（const pointer）

定义：

  • int* const p

特点：

  • 不能改变指针指向
  • 可以修改值

示例：

  • p = &y ✘
  • *p = 10 ✔

3.3 指向常量的常量指针

定义：

  • const int* const p

特点：

  • 不能改指向
  • 不能改值

总结
在 C/C++ 中，权限本质指的是“是否可以通过某个指针修改数据”。所谓“权限缩小”，就是把原本“可以修改”的对象，通过 const 限制为“不可修改”，这种行为是安全的，因此允许，例如 const int *p 指向变量，本质是“我选择不通过 p 修改它”；
因此指向常量的指针以及指向常量的常量型指针可以指向变量

而“权限放大”则是试图通过指针获得本不具备的修改能力（如用 int * 指向 const int），这会破坏数据的只读性，因此被禁止。

所有指针与常量的规则，本质都遵循一句话：👉 只能减少修改权限，不能增加修改权限；同时 const 只限制“指针的使用方式”，不会改变变量本身的属性，因此“指向常量的指针”“常量指针”“双 const 指针”本质都是在约束“能不能改值”和“能不能改指向”，而是否允许绑定某个对象，取决于是否违反了“不能放大权限”的原则。

  • 能改”的指针 ❌ 不能指向 const
  • “不改”的指针 ✅ 可以指向任何

4. const 与函数

4.1 参数中的 const

目的：
👉 防止函数修改外部数据

示例：

  • void f(const int* p)
    • *p 不可修改

4.2 返回值中的 const

目的：
👉 防止调用者修改返回对象

示例：

  • const char* func()

int* const w();

int main() {
int* p = w();
p = nullptr;
}
合法 因为虽然p被复制了一个限制地址的指针 但本质是复制 失效。所以可以被重新修改地址

  • int* const w(); 里的 const 限制的只是函数内部的那份指针
  • 函数返回时，你拿到的是拷贝，所以外部的变量 p 不再受原来的 const 限制
  • 也就是 “指针本身的 const 在返回值上失效”

4.3 规则总结

  • const 参数：保护输入
  • const 返回：保护输出

5. 临时对象（Temporaries）

  • 编译器生成的临时对象默认是 const
    因为临时对象生命周期很短，C++不希望你去修改一个马上就要消失的东西
    意义：

  • 防止对临时对象进行非法修改

  • 提高安全性

  • 临时对象 = 没有变量名接收的对象表达式结果

6. 类中的 const（重点大题区）

6.1 static 成员变量

特点：

  • 所有对象共享
  • 必须在类外初始化

格式：

  • int Class::var = value;

6.2 const 成员变量

特点：

  • 必须初始化
  • 只能在构造函数初始化列表中初始化

原因：

  • const 不能先声明再赋值

6.3 初始化列表

作用：

  • 初始化 const 成员
  • 初始化引用成员

示例：

  • A::A(int i) : a(i) {}

6.4 初始化顺序（超级重要）

👉 按“声明顺序”，不是初始化列表顺序

错误来源：

  • 写顺序 ≠ 执行顺序

6.5 const 成员函数

定义：

  • 函数后加 const

特点：

  • 不能修改成员变量

示例：

  • int get() const

错误：

  • return x++ ✘

6.6 const 对象

规则：

对象类型 可调用函数
const对象 只能调用 const函数
非const对象 可调用所有函数

6.7 mutable（非常重要考点）

作用：
👉 允许在 const 函数中修改变量

示例：

  • mutable int x;

意义：

  • 逻辑常量 vs 物理常量

7. 总结核心思想

  • const 是“类型系统的一部分”
  • 用于：
    • 限制修改
    • 提高安全
    • 强化接口设计

第二部分：易错点总结（普通文本）

1. const 未初始化

  • const int x; ✘
    👉 必须初始化

2. const 指针混淆（最常错）

常见误解：

  • const int* p ≠ int* const p

记忆方法：
👉 “看 const 靠谁近”

3. 函数参数错误

  • 不能把 const 指针传给非 const 参数

示例：

  • void f(int* p)
  • const int* cp
  • f(cp) ✘

4. 返回值错误

  • const 返回值不能赋给非 const 指针

5. const 成员变量初始化错误

错误写法：

  • 在构造函数体内赋值

正确：

  • 用初始化列表

6. 初始化顺序错误（高频考点）

  • 顺序由“声明顺序”决定
  • 与初始化列表顺序无关

7. const 成员函数违规修改数据

  • 修改成员变量会报错

8. const 对象调用非 const 函数

  • 会编译错误

9. mutable 误用

  • 只用于“逻辑不变但需要修改”的变量
  • 不要滥用

10. 临时对象修改错误

  • 临时对象是 const
  • 不能修改
