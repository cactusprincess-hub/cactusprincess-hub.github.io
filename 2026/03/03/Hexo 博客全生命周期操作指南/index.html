📗 第二部分：核心知识库（术语解构）

为了让你“知其然更知其所以然”，以后面试或跟同学聊技术也能信手拈来。

1. Homebrew：Mac 的“万能管家”

  • 定义：它是 macOS 上的 包管理器 (Package Manager)。

  • 直白点说：它是给程序员用的“App Store”。在 Mac 上装开发工具，不用去官网下安装包，直接 brew install 搞定，且方便后续统一升级。

2. Node.js：博客的“发动机”

  • 定义：一个基于 Chrome V8 引擎的 JavaScript 运行时 (Runtime)。

  • 为什么需要它：Hexo 是用 JavaScript 编写的。Node.js 就像是运行 Hexo 这台机器的电力系统，没有它，Hexo 无法在你的 Mac 上运行。

3. Hexo：静态网站“代工厂”

  • 定义：一个 静态网站生成器 (Static Site Generator)。

  • 工作原理：

    • 输入：你写的 Markdown (源文件)。

    • 模具：Icarus 主题 (HTML/CSS 模板)。

    • 输出：纯网页代码 (HTML/JS/CSS)。

  • 优点：生成的是纯静态页面，不涉及后端数据库，所以访问极快且完全免费。

4. Git & GitHub：仓库与店面

  • Git：版本控制系统。记录你博客每一次的改动，就像游戏的“存档”。

  • GitHub：全球最大的代码托管平台。

  • GitHub Pages：GitHub 提供的静态网页托管服务。它分配给你一个 xxx.github.io 的域名，并免费帮你运行刚才生成的那些网页。

5. SSH (Secure Shell)：加密握手

  • 定义：一种网络协议，用于计算机之间的加密登录。

  • 为什么要用：

    • HTTPS 方式（用户名+Token）：像每次进门都要掏身份证、输密码，不仅累且容易超时报错。

    • SSH 方式：像“面部识别”。你把公钥给了 GitHub，你每次推送代码，它们会自动比对你的私钥，确认是你本人后秒放行。

📙 第三部分：避坑 & 小贴士

  1. 缓存是万恶之源：如果你改了配置却没生效，永远记得先 hexo clean。

  2. YAML 语法：.yml 文件对缩进极其敏感。冒号后面必须有一个空格！

    • 错误：title:我的博客

    • 正确：title: 我的博客

  3. 图片管理：如果你想在文章里插图，建议把图片放在 source/img/ 下，然后在 Markdown 里引用。

  4. 备份源码：GitHub 上的那个仓库是“成品”。你的 myblog 文件夹本身才是真正的宝贝。记得定期拷贝到移动硬盘，或者再建一个 GitHub Private 仓库，把整个文件夹（除了 node_modules）存上去。
