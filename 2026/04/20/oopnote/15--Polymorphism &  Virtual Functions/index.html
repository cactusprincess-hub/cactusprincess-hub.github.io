二、本章核心规则

  • 面向对象的基本特征包括：封装、继承、多态；动态多态主要靠 virtual functions 实现。

  • 派生类对象可以通过指针或引用当成基类对象来处理，这叫 upcasting。

  • 如果基类函数声明为 virtual，那么它在所有派生类中都保持虚函数属性。

  • 继承中对虚函数的重新定义叫 overriding。

  • 同名不同参的同一类函数是 overloading；普通成员函数在继承里被重新定义，常叫 redefining。

  • 使用虚函数实现多态时，必须通过基类指针或引用调用；直接拿对象本身调用时，编译器知道精确类型，通常是早绑定。

  • 作用域解析运算符 :: 会绕过虚函数机制。

  • 虚函数必须是非静态成员函数。

  • 构造函数不能是 virtual。

  • 析构函数通常应该是 virtual；如果基类析构函数是 virtual，派生类析构函数会自动成为 virtual。

  • 抽象类至少含有一个纯虚函数；纯虚函数写成 = 0。

  • 发生对象按值传递时，可能出现 object slicing（对象切片）。

  • 除了赋值运算符，一般运算符也可以像普通成员函数一样做虚函数。

经验句：
这章就背四个词：upcasting、virtual、override、slicing。

三、本章常考题型

1. 这是早绑定还是晚绑定

看调用对象是不是通过指针/引用传入。

2. 虚函数是否真正被覆盖

看函数签名是否完全一致，名字、参数、返回类型都要对。

3. 作用域解析后会不会还走虚函数

不会，A::f() 会绕过动态绑定。

4. 抽象类能不能实例化

不能，只能拿来做基类或用引用/指针。

5. 基类指针 delete 派生类对象时会发生什么

如果析构函数不是 virtual，派生类资源可能不会被正确释放。

6. 是否发生对象切片

看函数参数是不是按值传递。按值传递非常容易切片。

5. overloading / redefining / overriding

PDF 明确区分了三件事：

  • Overloading：同一作用域内同名不同参
  • Redefining：继承中普通成员函数的重新定义,会屏蔽基类的接口。
  • Overriding：继承中虚成员函数的重写，本身派生类对象可以被当成基类对象来处理，前提是通过指针或引用，这个时候只能调用父类接口
    • 但是加入virtual可以调用子类，父类引用指向谁，就调用谁的函数，此时upcating仍然存在只不过
      情况 1：普通函数（无 virtual）
      → 看指针 / 引用的类型，不看真实对象
      父类指针 / 引用 → 永远调父类的函数
      情况 2：虚函数（有 virtual）
      → 看真实对象是谁，传入谁就调谁
      传子类对象 → 调子类函数
      传父类对象 → 调父类函数

经验句：
同作用域叫重载，继承里普通函数叫重定义，继承里虚函数叫重写。指针和引用是多态的条件
目的
基类定义统一接口（play() 虚函数）
所有子类重写这个接口
通用函数（tune()）只通过基类接口调用
用向上转型 + 指针 / 引用传入任意子类
虚函数自动匹配子类实现 → 多态
这就是：
一套代码，兼容所有子类，加新功能不改老代码

11. VTABLE / VPTR：虚函数是怎么实现的

PDF 解释了编译器内部机制：

万能做题四步法（按顺序，一步都别跳）

步骤 1：先看「调用方式」（决定上限）

先看你是用什么调用函数的，3 种情况：

  1. 子类普通对象 Derived d; d.f();

    → 只看子类本身 + 继承规则（重点看隐藏）

  2. 父类指针 / 父类引用 Base* p = &d; Base& r = d;

    → 只认父类的接口，子类新增的函数永远看不见

    → 重写的虚函数会多态调子类

  3. 按值传递 Base b = d;

    → 对象切片，彻底变成父类，只调用父类

步骤 2：看函数「在哪同名」

  • 都在同一个类 → 直接判定：重载
  • 一个父类、一个子类 → 进入步骤 3

步骤 3：对「函数签名」判重写 / 重定义

父类和子类都有同名函数：

  1. 签名完全一样 + 父类 virtual

    → 重写 (Override)

  2. 签名不一样（参数不同 /const 不同）

    → 重定义 / 名字隐藏

步骤 4：定最终调用结果

  1. 子类对象 + 重写 → 调子类
  2. 子类对象 + 重定义 → 父类同名全隐藏，只能调子类自己的
  3. 父类指针 / 引用 + 重写 → 多态，运行时调子类
  4. 父类指针 / 引用 + 子类新增函数 → 报错（父类没有）
  5. 按值传递 → 永远调父类

17. 虚函数与构造函数

PDF 说明：对象创建时需要初始化 VPTR，所以构造函数会负责把 VPTR 设到正确的 VTABLE 上；但构造函数本身不能是 virtual。

经验句：
构造阶段对象还没“活完整”，所以构造函数不能虚。

19. 析构顺序要和构造顺序配套记

PDF 的输出表明：A *a = new B(15); delete a; 时，正确顺序应该先执行 B::~B()，再执行 A::~A()。如果没有 virtual，派生类资源就可能清不掉。

20. 虚函数与运算符重载

PDF 最后补了一句：运算符重载也可以像其他成员函数一样设成 virtual。也就是说，运算符本身并不排斥虚函数机制。

经验句：
运算符也只是成员函数的一种，照样能虚。

五、本章重点回忆版

  • 多态靠 virtual 实现，向上转型是通过基类指针/引用使用派生类对象。

  • virtual 一旦在基类声明，派生类自动继承虚属性。

  • override 要求签名一致；redefining 是普通成员函数重定义；overloading 是同作用域同名不同参。

  • :: 会绕开虚机制；直接对象调用通常是早绑定。

  • 抽象类至少一个纯虚函数，不能实例化。

  • 按值传参容易切片，引用/指针才能保留多态。

  • 析构函数常常必须 virtual，尤其是基类指针 delete 派生类对象时。

  • 虚函数背后是 VTABLE/VPTR 机制。
