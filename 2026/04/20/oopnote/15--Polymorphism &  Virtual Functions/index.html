二、本章核心规则

  • 面向对象的基本特征包括：封装、继承、多态；动态多态主要靠 virtual functions 实现。

  • 派生类对象可以通过指针或引用当成基类对象来处理，这叫 upcasting。

  • 如果基类函数声明为 virtual，那么它在所有派生类中都保持虚函数属性。

  • 继承中对虚函数的重新定义叫 overriding。

  • 同名不同参的同一类函数是 overloading；普通成员函数在继承里被重新定义，常叫 redefining。

  • 使用虚函数实现多态时，必须通过基类指针或引用调用；直接拿对象本身调用时，编译器知道精确类型，通常是早绑定。

  • 作用域解析运算符 :: 会绕过虚函数机制。

  • 虚函数必须是非静态成员函数。

  • 构造函数不能是 virtual。

  • 析构函数通常应该是 virtual；如果基类析构函数是 virtual，派生类析构函数会自动成为 virtual。

  • 抽象类至少含有一个纯虚函数；纯虚函数写成 = 0。

  • 发生对象按值传递时，可能出现 object slicing（对象切片）。

  • 除了赋值运算符，一般运算符也可以像普通成员函数一样做虚函数。

经验句：
这章就背四个词：upcasting、virtual、override、slicing。

三、本章常考题型

1. 这是早绑定还是晚绑定

看调用对象是不是通过指针/引用传入。

2. 虚函数是否真正被覆盖

看函数签名是否完全一致，名字、参数、返回类型都要对。

3. 作用域解析后会不会还走虚函数

不会，A::f() 会绕过动态绑定。

4. 抽象类能不能实例化

不能，只能拿来做基类或用引用/指针。

5. 基类指针 delete 派生类对象时会发生什么

如果析构函数不是 virtual，派生类资源可能不会被正确释放。

6. 是否发生对象切片

看函数参数是不是按值传递。按值传递非常容易切片。

11. VTABLE / VPTR：虚函数是怎么实现的

PDF 解释了编译器内部机制：
每个含虚函数的类会有一个 VTABLE，里面放虚函数地址；每个对象里还会偷偷放一个 VPTR，指向对应的 VTABLE。对象构造时会设置好 VPTR，因此虚调用可以在运行时决定到底调用哪个版本。

经验句：

PDF 最后补了一句：运算符重载也可以像其他成员函数一样设成 virtual。也就是说，运算符本身并不排斥虚函数机制。

经验句：

五、本章重点回忆版

  • 多态靠 virtual 实现，向上转型是通过基类指针/引用使用派生类对象。

  • virtual 一旦在基类声明，派生类自动继承虚属性。

  • override 要求签名一致；redefining 是普通成员函数重定义；overloading 是同作用域同名不同参。

  • :: 会绕开虚机制；直接对象调用通常是早绑定。

  • 抽象类至少一个纯虚函数，不能实例化。

  • 按值传参容易切片，引用/指针才能保留多态。

  • 析构函数常常必须 virtual，尤其是基类指针 delete 派生类对象时。

  • 虚函数背后是 VTABLE/VPTR 机制。
