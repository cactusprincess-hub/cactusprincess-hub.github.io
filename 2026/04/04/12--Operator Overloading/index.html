第一部分：知识点（普通文本）

1. 函数重载（Function Overloading）

函数重载指的是：多个函数可以使用相同的名字，但它们通过“参数个数”和“参数类型”来区分。C++ 在调用时会根据实参列表选择最匹配的函数。课件强调，同名函数应当承担相近的功能，否则会降低代码可读性。

2. 为什么需要运算符重载

运算符重载本质上也是一种函数调用，只是把原本像 Add 这样的成员函数，改写成更自然的运算形式，比如 c = c1 + c2。这样做的目的主要是让自定义类的代码更自然、更接近内置类型的写法，也更容易阅读。

3. 运算符重载的基本规则

  • 不能创造新的运算符 token。

  • 不能改变运算符作用于内置类型时的语义。

  • 不能改变操作数个数、优先级和结合性。

  • 至少有一个操作数必须是用户自定义类型，或者重载函数必须是成员函数。

也就是说，运算符重载不是“重新定义语言”，而是在语言允许的框架里增强自定义类型的表达能力。

7. 成员函数和友元函数的差别

成员函数形式有隐含 this，适合左操作数就是当前对象的情况。友元函数没有 this，因此更适合左右两边都需要对称参与运算的场景，比如 complex + complex 或 1.5 + complex。课件中专门指出：如果第一个操作数不是类对象，通常应使用友元函数。

8. 常见可重载运算符

课件列出了很多可重载运算符，包括：

  • 一元：+ - & ! ~ ++ --

  • 二元：= + - * / % += -= *= /= %= & | ^ ^= &= |= == != > < >= <= || && << >> >>= <<=

  • 特殊类相关：[] -> ++ -- = 转换 << >>

9. 不能重载的运算符

以下运算符不能重载：

  • . 成员访问

  • .* 通过指针访问成员

  • :: 作用域解析

  • ?: 条件运算符

  • sizeof

  • typeid

同时，课件还强调：

  • 不能改变运算符优先级

  • 不能创建新的运算符

  • 不能改变操作数个数规则

10. 返回值与参数形式的设计原则

如果参数只是读取不修改，通常应传 const reference，这样更高效也更安全。返回值类型要根据运算符语义决定：

  • operator+ 通常返回值对象

  • 赋值类运算符如 operator=、operator+= 应返回引用，通常是 *this 的非 const 引用，方便链式调用。

11. 临时对象与返回优化

表达式如 a + b 的结果会成为临时对象。课件指出，如果返回值写成 const 值对象，那么该临时结果通常只允许调用 const 成员函数。另一个重点是返回优化：编译器可能省略某些拷贝，但题目中分析顺序时仍应理解“构造、拷贝、析构”的逻辑流程。

12. 赋值运算符 operator=

  • X b = a; 是拷贝构造

  • b = a; 是赋值运算符

13. 拷贝构造与赋值的区别

拷贝构造是在“新对象创建时”使用，赋值运算符是在“对象已存在、重新赋值”时使用。课件通过 Location A(1, 2); Location B = A; 和 B = A; 说明了这两个动作触发的是不同函数。

14. 含指针成员的类必须特别处理拷贝

如果类中有指针成员，而你使用默认拷贝构造和默认赋值运算符，通常会发生浅拷贝：多个对象指向同一块堆内存。这样会导致：

  • 重复释放

  • 悬空指针

  • 内存泄漏

因此，含资源管理的类通常需要自己定义：

  • 拷贝构造函数

  • 赋值运算符

  • 析构函数

这就是典型的“三/五法则”思路。

15. 自动类型转换：构造函数转换

构造函数可以支持“从基础类型到类类型”的隐式转换。例如 complex c = 1.5; 可以通过构造函数把 double 转为 complex。课件中说明了：当重载 operator+ 时，c1 + 1.5 可以通过把 1.5 自动转换为 complex(1.5) 来完成。

第二部分：易错点总结（普通文本）

1. 把函数重载和运算符重载混为一谈

函数重载是同名不同参；运算符重载是给已有运算符绑定自定义类语义。它们相关但不是一回事。

2. 误以为运算符重载能改变语法规则

不能改变优先级、结合性、操作数个数，也不能创造新运算符。重载只是“换一种函数调用方式”。

3. 忘记“至少有一个操作数必须是用户定义类型”

如果两个操作数都是内置类型，运算符不能被你改写。课件明确指出这一限制。

4. 成员函数和友元函数的参数形式搞错

成员函数有隐含 this，所以二元运算符通常只写一个参数；友元函数没有 this，所以二元运算符要写两个参数。

5. 把前缀和后缀 ++/-- 写混

后缀版本必须多一个 int 占位参数：

这个 int 不是用来计算的，只是区分前后缀。

6. 误以为 operator-> 可以随便返回任何东西

-> 必须是成员函数，并且通常返回一个指针，才能继续完成成员访问。

7. [] 不是普通运算符，写法必须是成员函数

课件明确要求：下标运算符 operator[] 必须重载为成员函数。

8. 赋值运算符和拷贝构造混淆

B = A 是赋值，不是拷贝构造；B = A 发生在对象已存在时。B = A 和 Location B = A 不是同一个东西。

9. 含指针成员的类默认拷贝会出大问题

默认浅拷贝会让两个对象共享同一块堆内存，导致重复释放或资源丢失。课件用 A 类完整演示了这个问题。

10. 赋值运算符忘记处理自赋值

if (this == &r) return *this; 很关键。否则 a = a 可能先删掉自己的资源，再尝试拷贝自己，出错。

11. operator+ 返回引用通常不对

+ 通常返回新值对象；若返回引用，容易引用到局部对象或破坏语义。课件强调不同运算符应匹配合理返回类型。

12. 以为构造函数和转换运算符都能双向任意转换

构造函数通常支持“基础类型 → 类类型”；转换运算符支持“类类型 → 目标类型”。两者方向不同。

13. 忽略 operator<< / operator>> 的返回值

它们应返回流对象引用，否则无法链式输入输出，也不符合流操作习惯。
