一、章节总结

SQL（Structured Query Language）是介于关系代数与关系演算之间的关系数据库标准语言，集查询、数据操纵、数据定义和数据控制于一体。课件强调它是通用、功能很强、并且最适合关系数据库系统的标准语言；版本上提到 SQL-89、SQL-92、SQL-99（加入面向对象概念）和 SQL2003。

SQL 的突出特点有三点：第一，综合统一，把 DDL、DML、DCL 融合在同一种语言里；第二，高度非过程化，用户只需说“做什么”，不必说明“怎么做”；第三，面向集合，查询、插入、删除、修改的对象都是集合而不是单条记录。它还支持独立使用，也支持嵌入高级语言，语法结构基本一致，因此既方便交互，也方便程序调用。

从系统结构看，SQL 支持三级模式结构：基本表对应模式层，视图对应外模式，存储文件对应内模式。基本表是独立存在的真实表，一个关系对应一个基本表；视图则是从一个或多个基本表导出的虚表，本身不实际存储数据，其定义保存在数据字典中，但可以像表一样查询，并在一定条件下更新。

SQL 的数据定义功能主要包括模式、表、视图和索引。SQL2 还增加了 SQL 数据库模式的定义。模式由模式名、权限标识符和模式元素描述符组成；同一应用的表、视图、索引可以放在同一模式中。模式可以先建空壳，再逐步补充内部对象；删除模式时可用 CASCADE 级联删除全部对象，或用 RESTRICT 限制删除。

表的定义使用 CREATE TABLE，列名后面跟数据类型，还可以写列级约束和表级约束。课件用 Student、Course、SC 三个表作为标准示例：Student 表中 Sno 用 NOT NULL UNIQUE 和主键约束，Ssex 用 CHECK 限定为“男/女”；SC 表中 Sno、Cno 作为联合主键，Grade 用 CHECK 限定在 0 到 100，并通过 FOREIGN KEY 分别引用 Student 和 Course。课件还提到 SQL2 可以用 CREATE DOMAIN 定义域，便于多个列共享同一类型定义。

表的修改使用 ALTER TABLE，可以新增列、删除列或修改列定义。新增列后，旧记录中该列值自动为空值；修改列长度或类型时要小心，因为可能破坏已有数据。删除表用 DROP TABLE；RESTRICT 会拒绝删除被外键、视图等依赖的表，CASCADE 则会联动删除相关依赖对象。

索引是一种用于提高查询速度的数据结构。课件强调索引是大型关系数据库实现中的核心问题之一：可以在一个表上建一个或多个索引，也可以不建；DBA 或表的属主决定是否建立，而系统在查询时自动决定是否使用索引。CREATE INDEX 可以建普通索引，也可以建 UNIQUE 索引或 CLUSTER 聚簇索引；DROP INDEX 用于删除索引。聚簇索引会决定表中数据的物理顺序，因此一个表只能有一个聚簇索引。

SQL 的数据操纵主要包括查询、插入、修改和删除。本章主要展开的是查询：单表查询、连接查询、嵌套查询和集合查询。SQL 的统一 SELECT 语句一般结构包含 SELECT、FROM、WHERE、GROUP BY、HAVING、ORDER BY 等子句，分别控制输出列、查询对象、筛选条件、分组、分组过滤和排序。

单表查询部分重点讲了比较大小、范围查询、集合查询、字符串匹配、空值查询、多重条件、排序、聚集函数和分组。比如 BETWEEN 用于范围，IN 用于集合匹配，LIKE 用于模式匹配，IS NULL 不能用 = NULL 代替，ORDER BY 可指定 ASC/DESC，聚集函数包括 COUNT、SUM、AVG、MAX、MIN，GROUP BY 用于分组，HAVING 用于筛选组。

连接查询部分包括广义笛卡尔积、等值连接、自然连接、非等值连接、自身连接、外连接和复合条件连接。课件用 Student、SC、Course 作为标准示例，说明等值连接如何把学生信息和选课信息拼接，自然连接如何去掉重复属性，自身连接如何通过别名处理同一表的两次引用，外连接如何保留未匹配元组，复合条件连接如何把连接条件与其他筛选条件结合。

嵌套查询部分讲了不相关子查询与相关子查询，常见引出谓词包括 IN、比较运算符、ANY、ALL、EXISTS、NOT EXISTS。课件强调：IN 型子查询常用于“属于某个集合”的判断，ANY/ALL 常用于“某个值比集合中某些值大/小”的比较，EXISTS/NOT EXISTS 只关心子查询是否有结果，不关心具体值。全称量词和逻辑蕴涵可以用 NOT EXISTS 进行等价表达，这是 SQL 中处理“所有”“全部满足”类问题的标准套路。

集合查询部分讲了 UNION、INTERSECT、EXCEPT 以及集合结果排序。课件明确指出，ORDER BY 只能出现在整个集合操作的最后，不能写在 UNION/INTERSECT/EXCEPT 的中间结果上；对集合操作结果排序时，可以用序号指定排序列。

本章目录中还包括 SQL 中的视图、数据控制和嵌入式 SQL。结合前面的系统结构，视图属于外模式的重要组成部分；数据控制属于 SQL 的统一功能之一；嵌入式 SQL 则对应“SQL 作为高级语言中的子语言使用”的那条路线。

二、易错点总结

1. 把基本表和视图混为一谈

基本表是真实存储的独立表，视图是从基本表导出的虚表，不实际存储数据。很多人会把视图当成普通表直接理解，这是错的；视图本质上是“逻辑定义”，不是“数据实体”。

2. 把模式、表、数据库模式的层次弄混

SQL 模式不是一张表，而是一个命名空间，里面可以放表、视图、索引等对象。CREATE SCHEMA 只是建立模式框架，真正的数据对象还要继续定义。

3. 忘记模式名可能省略，但会隐含为用户名

课件明确说过：如果 CREATE SCHEMA 里没有显式写模式名，则隐含为用户名。这个细节很容易在考试里被忽略。

4. 把列级约束和表级约束混在一起

CREATE TABLE 里既可以写列级约束，也可以写表级约束。像 PRIMARY KEY、FOREIGN KEY、CHECK 都可能出现在不同层次，考试里常考“这个约束该写在哪里”。

5. 忽略 CHECK 的实际作用

课件中 Grade BETWEEN 0 AND 100、Ssex IN (‘男’,’女’) 都是典型的 CHECK 约束。很多同学会只记主键和外键，忘了 CHECK 也是非常常见的完整性约束表达方式。

6. 用 ALTER TABLE 增列后，以为旧数据会自动补合理值

新增列后，原有记录中新列一律为空值，不会自动生成默认业务值。修改列类型或长度则可能破坏已有数据，这个风险常常被忽略。

7. DROP TABLE 不考虑依赖关系

RESTRICT 和 CASCADE 的区别非常重要。若表被外键、视图、触发器、存储过程等依赖，RESTRICT 会拒绝删除；CASCADE 则会连带删除相关对象。考试很喜欢考“能不能删、删了会影响什么”。

8. 索引只记“快”，不记“代价”

索引能加快检索和连接，但会占额外空间，还会增加插入、更新、删除时的维护成本。课件明确强调要权衡数据性质和查询性质，不是所有列都适合建索引。

9. UNIQUE 索引不是“想建就能建”

如果该列已有重复值，就不能建 UNIQUE 索引。很多同学只记“唯一索引更快”，却忘了它的前提是数据本身必须唯一。

10. 把 SQL 结果的重复元组理解错

关系理论里元组不重复，但课件指出商用数据库为了效率，允许 SQL 结果中出现重复元组，所以 SELECT 默认可能返回重复行，需要用 DISTINCT 去重。这个点非常容易和“关系是集合”混淆。

11. DISTINCT 的作用范围弄错

DISTINCT 作用于所有目标列，不是单独作用于某一个列。像“SELECT DISTINCT Cno, DISTINCT Grade”这种写法是错的。

12. SELECT、FROM、WHERE、GROUP BY、HAVING、ORDER BY 的作用不分

SELECT 选列，FROM 选表，WHERE 过滤元组，GROUP BY 分组，HAVING 过滤组，ORDER BY 排序。最常见的错法是把 HAVING 当 WHERE 用，或者把 WHERE 写成聚集函数过滤条件。

13. WHERE 和 HAVING 混淆

WHERE 作用于基表或视图中的元组，不能直接使用聚集函数；HAVING 作用于组，可以使用聚集函数。这个区别是分组查询的核心考点。

14. 把 LIKE 的通配符含义记反

% 表示任意长度字符串，_ 表示任意单个字符。像“欧阳_ _”表示三个汉字姓名，“刘%”表示刘姓学生。很多同学会把两者含义弄反。

15. 不会用 ESCAPE

当要匹配的字符串本身含有 % 或 _ 时，必须使用 ESCAPE 转义，否则会被当成通配符。课件中的“DB_Design”就是典型例子。

16. 把 NULL 当成普通值

NULL 不是 0，也不是空串，也不是普通空白。它表示未知、不适用或保留的信息；与 NULL 的比较不能用 = NULL，而要用 IS NULL 或 IS NOT NULL。空值参与算术运算仍是空值，逻辑运算还可能得到 UNKNOWN。

17. 不理解空串和空值的区别

空串是零长度字符串，不等于 NULL。这个细节在数据库题里经常被混问。

18. ORDER BY 的位置写错

ORDER BY 只能出现在最终查询结果后面，不能放在 UNION/INTERSECT/EXCEPT 之前的子句后面。集合操作结果排序时，还要注意可用数字指定排序列。

19. 连接查询里忘记表名前缀

多个表中出现同名属性时，必须写表名前缀，否则会歧义。自身连接尤其容易出错，因为同一表引用两次时必须使用别名区分。

20. 把自然连接和等值连接完全等同

自然连接是等值连接的一种特殊情况，会自动去掉重复属性列；等值连接则只是按条件相等连接，结果中可能保留重复列。

21. 外连接理解不完整

普通连接只保留满足连接条件的元组；外连接还要保留左表或右表中未匹配的元组，缺失部分通常补 NULL。很多同学只记“外连接保留未匹配行”，但忘了它是“以某一边为主体”的。

22. 复合条件连接和普通连接混为一谈

复合条件连接是在连接条件之外再加其他筛选条件，本质上可以看成“连接后再筛选”。如果不区分连接谓词和其他限定条件，很容易写错。

23. 嵌套查询顺序想反

不相关子查询通常先算子查询再算父查询；相关子查询则依赖父查询元组逐行执行。很多人会把这两种执行方式混在一起。

24. IN、ANY、ALL、EXISTS 不会区分

IN 常表达“属于集合”；ANY 表示“子查询结果中的某一个”；ALL 表示“子查询结果中的所有”；EXISTS 只看是否存在结果。课件还给出 ANY/ALL 与 MAX/MIN 的对应关系，这个非常容易考。

25. 把 = ANY 和 = ALL 记错

课件明确指出，= ANY 相当于 IN；= ALL 通常没有实际意义。很多同学会把它们机械背成同类语义。

26. 不会用 NOT EXISTS 表达“全部满足”

SQL 没有全称量词，但可以用“对不存在的反例进行否定”来表达。像“选修了全部课程的学生”这种题，本质就是：不存在一门他没选的课程。

27. 集合运算题不会把问题翻译成“普通查询”

课件里多次强调，集合差、交、并很多时候可以转成普通 SQL 条件。比如“CS 系学生与年龄不大于 19 岁的差集”实际上就是“CS 系且年龄大于 19 岁”。如果一上来硬套集合运算，反而容易绕晕。

28. 以为标准 SQL 允许在集合运算中间随便排序

课件明确说 ORDER BY 只能用于最终结果，不能用于中间结果。集合操作时的排序必须放在最后，这是很多同学写集合题的高频错误。

29. 只记语法，不记语义

SQL 看起来是命令式语法，但本质是非过程化语言。真正做题时，关键不是死背语句，而是先判断：查哪些表、筛什么条件、是否需要分组、是否需要关联、是否需要“全部满足”语义。
